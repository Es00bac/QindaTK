# Examples

The [volume imaging phantom](volume-imaging/Main.qml) renders a typed
41 × 41 × 21 sphere phantom with 0.8 × 0.8 × 1.6 mm voxels in three linked,
calibrated principal planes; the cross-sections stay round because each view
fits physical spacing, plus a 30° oblique world reslice and a volume
rendering (GPU, or the CPU reference on the software renderer) that picks
into the same cursor. It includes an undoable measured-value transfer
function with a value histogram and explicit below/above/missing colors, a
shared voxel/world cursor whose centre is world (0, 0, 0) mm, and Save view /
Restore view, which keep the cursor, view and transfer settings in a settings
file for the next run (only for the same dataset; the transfer restore is
undoable). Grab it with `--wait 2000`: the volume frame is rendered in the
background.

The [CAD sketch](cad-sketch/Main.qml) renders a constrained mounting plate
with four circular bores. `CadViewport` can select, drag, snap, and create
points, segments, circles and arcs against the persistent `CadDocument`
model. A selected constrained length opens an inline numeric dimension
editor, and the property strip adds or removes constraints on the selection
and edits circle and arc geometry; the model also exports millimeter SVG
and DXF geometry.

The [live diagram](diagram-live/Main.qml) binds `DiagramCanvas` to a native
`DiagramDocument`. Moving cards and connecting ports edit persistent stable
IDs; Undo and Redo operate on the diagram graph. Cards come from stencils
in the Add menu, the Rework loop is a persistent group, and the two selected
cards show the align and distribute strip. The example shows measured
wire quantities and per-node totals; Auto layout arranges its feedback cycle
in one undoable step. Wires are routed around cards, and a `SankeyDiagram`
below the canvas draws the same conserved quantities as bands.

The [extension manager fixture](extension-manager-live/Main.qml) shows a
restored catalog with unavailable native extensions, clear diagnostics,
explicit directory discovery and separate Load actions.

The [live code editor fixture](code-editor-live/Main.qml) connects
`CodeEditor` to a native `CodeDocument` buffer and revision-tagged sample
syntax/diagnostic provider. It opens with a folded function, an extra caret,
and revision-tagged completion choices. Text remains editable with Qt's IME,
selection, undo and local save/reopen APIs.

The [local language server fixture](code-editor-lsp/Main.qml) keeps clangd
stopped until Start is clicked. It then publishes real C++ diagnostics and
completion into `CodeEditor`; `Preview.qml` auto-starts only for a screenshot
or focused preview run.

Most examples are plain QML files run by `qtk-preview` and each standalone
`examples/<name>/Main.qml` is a ctest smoke test (`example_<name>`). The
`workbench` example has a C++ host and its own `--check` gate, so its QML
file is not run directly by `qtk-preview`. Screenshots are regenerated by
`tools/scripts/screenshots.sh` into `docs/screenshots/`.

The [live terminal](terminal-live/Main.qml) keeps process execution behind an
explicit Start demo button and connects `Tk.TerminalView` to a real local PTY.

The [media source browser](media-source-browser.qml) is the WP-070 fixture
for `SourceProgramMonitor`, `MediaBin`, `MediaPlayer` and `MediaCatalog` on
real media. Run it with `qtk-preview examples/media-source-browser.qml`: it
writes two short test signals (bars, burned-in frame codes, sync pops) into
`<temp>/qindatk-media-demo`, imports them into virtual bins, plays the selected
clip in the source monitor and a two-cut timeline in the program monitor, and
Export program queues a verified FFV1/PCM Matroska render there. The files are
rewritten in place on each start.

The [color-grade fixture](color-grade/Main.qml) applies a tagged CPU image
transform and compares before/after pixels and scopes. Its edit session groups
each wheel gesture into one undo step; the host still supplies decoded frames.
The [caption model fixture](caption-model/Main.qml) connects `CaptionEditor`
to exact-millisecond cue edits, undo, local JSON and WebVTT/SRT sidecars.
The [caption render fixture](caption-render/Main.qml) burns active cues into
actual frame pixels at exact millisecond positions.
The [caption sequence fixture](caption-sequence/Main.qml) writes ordered PNG
frames and an exact-timing manifest for a host encoder.

The [publishing workbench](document-publishing/Main.qml) binds
`StyleManager`, `PageSetupDialog`, `TextFrameEditor`, and `TableEditor` to one
`Tk.RichTextDocument` (a press release from `publishing.js`: named styles, a
price table with a merged cell, and a story threaded through two text frames
with overset text). Every panel request is a document undo step; choosing a
frame or cell moves the page caret, and the caret selects them in the panels.
Connecting the free frame on page 2 takes the overset text. It is an
`example_document-publishing` smoke test, and
`tests/qml/tst_publishing_example.qml` drives it
([publishing.md](../docs/publishing.md)).

The [document review workbench](document-review/Main.qml) binds
`ReferenceManager`, `ReviewPane` and `EquationEditor` to one
`Tk.RichTextDocument` beside its page view. The field report's captions,
cross-reference, citations, bibliography, equation, comment thread and
tracked replacement are made with the document's own operations, so adding a
caption renumbers the cross-reference in one undo step, accepting a change
edits the text, and the equation is drawn on the page from its source. It
runs as the `example_document-review` smoke test, and
`tests/qml/tst_review_example.qml` drives it
([references-review.md](../docs/references-review.md)).

The [print and preflight workbench](print-preflight/Main.qml) binds
`PrintPreview`, `PrintSheetView` and `PreflightPanel` to one `PrintAdapter`
over the showcase document: the sheet preview is what the PDF or printer
job paints, and the issues and repairs are real checks
([printing.md](../docs/printing.md)).

The [PDF reader and review fixture](pdf-review/Main.qml) exercises `PdfView`
and `PdfAnnotationTools` on a two-page PDF. The default asset backend renders
pages and extracts searchable word positions through Poppler tools.
When Poppler Qt6 is installed, `PdfAnnotationDocument` backs the fixture's
note/highlight requests; `saveAs(path)` persists a copy with stable IDs.

The [slide authoring fixture](slide-authoring/Main.qml) exercises slide
sorting, object selection, master overrides, animation requests and separate
presenter/audience snapshots through five toolkit controls.

The [productivity fixture](productivity-suite/Main.qml) exercises mail,
calendar, recurrence and task controls. Its recurrence preview uses
`RecurrenceService`; message and task records remain sample snapshots.
The [local productivity fixture](local-productivity/Main.qml) puts all five
views over one `LocalProductivityStore`: threaded mail with lazy attachments,
a composer with validated recipient tokens and attachment jobs, a projected
calendar with scoped moves and a persisted recurrence editor, and a task board
with keyboard/pointer reorder and conflict resolution. Its
`ProductivityHost.qml` routes each request to the store and to the SMTP, IMAP
and CalDAV providers; with no account configured those requests come back
rejected by the providers, and `tst_productivity_seam` runs the same file
against local test servers. `RichMailComposer` edits a `RichTextDocument`;
autosaved draft rows keep both the compatibility plain body and canonical
`richDocumentJson`.
The [attachment fixture](local-attachment-store/Main.qml) imports and rereads
actual local payload bytes alongside a draft's stable attachment metadata.
The [local calendar projection fixture](local-calendar-projection/Main.qml)
expands stored recurring events into navigable seven-day ranges.
The [form/schema/report fixture](forms-schema-report/Main.qml) uses a local
SQLite provider, parameter-bound fields, saved design bindings and paginated
document/PDF report output. The [motion fixture](motion-authoring/Main.qml)
evaluates exact-tick keyframes, composites local SVG artwork into source
pixels and shows effect compatibility. These are
toolkit examples rather than complete productivity or motion applications.
The [motion overlay fixture](motion-overlays/Main.qml) draws sampled transform
paths and neighboring composited frames for onion-skin inspection.
The [motion persistence fixture](motion-persistence/Main.qml) saves and
reopens a versioned composition with exact animation ticks and stable layer
IDs; artwork remains an external asset.
The [motion effects fixture](motion-effects/Main.qml) renders the same source
before and after ordered brightness and grayscale effects.
The [node graph fixture](node-graph/Main.qml) presents host-owned node and
typed-edge snapshots, accepts compatible connections, and shows the host's
rejection for incompatible port types. `NodeGraphModel` separately supplies
typed image evaluation, cycle validation, undo and topology persistence for
hosts that use the toolkit's initial processing nodes.
The [live node graph fixture](node-graph-live/Main.qml) wires that model to the
editor: two grouped solid plates and an ellipse mask feed a masked blend, and
the rendered pixels, render errors, blend opacity (one undo step per drag),
blend mode and undo/redo sit beside the graph. Search, grouping, adding and
removing nodes, and keyboard linking all go through the model's validation.
The [tracking and roto fixture](tracking-roto/Main.qml) presents tracked point
confidence and loss beside editable, keyframed mask paths; snapshots and edit
requests follow the `TrackingRotoModel` host contract.
The [live tracking and roto fixture](tracking-roto-live/Main.qml) loads three
local frames, runs the toolkit's patch tracker, accepts its measured points and
shows a generated mask translation over the moved frame. Editing and preview
requests feed back into the real model; the fixture still leaves source media
decoding and project composition to a host application.
The [3D mesh and texture fixture](mesh-rig-3d/Main.qml) constructs two real
triangles with UVs, paints two texture samples through mesh rays and displays
the posed, textured result in `SceneView3D` when Qt Quick 3D is available.
The [3D scene fixture](scene-3d/Main.qml) connects `SceneOutliner` to the
persistent `SceneModel3D` hierarchy and routes stable-ID reparent requests with
an explicit keep-world/local transform choice. `MaterialPreview` edits the
selected primitive's persisted material while the actual Qt Quick 3D scene
updates its shading.
The [3D scene session fixture](scene-session/Main.qml) creates a scene through
`DocumentManager` and provides visible Save As, Reopen and shared Undo/Redo.
The [live mesh workbench](mesh-rig-live/Main.qml) wires `RigEditor`, `UVEditor`
and `TexturePaintView` to one `MeshRigDocument`. The GPU viewport displays the
same posed, painted triangles and supplies camera rays for paint gestures.
The [live script console](script-console-live/Main.qml) runs local JavaScript
against a JSON document snapshot and shows output in `ScriptConsole`.
Applications explicitly expose command IDs and attach semantic undo history
before scripts can automate edits.
The [image comparison fixture](image-compare/Main.qml) aligns two local images
for split, blink and encoded-sRGB difference inspection.
The [mask and brush controls fixture](mask-brush-controls/Main.qml) shows
stable channel/preset snapshots and explicit host acknowledgments for brush
dynamics requests. The [tiled raster fixture](tiled-raster/Main.qml) paints
actual masked RGBA tiles, undoes a stroke, saves and reopens its native state,
and exports a tagged sRGB composite PNG. Its `RasterStrokeInput` overlay
accepts tablet pressure/tilt and mouse strokes on the rendered canvas.
The [raster workbench fixture](raster-workbench/Main.qml) connects those
controls to the tiled document, paints with mouse gestures and compares live
before/after PNG pixels without writing temporary source images.
The [raster canvas fixture](raster-canvas/Main.qml) places a masked tiled
raster on a `CanvasDocument` beside a vector star, rotates it as a canvas
object, paints through the canvas view and publishes each stroke as one canvas
undo step. A revision-keyed comparison shows the raster at placement time
against the current one.
The [rig and UV fixture](rig-uv/Main.qml) presents stable-ID bone and triangle
UV snapshots with host edit requests; its skeleton is a 2D projection, and
texture painting stays in preview mode until a host supplies camera rays.

The [device settings panel](device-settings-panel.qml) exercises pending
audio configuration and explicit host accept/reject acknowledgments. A real
device engine must supply enumeration and apply the settings.

The [mixer and routing fixture](mixer-routing.qml) binds `MixerView`
(`ChannelStrip`, `ChannelRoutingPanel`, `PanningControl`) and `RoutingMatrix`
to a real `AudioSession` mix: buses, pre/post-fader sends, a solo-safe return,
a group and a mono track. Every control edits the graph the engine plays, and
refused routes show the mixer's reason ([docs/audio-mixer.md](../docs/audio-mixer.md)).

The [calibrated audio controls fixture](audio-controls/Main.qml) exercises
`Knob`, `Fader`, `AudioMeter`, and `LoudnessHistory` with provider snapshots.

The [waveform and spectrogram fixture](waveform-spectrogram/Main.qml)
exercises `WaveformEditor` and `SpectrogramView` with exact sample selection
requests and host-owned spectral snapshots. The
[live waveform example](waveform-live/Main.qml) runs the same editors on the
real stack ([docs/audio-editing.md](../docs/audio-editing.md)): a generated
recording imported into an `AudioSession` that loops through the engine on
the silent null device, worker-thread peaks (`AudioWaveformSource`) and STFT
tiles (`AudioSpectrogramSource`), and gain, fades, silence, delete, crop and
spectral band/mask gain (preview, commit, cancel) applied to `session.edits`
with its undo and redo; the playhead and output meter come from the engine.

The [MIDI editing fixture](midi-editors/Main.qml) exercises `PianoRoll`,
`MidiControllerLane`, `StepSequencer` and `ClipLauncher` with exact tick strings
and host-owned pattern and launch state.

The [take-comp example](take-comp/Main.qml) runs `TakeCompView` on a live
`AudioSession`: a generated three-pass loop recording becomes takes of a real
comp with crossfades; swipes preview, Accept/Reject commit or cancel, Audition
and Compare change what plays, and Undo/Redo walk the comp history.

The [plugin host UI fixture](plugin-host/Main.qml) exercises `PluginBrowser`
and `PluginRack` with discover, add, reorder, bypass and state acknowledgments
from a mock host. The [score fixture](score-view/Main.qml) exercises
`ScoreView` with host-positioned notation and exact entry requests.

inspector panel whose body scrolls a section header and a two-column
`Tk.Grid` of readouts. Start here to see how `Flex`, `Box`, `Scroll`,

## rich-table

Structured table editing (WP-051): `Tk.TableEditor` bound to the paginated
`Tk.RichTextDocument` loaded from the rich-document fixture. The editor shows
the document's `tables` snapshot, and its cell-text, row/column insertion and
deletion, and relative column-width requests call the document's table
methods, so the page reflows at once and each edit is one undo step (the
header's Undo/Redo buttons). Selecting a cell reveals it on the page; moving
the page caret into a cell selects it in the editor. A refused request shows
the document's reason in `tableStructureStatus`. "Extend cell selection"
adds cells for Merge; Split restores a merged cell's slots.

- Run: `qtk-preview examples/rich-table/Main.qml --size 1180x760`

## render-queue-live

This standalone host wires `RenderQueueView` to `RenderQueueModel`. It creates
three fixed PNG source frames, hashes them into an immutable caption render
snapshot, then writes a verified captioned PNG sequence and exact manifest.
Validate and Submit are interactive; Cancel, Retry and Open output route back
to the queue. Open output is offered only after verified publication. The
state path records queued, running and succeeded transitions in one run.

- Build: `cmake --build build/dev --target qtk-render-queue-live`
- Run: `build/dev/examples/qtk-render-queue-live --output-root /tmp/qtk-render-demo`
- Automated check and screenshot: `QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software build/dev/examples/qtk-render-queue-live --check --output-root /tmp/qtk-render-demo --grab /tmp/qtk-render-demo.png`
- Output: `/tmp/qtk-render-demo/caption-output/frame-000000.png` through `frame-000002.png` and `render-manifest.json`
- Screenshot: [render-queue-live.png](../docs/screenshots/render-queue-live.png)

Use a new output root for a fresh render. Reopening a root displays its persisted
job and verifies it before the automated check succeeds.

- `scene-3d/Main.qml` — actual Qt Quick 3D primitive scene, parented transforms, picking, snapped translation and undo. Use `qtk-preview --gpu` for rendered pixels; the software adaptation reports unavailable.

`scientific-plot/Main.qml` shows two `ScientificPlot` figures: a known
exponential response with asymmetric host-supplied one-sigma error bars, a gap,
a model trace and two annotations; and a sampled Gaussian field (`ScientificGrid`,
bilinear colour map with one missing node) under scatter probes with X and Y
uncertainty. Run `qtk-preview examples/scientific-plot/Main.qml --grab figure.png --size 1280x680`.

## scientific-3d-family

`scientific-3d-family/Main.qml` joins the scientific 3D family in one window:
a pill switcher shows the `scientific-plot-3d` surface and scatter page or the
`volume-imaging` slices and volume page. Both stay loaded, so each keeps its
state. Run `qtk-preview examples/scientific-3d-family/Main.qml --size 1280x960`.

## scientific-plot-3d

`scientific-plot-3d/Main.qml` shows `ScientificPlot3D` with a sampled saddle
surface (a small hole of missing nodes), three 3D probe points, an
interpolation toggle and the source table. Use `qtk-preview --gpu` for the
Qt Quick 3D renderer; the software adaptation draws the same scene with the
export painter.

## workbook

The WP-055 spreadsheet over a two-sheet budget, a workbook session of a
`DocumentManager` (`createDocument("qindatk.workbook.v1")`). `WorkbookTabs` switch
between the Budget and Summary sheets (whose formulas refer to Budget by
sheet ID, so renames and reordering keep them; the tab menu colors, hides
and protects sheets). The `FormulaBar` edits the active cell's source input
and shows its formatted value; Enter commits, Escape restores, and clicking
cells while editing a formula inserts their references. Select F2:F5 and
press Fill down (Ctrl+D) or drag the fill handle to complete the totals with
relative references moved. The Budget sheet has number formats, a frozen
header row and column, a data bar and a highlight rule, and a validated tax
rate (B8 warns above 50%). Summary uses the name `Totals`, a whole-column
`COUNTA(Budget!A:A)` and a merged note. The format toolbar applies bold,
italic, underline, alignment, number formats, a highlight fill, merges
and freeze panes to the selection; the side panel edits conditional formats
(with a live preview) and validation rules. Ctrl+C/Ctrl+V use the system
clipboard. Undo/Redo go through the manager's `UndoService`, which holds
the workbook's history. Save writes a `.qtkwb` file to the temporary
directory through the session on a worker, and Reopen saved closes the
session (discarding later changes) and opens the file again. The status line reports the revision and the last
recalculation's evaluated cells.
