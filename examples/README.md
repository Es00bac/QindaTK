# Examples

The [CAD sketch](cad-sketch/Main.qml) renders a constrained mounting plate
with four circular bores. `CadViewport` can select, drag, snap, and create
points, segments, circles and arcs against the persistent `CadDocument`
model. A selected constrained length opens an inline numeric dimension
editor; the model also exports millimeter SVG and DXF geometry.

The [live diagram](diagram-live/Main.qml) binds `DiagramCanvas` to a native
`DiagramDocument`. Moving cards and connecting ports edit persistent stable
IDs; Undo and Redo operate on the diagram graph. The example shows measured
wire quantities and per-node totals; Auto layout arranges its feedback cycle
in one undoable step.

The [extension manager fixture](extension-manager-live/Main.qml) shows a
restored catalog with unavailable native extensions, clear diagnostics and
explicit descriptor and Load actions.

The [live code editor fixture](code-editor-live/Main.qml) connects
`CodeEditor` to a native `CodeDocument` buffer and revision-tagged sample
syntax/diagnostic provider. Text remains editable with Qt's IME, selection,
undo and local save/reopen APIs.

Most examples are plain QML files run by `qtk-preview` and each standalone
`examples/<name>/Main.qml` is a ctest smoke test (`example_<name>`). The
`workbench` example has a C++ host and its own `--check` gate, so its QML
file is not run directly by `qtk-preview`. Screenshots are regenerated by
`tools/scripts/screenshots.sh` into `docs/screenshots/`.

The [live terminal](terminal-live/Main.qml) keeps process execution behind an
explicit Start demo button and connects `Tk.TerminalView` to a real local PTY.

The [media source browser](media-source-browser.qml) is a standalone WP-070
fixture for `SourceProgramMonitor` and `MediaBin`. Run it with
`qtk-preview examples/media-source-browser.qml`; frame and thumbnail
placeholders remain visible until an application provides real media data.

The [color-grade fixture](color-grade/Main.qml) applies a tagged CPU image
transform and compares before/after pixels and scopes. Its edit session groups
each wheel gesture into one undo step; the host still supplies decoded frames.
The [caption model fixture](caption-model/Main.qml) connects `CaptionEditor`
to exact-millisecond cue edits, undo, local JSON and WebVTT/SRT sidecars.
The [caption render fixture](caption-render/Main.qml) burns active cues into
actual frame pixels at exact millisecond positions.
The [caption sequence fixture](caption-sequence/Main.qml) writes ordered PNG
frames and an exact-timing manifest for a host encoder.

The [publishing workbench](document-publishing/Main.qml) exercises
`StyleManager`, `PageSetupDialog`, `TextFrameEditor`, and `TableEditor` with
host-owned sample records; it is also an `example_document-publishing` smoke
test. Production document transactions belong to the host backend.

The [document review workbench](document-review/Main.qml) exercises
`EquationEditor`, `ReferenceManager`, and `ReviewPane` with host-owned sample
records, including a broken reference and orphaned comment.

The [print and preflight workbench](print-preflight/Main.qml) exercises
`PrintPreview` and `PreflightPanel` with a live rich-document preview and
sample host-owned output issues.

The [PDF reader and review fixture](pdf-review/Main.qml) exercises `PdfView`
and `PdfAnnotationTools` on a two-page PDF. The default asset backend renders
pages and extracts searchable word positions through Poppler tools.
When Poppler Qt6 is installed, `PdfAnnotationDocument` backs the fixture's
note/highlight requests; `saveAs(path)` persists a copy with stable IDs.

The [slide authoring fixture](slide-authoring/Main.qml) exercises slide
sorting, object selection, master overrides, animation requests and separate
presenter/audience snapshots through five toolkit controls.

The [productivity fixture](productivity-suite/Main.qml) exercises mail,
calendar, recurrence and task controls. Its recurrence preview uses
`RecurrenceService`; message and task records remain sample snapshots.
The [local productivity fixture](local-productivity/Main.qml) connects the
same kinds of controls to `LocalProductivityStore` for persisted mail, drafts,
events and task moves with local recovery and undo. `RichMailComposer` edits a
`RichTextDocument`; autosaved draft rows keep both the compatibility plain
body and canonical `richDocumentJson`, so formatting reopens with the stable
draft ID and attachment metadata intact.
The [attachment fixture](local-attachment-store/Main.qml) imports and rereads
actual local payload bytes alongside a draft's stable attachment metadata.
The [local calendar projection fixture](local-calendar-projection/Main.qml)
expands stored recurring events into navigable seven-day ranges.
The [form/schema/report fixture](forms-schema-report/Main.qml) uses a local
SQLite provider, parameter-bound fields, saved design bindings and paginated
document/PDF report output. The [motion fixture](motion-authoring/Main.qml)
evaluates exact-tick keyframes, composites local SVG artwork into source
pixels and shows effect compatibility. These are
toolkit examples rather than complete productivity or motion applications.
The [motion overlay fixture](motion-overlays/Main.qml) draws sampled transform
paths and neighboring composited frames for onion-skin inspection.
The [motion persistence fixture](motion-persistence/Main.qml) saves and
reopens a versioned composition with exact animation ticks and stable layer
IDs; artwork remains an external asset.
The [motion effects fixture](motion-effects/Main.qml) renders the same source
before and after ordered brightness and grayscale effects.
The [node graph fixture](node-graph/Main.qml) presents host-owned node and
typed-edge snapshots, accepts compatible connections, and shows the host's
rejection for incompatible port types. `NodeGraphModel` separately supplies
typed image evaluation, cycle validation, undo and topology persistence for
hosts that use the toolkit's initial processing nodes.
The [live node graph fixture](node-graph-live/Main.qml) wires that model to the
editor and displays its actual blended pixel output from two solid-color nodes.
The [tracking and roto fixture](tracking-roto/Main.qml) presents tracked point
confidence and loss beside editable, keyframed mask paths; snapshots and edit
requests follow the `TrackingRotoModel` host contract.
The [live tracking and roto fixture](tracking-roto-live/Main.qml) loads three
local frames, runs the toolkit's patch tracker, accepts its measured points and
shows a generated mask translation over the moved frame. Editing and preview
requests feed back into the real model; the fixture still leaves source media
decoding and project composition to a host application.
The [3D mesh and texture fixture](mesh-rig-3d/Main.qml) constructs two real
triangles with UVs, paints two texture samples through mesh rays and displays
the posed, textured result in `SceneView3D` when Qt Quick 3D is available.
The [3D scene fixture](scene-3d/Main.qml) connects `SceneOutliner` to the
persistent `SceneModel3D` hierarchy and routes stable-ID reparent requests with
an explicit keep-world/local transform choice.
The [live mesh workbench](mesh-rig-live/Main.qml) wires `RigEditor`, `UVEditor`
and `TexturePaintView` to one `MeshRigDocument`. The GPU viewport displays the
same posed, painted triangles and supplies camera rays for paint gestures.
The [live script console](script-console-live/Main.qml) runs local JavaScript
against a JSON document snapshot and shows output in `ScriptConsole`.
Applications explicitly expose command IDs and attach semantic undo history
before scripts can automate edits.
The [image comparison fixture](image-compare/Main.qml) aligns two local images
for split, blink and encoded-sRGB difference inspection.
The [mask and brush controls fixture](mask-brush-controls/Main.qml) shows
stable channel/preset snapshots and explicit host acknowledgments for brush
dynamics requests. The [tiled raster fixture](tiled-raster/Main.qml) paints
actual masked RGBA tiles, undoes a stroke, saves and reopens its native state,
and exports a tagged sRGB composite PNG. Its `RasterStrokeInput` overlay
accepts tablet pressure/tilt and mouse strokes on the rendered canvas.
The [raster workbench fixture](raster-workbench/Main.qml) connects those
controls to the tiled document, paints with mouse gestures and compares live
before/after PNG pixels without writing temporary source images.
The [rig and UV fixture](rig-uv/Main.qml) presents stable-ID bone and triangle
UV snapshots with host edit requests; its skeleton is a 2D projection, and
texture painting stays in preview mode until a host supplies camera rays.

The [device settings panel](device-settings-panel.qml) exercises pending
audio configuration and explicit host accept/reject acknowledgments. A real
device engine must supply enumeration and apply the settings.

The [mixer and routing fixture](mixer-routing.qml) exercises `ChannelStrip`,
`MixerView`, `PanningControl`, and `RoutingMatrix` against a host-owned model.
The audio graph and DSP remain a host/backend integration task.

The [calibrated audio controls fixture](audio-controls/Main.qml) exercises
`Knob`, `Fader`, `AudioMeter`, and `LoudnessHistory` with provider snapshots.

The [waveform and spectrogram fixture](waveform-spectrogram/Main.qml)
exercises `WaveformEditor` and `SpectrogramView` with exact sample selection
requests and host-owned spectral snapshots.

The [MIDI editing fixture](midi-editors/Main.qml) exercises `PianoRoll`,
`MidiControllerLane`, `StepSequencer` and `ClipLauncher` with exact tick strings
and host-owned pattern and launch state.

The [take-comp fixture](take-comp/Main.qml) exercises `TakeCompView` with
sample-exact swipe requests and host-owned source and comp snapshots.

The [plugin host UI fixture](plugin-host/Main.qml) exercises `PluginBrowser`
and `PluginRack` with discover, add, reorder, bypass and state acknowledgments
from a mock host. The [score fixture](score-view/Main.qml) exercises
`ScoreView` with host-positioned notation and exact entry requests.

## smoke

The smallest useful screen: a canvas with a zoom island beside an
inspector panel whose body scrolls a section header and a two-column
`Tk.Grid` of readouts. Start here to see how `Flex`, `Box`, `Scroll`,
`Panel` and the text family fit together.

- Run: `qtk-preview examples/smoke/Main.qml --dump`
- Exercises: `Flex`, `Box`, `Panel`, `Scroll`, `Grid`, `Island`,
  `SectionHeader`, `Divider`, `IconButton`, `Caption`, `Mono`, `Label`

## adaptive-layout

A 360×300 narrow inspector scene exercises a wrapped action row, auto-fill
Grid cards, and a Stack overlay with a long message and a reserved badge slot.
The sections flow by content height inside `Tk.Scroll`, including at 2× text
size. Set `interfaceDirection` to `Qt.RightToLeft` to inspect mirrored
placement. The focused `tst_layout` matrix checks both densities, both
directions, and normal/2× text.

- Run: `qtk-preview examples/adaptive-layout/Main.qml --dump --size 360x300`
- Screenshot: `qtk-preview examples/adaptive-layout/Main.qml --grab out.png --density comfortable --size 360x300`
- Exercises: `Flex.Wrap`, responsive `Grid` auto-fill, `Stack` overlay insets, long-label wrapping, density-aware spacing, and logical direction

## gallery

The core controls in [docs/controls.md](../docs/controls.md) in their common
documented states — variants, sizes, checked/disabled/busy/error, selected
and two-line rows, expanded and collapsed tree rows — grouped by section with a header
that switches the preset and the density live and a search field that
filters sections by title. The header wraps as text grows; at maximum
Touch/text zoom its preset switch scrolls horizontally so every choice stays
reachable. One QML file per section (`TextSection.qml`,
`LayoutSection.qml`, …); `Section.qml` and `GalleryRow.qml` are the two
layout helpers.

- Run: `qtk-preview examples/gallery/Main.qml`
  (`--theme sloom-light`, `--density comfortable`, `--size 1280x3400` to see
  the whole page at once)
- Exercises: the original 62-control gallery set, including `DockHost` (an embedded dock with a
  tab group), `Menu`/`MenuBar`/`Popover`/`Dialog`/`CommandPalette` (opened
  from buttons), `Splitter`, `Ruler`, `ZoomControl`, and a swatch of every
  `Tk.Theme.color` role
- Screenshot: [docs/screenshots/gallery.png](../docs/screenshots/gallery.png),
  [gallery-comfortable.png](../docs/screenshots/gallery-comfortable.png),
  [gallery-light.png](../docs/screenshots/gallery-light.png)

## rich-document

Rich text and pages (WP-050): one `Tk.RichTextDocument` shown as pages in a
`RichDocumentView` and as a continuous draft in a `RichTextEditor`. A
`FormatBar` follows whichever of the two has focus, `FindReplaceBar` uses
`RichTextFindReplaceService` to search and replace in that same document,
and a `PageNavigator` shows thumbnails and an outline. `showcase.qtkrich` is a native
`qindatk.richtext/1` file containing:

- mixed scripts, lists, a link and an inline image;
- a 30-row table that crosses a page break with a repeated header;
- a float that moves with its anchor, and a page stamp;
- a page-break appendix with right-to-left paragraphs.

- Run: `qtk-preview examples/rich-document/Main.qml`
  (`--dump --size 1280x800` lists `richDocumentPage_<pageKey>` for the
  visible pages only)
- Exercises: `RichTextDocument`, `RichDocumentView`, `RichTextEditor`,
  `RichTextFindReplaceService`, `FindReplaceBar`, `FormatBar`, `PageNavigator`,
  `Panel`, `StatusBar`
- Screenshots: [compact](../docs/universal-toolkit/implementation/evidence/WP-050-compact.png),
  [comfortable](../docs/universal-toolkit/implementation/evidence/WP-050-comfortable.png)

## render-queue

The render queue fixture shows queued, running, failed, succeeded, cancelled
and stale host-owned job snapshots. Buttons report validation, submission,
cancellation, retry and output-open requests; they do not execute rendering.
The output-open action appears only when a succeeded snapshot has a validated
output manifest.

- Run: `qtk-preview examples/render-queue/Main.qml --grab render-queue.png --size 1020x700`
- Exercises: `RenderQueueView`, immutable source/version and output snapshots,
  explicit host requests, diagnostics and manifest-gated output access
- Screenshot: [render-queue.png](../docs/screenshots/render-queue.png)

## render-queue-live

This standalone host wires `RenderQueueView` to `RenderQueueModel`. It creates
three fixed PNG source frames, hashes them into an immutable caption render
snapshot, then writes a verified captioned PNG sequence and exact manifest.
Validate and Submit are interactive; Cancel, Retry and Open output route back
to the queue. Open output is offered only after verified publication. The
state path records queued, running and succeeded transitions in one run.

- Build: `cmake --build build/dev --target qtk-render-queue-live`
- Run: `build/dev/examples/qtk-render-queue-live --output-root /tmp/qtk-render-demo`
- Automated check and screenshot: `QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software build/dev/examples/qtk-render-queue-live --check --output-root /tmp/qtk-render-demo --grab /tmp/qtk-render-demo.png`
- Output: `/tmp/qtk-render-demo/caption-output/frame-000000.png` through `frame-000002.png` and `render-manifest.json`
- Screenshot: [render-queue-live.png](../docs/screenshots/render-queue-live.png)

Use a new output root for a fresh render. Reopening a root displays its persisted
job and verifies it before the automated check succeeds.

- `scene-3d/Main.qml` — actual Qt Quick 3D primitive scene, parented transforms, picking, snapped translation and undo. Use `qtk-preview --gpu` for rendered pixels; the software adaptation reports unavailable.

## scientific-plot

`scientific-plot/Main.qml` plots a known exponential response with host-supplied
one-sigma measurements. It uses `ScientificDataset`, `ScientificPlot`, shared
`ChartAxis` calibration and the uncertainty renderer's PNG/SVG export path.
Run `qtk-preview examples/scientific-plot/Main.qml --grab figure.png --size 1080x680`.
