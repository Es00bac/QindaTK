# WP-033 — Shared application workbench proof

**State: accepted.** This package composes the already accepted shared services
into a runnable two-document reference application. Its requirements are in
[phase 02](../phase-02-controls-data.md#wp-033) and the
[shared workbench acceptance scenario](../acceptance.md#complete-application-proofs).

## Baseline and ownership

The integration source at `99cddd0` passed **96/96** repository CTest cases on
Qt 6.11.1 and Qt 6.8.3, including the separate service suites. That result
establishes the starting regression baseline; it does not establish the
combined WP-033 workflow. `DocumentManager` and `DocumentSession` currently
own reference `PropertyDocument` content, an `UndoService`, native reference
format saving and recovery. The new application must use those real services
and label any domain adapter or fixture as such.

Sol owns the integrated workflow and source fixes. The separate UI and
installed-consumer lanes have delivered bounded proofs; neither alone
qualifies the package.

## Bounded proofs now available

- The standalone [workbench](../../../../examples/workbench/README.md) opens
  two real `DocumentManager` reference sessions, with stable-ID asset and
  editable grid projections plus an inspector `PropertyBinding`. A grid cell
  commits through `EditTransaction`; a two-cell paste uses one `UndoService`
  macro and releases the grid's temporary overrides. The same
  scoped `workbench.rename` command is available through the toolbar,
  inspector context menu, Ctrl+Shift+R and the toolbar button's accessible
  press action. The Qt 6.11 and Qt 6.8 workbench builds each passed `--check`
  and `--dump`: a cell edit increments one revision, a two-cell paste increments
  two document revisions but creates one undo entry, both cells restore in one
  undo, projections agree, and the inactive document is unchanged. The command
  routes also commit and undo after switching documents. Dump geometry:
  `workbenchPanels 0,62 1280x700`, collection 174 wide, grid 886 wide,
  inspector 204 wide, `workbenchGridFilter 0,0 811.375x24`,
  `workbenchGridSort 813.375,0 62.625x24`, and `documents=2`. The workbench
  sorts Name and filters across columns while retaining the selected stable
  row ID per document, including when a filter temporarily hides it. Its
  `--check` selects a nonfirst row, sorts, hides and restores it, switches
  documents, then verifies separate remembered row IDs. A document rename
  re-sorts the visible rows and undo restores the prior order. Sol regenerated and opened the
  [compact](WP-033-workbench-compact.png) and
  [comfortable](WP-033-workbench-comfortable.png) captures; tabs, grid,
  collection and inspector remain visible and aligned in both densities.
- The standalone [installed consumer](../../../../tests/consumer/wp033/README.md)
  passed against refreshed installed stages on both Qt 6.11 and Qt 6.8. It
  captures and reloads a two-document workspace, reopens A0/B0 content and
  restores the active document and stable view IDs. It closes restored B while
  a snapshot-bound job is still running and verifies that the result is stale,
  unpublished and cannot change active A. It also exercises two
  independent document scopes, a stale revision rejection, copy A → B and
  independent undo, then an external conflict on A's save while B saves. It
  reopens clean B and restores A's latest edit from recovery without replacing
  the external file. The first workspace attempt caught a fixture error: B was
  active at capture time while the assertion expected A. The fixture now
  activates A before capture; both installed reruns pass.

The installed consumer first proved the workspace reload and recovery service
paths independently; the workbench UI integration below closes those local
workflow gaps without claiming generic domain serialization.

The workbench now connects lifecycle controls to the real manager services.
The inspector offers Save As/open, restores the active document's failed-save
recovery revision, captures/saves/restores the workspace, and can close the
active document while a delayed job is running. `--check` now verifies Save As
followed by reopen from disk, workspace restore reopening a closed third
document, recovery after an external save conflict, and suppression of the
closed document's delayed result. The transfer action originally used a JSON
string archive; the native collection path below supersedes it. The compact
[lifecycle capture](WP-033-workbench-lifecycle.png) was inspected at 1280×800.
The focused installed-package `--check` passed on Qt 6.11.1 with the
configured `-j24 -l24` Ninja limits.

## Acceptance scenarios and remaining checks

1. Prove retained selection by ID across multiple live views. The workbench's
   sort/filter and two-document selection path now passes on both Qt versions.
2. The native external AT-SPI client locates the workbench `Apply name`
   button and invokes its desktop `Press` action. This reaches the same
   `CommandButton` and `workbench.rename` route as the toolbar.
3. The workbench validates a transferable object payload and remaps its ID
   into an undoable native destination collection. Explicit nested references
   among transferred rows are remapped. Resource-bearing transfers remain
   unsupported without a domain resource store.
4. The close-during-job guard now runs through an actual workbench action; its
   stale completion is not published after the source document closes.
5. Save As/reopen, failed-save recovery and workspace capture/save/restore now
   run through the workbench UI and host. Workspace reopen is proven for a
   saved reference document; generic domain serialization remains outside the
   reference codec.
6. The lifecycle flow passes `--check` on Qt 6.11.1 and Qt 6.8.3. The
   inspected capture is the existing Qt 6.11.1 lifecycle image; this lane
   changes no visuals.

## Final gate closure — isolated `work/wp033-final-gate`

The Qt 6.8.3 installed consumer and native external accessibility gates both
passed from base `9ec78e40d8085bbf7a6497b04e7709875b25910`. Portage reported
`MAKEOPTS=-j24 -l24`; all direct builds inherited the default configured

The host's Poppler Qt 6 package resolves to a Qt 6.11 build and cannot link
into a Qt 6.8 consumer. The toolkit now has the default-on
`QINDATK_ENABLE_POPPLER_QT6` CMake option so Qt 6.8 installations can disable

Qt 6.8 build also disabled the unavailable optional Quick3D renderer. It
rebuilt and installed `qindatk` and its QML plugins into `build/qt68-stage`.

Qt 6.8.3 SDK and refreshed stage. With the SDK libraries and plugins selected,

clipboard ID remapping, Save As/reopen, workspace restore, failed-save
