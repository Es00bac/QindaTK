# WP-033 — Shared application workbench proof

**State: active.** This package composes the already accepted shared services
into a runnable two-document reference application. Its requirements are in
[phase 02](../phase-02-controls-data.md#wp-033) and the
[shared workbench acceptance scenario](../acceptance.md#complete-application-proofs).

## Baseline and ownership

The integration source at `99cddd0` passes **96/96** repository CTest cases on
Qt 6.11.1 and Qt 6.8.3, including the separate service suites. That result
establishes the starting regression baseline; it does not establish the
combined WP-033 workflow. `DocumentManager` and `DocumentSession` currently
own reference `PropertyDocument` content, an `UndoService`, native reference
format saving and recovery. The new application must use those real services
and label any domain adapter or fixture as such.

Sol owns the integrated workflow and source fixes. The separate UI lane is
building a runnable workbench example. The separate installed-consumer lane
is exercising multi-document commands, editing, transfer and failure paths.
Neither lane alone qualifies the package.

## Acceptance scenarios still to prove

1. Create two documents and multiple views; switch the active document while
   command chrome, inspector, selection and an editable grid remain scoped to
   the correct IDs.
2. Invoke one semantic edit from toolbar, keyboard, context menu and an
   accessible action. Preview/cancel and accepted edit must produce the same
   authoritative state and exactly one undo step where appropriate.
3. Copy from one document to another, validate/remap IDs, undo atomically,
   then sort/filter without changing the intended selected entity.
4. Run asynchronous work, close or switch its owner before completion, and
   prove stale results do not mutate the new active document.
5. Fail a save, keep the dirty document open, restore a validated recovery
   revision, switch and restore workspace state, and reopen saved content with
   equivalent values and identities.
6. Open compact and comfortable screenshots, record geometry dumps, pass
   focused and full integrated gates on both supported Qt versions, and run
   the installed workbench consumer.

The spatial `CanvasDocument` has an adapter boundary, but no shared
`DocumentSession` persistence or `UndoService` binding yet. That is recorded
in [WP-040](WP-040.md) and remains a separate integration issue to resolve
before accepting the spatial canvas package.
