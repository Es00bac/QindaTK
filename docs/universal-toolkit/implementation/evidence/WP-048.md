## Implementation and decisions

- **Exact core.** `TimelineTime` (portable 128-bit `mulDiv` with one explicit
  rounding, checked add/subtract, rescale, seconds text, rational grid lines)
  and `TimelineModel`: tracks, clips (exact start, duration, source offset,
  source duration) and markers (time or musical anchor) by UUID in a declared
  timebase (default 705,600,000 ticks/s). Per-track interval index, lazy edge
  indexes, bounded QML queries, JSON persistence `qindatk.timeline/1` with
  decimal-string ticks.
- **Transactions.** Typed `TimelineEditRequest`/`TimelineEditInput`
  (C++) and the same shapes as QML maps; revision-guarded `begin`,
  side-effect-free `update` previews, one `commit` = one history step,
  `cancel`. Sessions retire on any competing change (`editInvalidated`,
  later calls `StaleRevision`). Local history (256 steps, 64 MiB) with
  precondition-checked undo/redo; `externalUndo` bridge with `committed`
  payloads and guarded `applyHistoryChanges` (D-040 pattern).
- **Policy and planner.** `TimelineEditPolicy` capabilities with reasons,
  overlap mode, ripple scope, minimum length, source/negative-time bounds,
  kind matching, change-count limit and a C++ `validate` veto. The pure
  `TimelinePlanner` resolves move (rigid, cross-track), trim (clamped, media
  aligned), split (deterministic UUIDv5 right part), delete, ripple (union of
  removed intervals; locked tracks skipped), numeric timing, markers, tracks
  and clip insertion. `TimelineSnapper`: clip edges, markers, playhead, edit
  range and zero first; grid lines only when no object target is in reach
  (found while computing test answers: a 29.97 fps grid otherwise always beat
  a clip edge).
- **Virtualization.** `TimelineViewport` maps pixels from exact integer
  differences and publishes three key-diffed `TimelineVisibleList` models:
  retained rows keep their delegates, moved clips show a ghost at the
  committed place, tiny clips merge into summary rows under a 1,024-row cap.
- **Media seam.** `TimelineMediaProvider` with owner supersede, cancellation
  tokens, stale-result rejection, a queued pump (same-turn supersedes never
  reach the backend), bounded concurrency/queue/cache; host
  `TimelineMediaBackend`; a labeled synthetic reference backend (analytic
  peaks, frames reported unsupported).
- **Transfers (WP-016).** `TimelineClipboard` (copy/cut/paste as
  `TransferPayloadCodec` object items; timebase and foreign-media guards) and
  `TimelineDropTarget` (Copy-only `DropTarget`, snapshot-guarded commit).
- **Gallery.** `examples/gallery/TimelineSection.qml` shows a three-track
  session ([capture](WP-048-gallery-section.png)).
- **Views.** `EditTimeline` (+ `EditTimelineLanes`, `EditTimelineHeaders`,
  `EditTimelineCommands.js`), `TrackHeader`, `ClipItem`, `TimeSelection`,
  `MarkerLane`, `TimelineTimingEditor`. One pointer controller per surface
  (clip lanes, header column, marker lane) owns every drag, never a recycled
  delegate; edge autoscroll for clip, range, marker and track-reorder drags;
  keyboard map, revision-guarded numeric entry that keeps untouched values exact,
  accessible Pane/List/ListItem/Grouping/Slider/Splitter roles; the ruler's
  loop band shows the transport's acknowledged loop.
- **WP-027 not reused.** `VirtualCollectionAdapter` indexes one ordered list;
  a timeline needs two-axis interval virtualization (visible tracks × time),
  so rows come from `TimelineViewport` instead. Clip selection does reuse the
  WP-012 `SelectionModel`.
- Shared files touched for Sol's integration: `src/CMakeLists.txt` (new C++
  sources), `tests/CMakeLists.txt` (four tests), `examples/gallery/Main.qml`
  (one section line), `docs/controls.md`,
  `docs/controls-media.md`, `docs/index.md`, `docs/decisions-application.md`
  (D-045 after integration with the spatial canvas decision) and
  `docs/catalog.json` (+14 types, none removed).

## Independent review

A separate reviewer agent audited the lane at `9cae7d0` and reproduced 11
defects with scratch probes. Each has a fix and a regression test that fails
without it. Two of the QML tests were checked by reverting their fix: the
reorder and timing-editor cases both failed, then passed again once the fix
was restored.

| # | Defect (reproduced) | Fix | Regression test |
| --- | --- | --- | --- |
| 1 | A header reorder that stayed inside the dragged track's own slot sent `beforeTrackId: ""`, which means "last", so the track jumped to the end | the own slot names the track itself, which plans no change | `test_headerReorderFollowsItsOwnSlot` |
| 2 | Header resize/reorder lived in `TrackHeader` delegates; a preview that moved the track out of view destroyed the delegate and leaked the session, blocking every later edit | `EditTimelineHeaders` owns the gestures in one column pointer area (`trackHeaderPointer`; headers run with `gestures: false`), with reorder autoscroll | `test_headerDragOutlivesItsDelegate` |
| 3 | Escape in `MarkerLane` cancelled the drag, but the next move of the same press started and committed a new one | cancel and invalidation end the press | `test_markerEscapeEndsThePress` |
| 4 | Replacing `model` mid-drag left the old model's session open (lanes, marker lane, headers) | each surface remembers the session's model and cancels on `modelChanged` and destruction | `test_replacingTheModelCancelsEveryGesture` |
| 5 | `RippleAllTracks` parallel trims summed coincident edit points (clips after a 0.5 s trim moved 1 s) | identical edit points collapse; distinct points still accumulate | `parallelRippleTrimsInsertTimeOnce` |
| 6 | `planMove` added `minimum + delta` unchecked; a far-right pointer wrapped and committed the clip at 0 | checked add; overflow is refused | `extremePointersAreRejectedNotWrapped` |
| 7 | Lowering `historyLimit` dropped the nearest redo step first, so the remaining redo failed and cleared history | drop oldest undo steps, then the farthest redo steps | `historyLimitKeepsTheNearestRedo` |
| 8 | A tempo change retired an active edit only if a stored musical marker moved; a musical `addMarker` committed at a position never previewed | any `TimeMap` change retires the session | `timeMapChangeRetiresTheEdit` |
| 9 | `insertClips` templates with one ID planned two changes with one ID (preview ok, commit refused) | distinct template IDs are required at `begin` | `insertTemplatesNeedDistinctIds` |
| 10 | `M` over an existing cue selected the old cue by position, so Delete removed the wrong marker | commits return `createdIds`; the lane selects the new ID | `test_addMarkerAtAnOccupiedTickSelectsTheNewOne`, `commitReportsCreatedIds` |
| 11 | A click on a resize seam began and committed an empty session: "The edit has no preview to commit" | a resize begins on the first movement (also in standalone `TrackHeader`) | `test_resizeSeamClickIsNotAnEdit` |

The reviewer's suspected items were fixed as well:

- The timing editor now applies with the revision it opened at, so it cannot
  overwrite a newer value it never showed
  (`test_timingEditorRefusesValuesItNeverShowed`).
- Unchecked arithmetic now uses checked add/subtract: trim bounds, split
  distances, ripple-delete union lengths, numeric-timing ripple, marker
  applied delta, the copy start offset and the synthetic backend span.
  Musical-marker ends use `TimelineMarker::end()`, and derived positions
  saturate so that `end()` never overflows.
- Media provider:
  - signal arguments are copied before emitting, so a slot cannot leave them
    dangling;
  - a backend swap fails pending requests and then emits `backendChanged`,
    on which `ClipItem` asks again;
  - requests without an owner keep only the newest 1,024 finished results
    (`mediaBackendSwapFailsPendingAndBoundsUnowned`).
- The contract now documents that insert destination errors are hard (no
  preview), and that external history keeps at most 4,096 unreleased steps.

The reviewer found the exact arithmetic (2,000,000 randomized `mulDiv` cases
against `__int128`, grid brackets, seconds text), interval queries, key
diffing and the provider core correct. Two probe observations are documented
API semantics, not defects: an empty `beforeTrackId` appends, and a commit
with no preview is refused. The views no longer send either.

After the fixes, `examples/edit-timeline` dumps identical geometry and
delegate counts (91/13/1 compact, 70/10/1 comfortable), and a capture with a
1.5 s settle matches the committed one. The default 120 ms settle, under a
load average near 18, grabbed before the synthetic peaks arrived. A scratch
scene with two timelines, one mid-resize and one mid-reorder, gives:

                                 TrackHeader#trackHeader_…0003  0,136 150x56  (rows below follow)
EditTimeline#reorderingTimeline  trackHeader_…0003 0,0 · …0001 0,56 · …0002 0,112 · …0004 0,168  (preview 3,1,2,4)

  `d792898`, then fast-forwarded into `work/universal-implementation` at
  `05145cb`. D-045 preserves the existing canvas D-044; the combined catalog

  track headers, clip spans, waveform previews, marker and playhead are

  passed 100/101 cases, including every timeline case. The one failed case
  sampled a canvas pixel using a view coordinate cached before asynchronous
  page fitting finished. Commit `05145cb` recalculates that coordinate while
  waiting. The focused GPU case then passed on both Qt versions with three
  QtTest passes, zero skips, and an actual scene-graph provider. No production
  source changed after the full runs. The merged Qt 6.11 `all_qmllint` target
  exited 0. After the user's explicit concurrency override, the two focused
  test rebuilds used `cmake --build <dir> --parallel 4`. The user subsequently
  reinstated the configured MAKEOPTS policy for all new builds.
- A refreshed integrated Qt 6.11 stage now builds the standalone WP-048
  consumer. It imports the installed `Tk.TimelineModel` and `Tk.EditTimeline`,
  commits one exact tick move above 2^53, checks one undo step and exact
  undo/redo, then reloads JSON with the same UUIDs and tick values. The
  executable exited 0 offscreen on both Qt 6.11 and Qt 6.8 installed stages.
  The first compile exposed a missing `<QQuickItem>` include in the consumer;
  that is fixed.
- At shared revision `e18a86e`, the complete integrated CTest suite passed
  **101/101 on Qt 6.11** (89.62 s) and **101/101 on Qt 6.8** (87.34 s),
  including `tst_canvas_render_rhi`, all timeline suites, QML interaction and
  example smokes. The WP-048 production sources were unchanged after that
  revision; later changes here reconcile documentation and package status.
- Proposal checks covered: AUD-04 (move/trim many clips with snapping,
  autoscroll, cancel and undo; offscreen clips are rows, not delegates);
  AUD-05 (resize/reorder keep headers, clips and IDs aligned); AUD-06
  (move/resize under zoom with usable hit regions, one committed state);
  AUD-07 (crossing, empty and cancelled ranges documented and tested);
  AUD-08 (markers keep their anchoring across tempo/rate changes and reopen).
- **Dependency reconciliation.** D-045 assigns exact time-axis snapping to
  `TimelineSnapper`. WP-041's spatial SnapModel and selection handles do not
  serve the edit timeline, so they are not a prerequisite for this package.
  The documented `TimelineMediaBackend` seam deliberately lets hosts supply
  decoded peaks and frames. Audio engine/waveform integration belongs to
  WP-060/WP-063 and video decoding to WP-070; the synthetic reference backend
  is explicitly labeled. Neither
  codec implementation is part of AUD-04 through AUD-08's completion checks.
  These boundaries are recorded in D-045 and the manifest dependency was
  narrowed accordingly.
- **Accepted scope.** AUD-04 through AUD-08's actual completion checks pass:
  exact reversible edits, bounded virtualization, stable track/clip identity,
  usable hit regions, cancellation, range crossing, and marker anchoring after
  reopen. Native AT-SPI delivery of virtual clip items (WP-092), a real engine
  behind `TransportAdapter` (WP-060), and touch-density qualification remain
  downstream workflow work.
