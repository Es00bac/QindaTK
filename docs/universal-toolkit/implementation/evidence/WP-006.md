# WP-006 — Layout and scrolling contracts

**Status: accepted for the documented Qt 6.8.3 and 6.11.1 Linux paths,
2026-09-23.** The [initial diagnostic](WP-006-diagnostics.md) preserves the
pre-change observations. Each assigned foundation obligation has an explicit
implementation or supported limit below.

| Obligation | Integrated disposition and evidence |
| --- | --- |
| FND-01 baseline and intrinsic behavior | Flex aligns actual child baseline offsets on each row; its fallback for a plain Item uses the bottom edge. Runtime width and font changes propagate through Flex, Grid, Box and Scroll when children publish implicit size. [Intrinsic tests and boundary](WP-006-FND-01-intrinsic.md), [baseline dump and pixel record](WP-006-diagnostics.md#subsequent-integrated-baseline-repair). |
| FND-02 Grid tracks | D-020 defines a bounded responsive auto-fill/auto-fit grammar, finite minmax behavior, invalid-prefix fallback, existing intrinsic aliases and `1fr` zero-floor compatibility. Parser, resize, placement, overflow and screenshot checks are in the [Grid evidence](WP-006-grid.md). |
| FND-03 direction and narrow layout | Flex, Grid and Stack have explicit `layoutDirection` with logical Start/End geometry under D-019. The [adaptive fixture](WP-006-FND-03-adaptive.md) verifies compact/comfortable, LTR/RTL and 1×/2× text. At 2× it grows its content and scrolls rather than overlapping sections. |
| FND-04 per-side Box edges | The conditional support decision retains square per-side edge rectangles with a rounded background; `radius: 0` is recommended for per-side rules. [Diagnostic pixels](WP-006-diagnostics.md#subsequent-stack-direction-and-box-support-decision) and `docs/layout.md` state the exact boundary. |
| FND-05 nested scrolling | D-021 defines hard bounds and event handoff. Inner and outer Scrolls, Grid-cell Scroll, and canvas Viewport fixtures cover wheel, keyboard, paging, focus reveal, Ctrl+wheel zoom and horizontal-overflow policy. [Focused event evidence](WP-006-scroll.md). |

## Integrated verification

The live `portageq envvar MAKEOPTS` reported `-j24 -l24`. Direct Ninja
builds used those configured job and load limits unchanged. The final
integrated source builds and passes **19/19 CTest targets on Qt 6.11.1 and
19/19 on the isolated Qt 6.8.3 SDK**. Both `all_qmllint` targets exit 0;
existing unqualified-access warnings remain. The 19 targets include
`tst_layout`, `tst_layout_intrinsic`, `tst_qml` and all example smoke tests.

The 360×300 adaptive fixture's 2× compact LTR dump reports
`Flex#adaptiveFlex 4,4 352x182`, `Item#adaptiveGridHost 4,198 352x150`
and `Stack#adaptiveStack 4,360 352x98`; its Scroll content is 462px high.
At comfortable RTL the corresponding positions are `5,5 350x218`,
`5,237 350x180` and `5,431 350x154`, with 590px Scroll content. All four
2× software captures and all four OpenGL RHI captures were opened. The
OpenGL renderer was the AMD Radeon RX 5700 XT; a Qt 6.8.3 OpenGL capture
was also opened. Compact/comfortable diagnostic captures on software and
OpenGL were inspected for baseline placement, mirrored layout, square Box
edges and clipped nested Scroll content.

## Public support limits

- Responsive Grid auto-repeat accepts one sole bounded `minmax` track
  expression. Intrinsic keyword aliases and spanning flexible-track limits
  are specified in D-020; named lines, subgrid and CSS-equivalent distinct
  min/max-content measurement are outside this contract.
- A width-dependent child must publish its implicit size for a parent to
  measure it. Geometry-only children need an explicit implicit-size wrapper.
- Scroll hands off ordinary wheel and key events when a viewport cannot move.
  A touch drag stays with the viewport where it began. Physical trackpad
  phases, touch hardware and other operating systems remain platform
  qualification work. Vulkan could not initialize through this host's
  headless offscreen platform; the inspected GPU path uses OpenGL RHI.
- Box per-side rules have square ends even when its background is rounded.

Layout containers are not editable controls, so the completion gate's
default/reset/mixed edit contract does not apply. Keyboard/focus behavior
for the scrolling controls is covered by the event tests above. Theme roles,
objectNames, examples, `docs/layout.md`, ADRs D-019 through D-021 and the
generated catalog were reviewed with the integrated source.
