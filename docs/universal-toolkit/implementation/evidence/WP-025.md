# WP-025 — Preferences, shortcuts and find/replace

**State: accepted.** Proposal scope: CTL-10 ShortcutEditor, CTL-11
PreferencesDialog and CTL-25 FindReplaceBar. Contracts are in
[settings/workspace](../../../settings-workspace.md),
[commands](../../../commands.md), [find/replace](../../../find-replace.md)
and the [control catalog](../../../controls.md).

## Behavior delivered

- PreferencesDialog stages registered SettingsModel descriptors, validates
  values, separates Apply from Cancel, exposes reset and restart indication,
  and keeps schema authority in C++.
- ShortcutEditor captures portable sequences, validates active-scope
  conflicts through ShortcutMap, persists JSON text in the registered
  `app:shortcuts.overrides` setting, and reloads it into a fresh map.
  Capture completion, Escape and Tab restore focus to the stable row or
  search-field fallback; the host also receives `focusReturnRequested`.
- FindReplaceBar uses FindReplaceService against a real QQuickTextDocument.
  Search snapshots run off the GUI thread, reject stale revisions, support
  scope/cancellation, and block replacement in read-only or composition state.
  Replace All uses one QTextCursor edit block so one undo reverts the group.

## Preferences review closure

Review found that Escape and programmatic popup close could leave a settings
stage open across reopen, and Return could bypass Apply. A hidden invalid
setting could not receive keyboard focus. `PreferencesDialog` now discards its
stage on hide/destruction, validates the focused editor before Return/Enter
applies, reveals an invalid key by clearing filters, and focuses its editor
after the virtual list materializes. The list area now has measured height and
Flex widths; the first validation screenshot exposed a zero-width editor,
which was corrected before the final focused run.

The named Qt 6.11 `tst_wp025_preferences_dialog.qml` lifecycle fixture passed
**5/5** with zero QML warnings. The existing WP-025 fixture passed **11/11**.
Root opened the [compact](WP-025-invalid-compact.png) and
[comfortable](WP-025-invalid-comfortable.png) captures. The invalid shortcut
editor is visible, focused and 96×24 compact or 116×29 comfortable; the
category rail is 120px or 145px wide, and the validation message is readable.
The compact popup is 420×265 and the comfortable popup 504×312. The final dual-Qt and installed-consumer gates passed in the acceptance batch.
