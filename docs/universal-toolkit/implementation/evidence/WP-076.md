# WP-076 initial scene core slice

Status: implementation slice for integration; full WP-076 is not accepted.

## Delivered

- `SceneModel3D`: stable primitive IDs, bounded hierarchy, local/world transform
  snapshots, exact uniform-scale keep-world reparent, appearance/visibility,
  world-space snapped manipulation transactions, cancel/undo/redo and atomic
  native save/reopen.
- `SceneView3D`: actual optional Qt Quick 3D shaded geometry, nearest mesh picking,
  public pixel/world projection and hit results, camera-plane drag and arrow-key
  translation, Escape/pointer/model replacement cancellation.
- Native scene fixture, gallery entry, API/limits documentation and focused core
  and GPU interaction scenarios. No complete 3D application was built.
- Qt Quick 3D is discovered quietly and only its renderer file is omitted if
  unavailable. The scene model and view still build on SDKs lacking that module;
  the view displays an unavailable state.

## Focused validation

System `portageq envvar MAKEOPTS` returned `-j24 -l24`; all direct CMake builds
used the same limits. Worktree build directory is `build/wp076`.

The model scenario verifies a child under a rotated/scaled parent, keep-world
reparent, snapped world movement, exact cancellation, one undo step, persistence
of committed state during a preview, save/reopen and inherited visibility.
The scenario found and fixed a real round-trip drift: the decoder no longer
renormalizes quaternions that are already unit length within float tolerance.

The GPU scenario verifies Qt's actual mesh picking, world/pixel mapping,
drag/undo and Escape cancellation while the same pointer press continues.
It runs separately from the default software QtQuickTest suite in `tests/gpu/`.

The machine's offscreen OpenGL platform exposed only GLSL 1.20, which could not
render these Quick3D shaders. Native xcb/OpenGL produced actual shaded pixels;
no software imitation was used. The software adaptation displays unavailable.

## Remaining scope

See [scene-3d.md](../../../scene-3d.md): complete outliner, axis/rotation/scale
gizmos, imported meshes/instances, material editing/preview, camera navigation,
shared document history, device loss/multiple-view qualification, Qt 6.8 and
accessibility traversal remain outside this initial slice. Uniform positive
scale is intentional; nonuniform transforms/shear are unsupported.

## Final lane results

- Configured and built `tst_scene_model_3d`, `qtk-preview` and `qindatkplugin`
  from the isolated tree with Qt 6.11.1 and the configured `-j24 -l24` limits.
- Focused CTest: **3/3 passed** (`tst_scene_model_3d`, `example_scene-3d`,
  `example_gallery`). The gallery and scene smoke tests use software fallback.
- Native production plugin interaction scenario: **3/3 passed** (init, the single
  pick/drag/undo/cancel scenario, cleanup) via `qmltestrunner`, xcb/OpenGL.
- Actual final shaded pixels captured in `WP-076-scene-3d.png` and opened for
  inspection. The image shows the cube, sphere and cylinder from scene data.
- Dump: `SceneView3D#sceneView3D 12,98 1056x589` and
  `SceneView3DRenderer#sceneRenderer3D 0,0 1056x589` at logical 1080x720.
- `gen_catalog.py` regenerated the catalog; `git diff --check` passed.

is a known follow-up alongside the renderer/device lifecycle work above.
