# WP-076 initial scene core slice

Status: initial scene core is integrated; full WP-076 is not accepted. Shared
document undo, save/reopen and recovery are now integrated as a later
[scene session slice](WP-076-scene-session.md), alongside the
[material slice](WP-076-materials.md). The
[completion slice](WP-076-completion.md) adds the on-object gizmo, the
render-resource lifecycle and the requirement-by-requirement disposition.

## Delivered

- `SceneModel3D`: stable primitive IDs, bounded hierarchy, local/world transform
  snapshots, exact uniform-scale keep-world reparent, appearance/visibility,
  world-space snapped manipulation transactions, cancel/undo/redo and atomic
  native save/reopen.
- `SceneView3D`: actual optional Qt Quick 3D shaded geometry, nearest mesh picking,
  public pixel/world projection and hit results, camera-plane drag and arrow-key
  translation, Escape/pointer/model replacement cancellation.
- Native scene fixture, gallery entry, API/limits documentation and focused core
  and GPU interaction scenarios. No complete 3D application was built.
- Qt Quick 3D is discovered quietly and only its renderer file is omitted if
  unavailable. The scene model and view still build on SDKs lacking that module;
  the view displays an unavailable state.

## Focused validation

System `portageq envvar MAKEOPTS` returned `-j24 -l24`; all direct CMake builds
used the same limits. Worktree build directory is `build/wp076`.

The model scenario verifies a child under a rotated/scaled parent, keep-world
reparent, snapped world movement, exact cancellation, one undo step, persistence
of committed state during a preview, save/reopen and inherited visibility.
The scenario found and fixed a real round-trip drift: the decoder no longer
renormalizes quaternions that are already unit length within float tolerance.

The GPU scenario verifies Qt's actual mesh picking, world/pixel mapping,
drag/undo and Escape cancellation while the same pointer press continues.
It runs separately from the default software QtQuickTest suite in `tests/gpu/`.

The machine's offscreen OpenGL platform exposed only GLSL 1.20, which could not
render these Quick3D shaders. Native xcb/OpenGL produced actual shaded pixels;
no software imitation was used. The software adaptation displays unavailable.

## Remaining scope

See [scene-3d.md](../../../scene-3d.md): imported meshes/instances, material
editing/preview, camera navigation, shared document history, device loss and
multiple-view qualification, Qt 6.8 and accessibility traversal remain open.
Uniform positive scale is intentional; nonuniform transforms/shear are
unsupported.

## Integrated outliner and transform controls

The merged scene example now includes `SceneOutliner` with keyboard selection,
visibility and drag-to-parent, plus translation, rotation and scale modes with
explicit world/local axis constraints in `SceneView3D`. The configured
`-j24 -l24` integration build passed. Focused merged CTest passed 4/4 across
the scene model, scientific plot and both example smokes; the outliner QML
scenario passed 5/5 and the native xcb/OpenGL scene interaction passed 3/3.

[`WP-076-scene-combined-gpu.png`](WP-076-scene-combined-gpu.png) was captured
from the merged example at logical 1080×720 (`--gpu --wait 2000`) and opened.
It shows legible outliner rows and toolbar text alongside shaded cube, sphere
and cylinder pixels. The dump locates `SceneOutliner#sceneOutliner` at
0,0 270×589 within the lower 1056×589 work area. The screenshot is 1620×1080
physical pixels due to 1.5× display scale.

The next focused GPU interaction run passed 4/4 after adding right-drag orbit,
middle-drag pan and wheel-step zoom to the reusable viewport. The navigation
scenario verifies the camera changes without opening a scene edit; the existing
pick, transform, cancel and undo scenario still passes.
