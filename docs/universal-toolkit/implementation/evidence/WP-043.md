# WP-043 — Document color and curve editing

**State: active presentation and numerical color slices; package not accepted.**
Its WP-040 dependency, color display/proof integration and curve backend work
remain open.

`Tk.CurveEditor` is a reusable host-data curve surface. The host supplies
stable-ID normalized knots and an already evaluated sample line. The control
maps those values to view coordinates and reports knot selection, move
preview, finish and cancel through pointer, keyboard and accessible actions.
A click selects without committing. Pointer ownership stays on the editor
root, so replacing the host knot array during a preview does not lose the
gesture. The host owns canonical interpolation, constraints, transactions,
undo and persistence.

The focused QML suite passed **4/4** on Qt 6.11.1 and Qt 6.8.3. It checks
normalized/view mapping, stable ID requests, cancel without mutation, a
selection click without finish, and a drag that finishes after the host
replaces knot records. The scene passed `qtk-preview --check` on both Qt
versions. The compact dump showed `CurveEditor#curveSceneEditor 12,54
876x534`, `CanvasItem#curvePlot 10,10 856x514`, and four 20×20 hit targets
`curveKnot_black`, `curveKnot_shadow`, `curveKnot_midtone`,
`curveKnot_white`. Sol opened the
[compact](WP-043-curve-compact.png) and
[comfortable](WP-043-curve-comfortable.png) 900×600 captures; the supplied
cyan sample line and all four knots remain inside the plot at both densities.
The reproducible scene is
[CurveEditorScene.qml](../../../../examples/spatial-canvas/CurveEditorScene.qml).
After integration, the full Qt 6.11.1 and Qt 6.8.3 CTest suites each passed
**102/102**.

`Tk.GradientEditor` presents host-owned stable-ID color stops. It requests
selection, insertion, preview, finish, cancel and deletion; the host owns
canonical order, values, transactions and undo. The live stop preview follows
the pointer, keyboard and accessible increase/decrease actions nudge by a
configurable normalized step, and a drag returned to its starting value
emits cancel. Focused Qt 6.11 QML tests passed **9/9**, covering those
interactions and host record replacement during a drag. The preview dump
places `GradientEditor#gradientEditor 12,12 876x40`,
`CanvasItem#gradientPreview 1,1 850x16` and three stable stop targets.
The same focused **9/9** QML suite passed on Qt 6.8.3. Sol opened the
[compact](WP-043-gradient-compact.png) and
[comfortable](WP-043-gradient-comfortable.png) captures; the preview and
three colored stops render at both densities. The fixture is
[Main.qml](../../../../examples/gradient-editor/Main.qml).
The shared Qt 6.11 and Qt 6.8 CTest suites each passed **104/104** after
the gradient integration.
`all_qmllint` exited 0 with existing warnings outside this control; the
catalog generator and preservation fixtures passed at 264 types.

`Tk.ColorPicker` now presents a host-owned sRGB saturation/value square,
hue rail and optional alpha rail. It emits preview, finish and cancel requests
without changing the host's committed color. Sol reviewed the normalized Qt
`hsvHue` contract and added cyclic hue nudges and optional alpha sizing. The
focused QML suite passed **6/6 cases** on both Qt 6.11.1 and Qt 6.8.3 after
review; the example passed `qtk-preview --check` on both. Sol inspected the
[compact](WP-043-colorpicker-compact.png) and
[comfortable](WP-043-colorpicker-comfortable.png) captures; geometry and
interaction details are in the [picker evidence](WP-043-colorpicker.md).

`ColorProfile` / `ColorContextSnapshot` / `ColorEngine` add an isolated C++
numerical slice ([contract](../../../color.md)). Profiles own their validated
RGB ICC containers and SHA-256 identities. The Little CMS backend converts
Float32 RGB with relative colorimetric intent/BPC off, preserves straight alpha
exactly, tags results with destination IDs and context generations, and bounds
its compiled-transform LRU. It reports unavailable/mismatched profiles and
unsupported proof/model/intent operations instead of guessing. Gamut remains
unknown, and canvas/gradient preview paths are not changed by this slice.

**Numerical verification:** Qt 6.11.1 / LCMS 2.19 focused CTest passed **1/1**
(`tst_color_engine`, **8/8** QtTest checks). The isolated build used the
configured `-j24 -l24` limits. Fixtures include
fixed sRGB/linear ICC bytes and independent piecewise equations, both transfer
knees, known 0.5 conversions, colored values, alpha zero, malformed profiles,
Float32 range rejection, destination routing and cache eviction. The numerical
tolerance is absolute `2e-6` against the ICC's serialized 16.16 transfer
coefficients; ideal sRGB 0.5 references use `1e-5` to allow that quantization.
Observed decoding/encoding were `0.2140451968` / `0.7353545427`, versus ideal
`0.2140411405` / `0.7353569831`. Alpha is copied exactly, including a double
not exactly representable as Float32. Catalog regeneration remained **264
types**, with no generated diff in Astra's isolated branch.

After integration with the picker, `docs/catalog.json` contains **265 types**.
The focused color-engine CTest passes **1/1** on Qt 6.11.1 and Qt 6.8.3. Both
standalone installed consumers pass on the shared branch. Each compiles using
only the staged public
headers and `QindaTK::qindatk`, converts an ICC-tagged midpoint and checks
the destination identity, generation and unchanged straight alpha. QML lint
exits 0; the new picker file has no direct qmllint diagnostics.
The earlier shared **104/104** suites predate these WP-043 slices; they were
not repeated for this active package.

`CurveEvaluator` now defines typed axes, normalized stable-ID knots and
absolute tangent handles. Its stateless validator and evaluator cover step,
linear and cubic interpolation plus hold, linear and repeat edges. The
[backend evidence](WP-043-curve-backend.md) records the analytical fixtures;
after integration, its focused CTest passed **1/1 on both Qt 6.11.1 and Qt
6.8.3**. The control still receives host samples; no document transaction or
QML codec has been connected to the evaluator.

**Still required:** tangent and multi-knot edit integration, domain-specific
constraints, an authoritative transaction/undo/persistence path,
proof/output-profile fixtures, managed display integration, stop interpolation
and typed picker integration, and numerical plus software/GPU output fixtures.
