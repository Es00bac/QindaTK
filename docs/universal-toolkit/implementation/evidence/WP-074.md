# WP-074 — Node-based compositing

**State: ready for acceptance (branch `work/wp074-finish`); not yet accepted.**

`NodeGraph` is a reusable editor for host-supplied node, edge and group
snapshots. `NodeGraphModel` is the reference host: a typed image-processing
graph that validates every request, keeps history and renders pixels. The
[live fixture](../../../../examples/node-graph-live/Main.qml) connects the two.
Contracts: [node graph](../../../node-graph.md) and the `NodeGraph` rows in
[controls](../../../controls.md).

## Requirements

1. **Identity, typing, cycles, parameters, invalidation.** Node, edge and group
   IDs are stable UUIDs. One type table defines typed ports (`image`, `mask`,
   optional inputs) and parameter identity (ID, value type, range/options,
   default), published as `nodeTypes`. `connectPorts` rejects unknown or deleted
   ports, mismatched types, self links, cycles and occupied inputs without
   changing the revision. Changed parameters, pixels or links invalidate only the
   node and its downstream cache; `render()` returns `evaluatedNodeIds` so this
   can be observed.
2. **Processing.** `source`, `solid`, `mask` (rectangle or ellipse), `transform`
   (translate, scale, rotate about the canvas centre), `blend` (8 modes,
   opacity, optional mask input) and `output`.
3. **Navigation and editing.** Pan and zoom (fixed Ctrl+wheel zoom about the
   pointer, see below), search with outlined matches and next/previous reveal,
   group frames (select, drag, group, ungroup), multi-selection, add-node
   menu, node removal, a live link preview, and keyboard paths for all of
   these (listed in controls.md). Keyboard linking picks the first free input
   of the armed output's type.
4. **Transactions, cancellation, errors, serialization.** `beginEdit`,
   `commitEdit` and `cancelEdit` turn one gesture into a single undo step, or
   restore the graph and redo stack. Escape, or a drag grab taken by another
   handler, emits no move request. A pending link whose source node is removed
   is dropped. A failed render keeps the last good frame, and the error can be
   fixed by editing or undo. Graph files are now version 2 (adds groups);
   version 1 still loads, and newer versions are rejected before the graph
   changes. Node cards and frames draw snapshots only; they hold no engine
   state.
5. **Verification.** Covered by the tests below.

**Accept when:** the fixture edits a real typed graph through the model and
shows the rendered frame, render errors and undo/redo. Rejected links show the
model's error in the graph status bar.

Two defects in the existing code were fixed:

- Ctrl+wheel zoom read `event.point`, which WheelEvent does not have (qmllint
  `missing-property`). It now uses `event.x`/`event.y`, covered by
  `test_ctrl_wheel_zooms_about_the_pointer`.
- The old fixture never bound selection, so its Disconnect button could never
  be enabled. The fixture now binds it.

## Scope notes (outside this package)

- **Large-graph and alternate-Qt qualification**: WP-091 (performance and
  fault) and WP-088 (platform). Nodes outside the viewport are not loaded;
  1,000-node latency has not been measured here. The Qt 6.8 build, full ctest
  and installed-consumer build run at the integrator's checkpoint.
- **Screen-reader (AT-SPI) run and localization of model-supplied labels**:
  WP-092. Roles, names and tooltips are set on every part. The port and type
  labels in the type table are English data strings; hosts can map `type` and
  `portId` to their own labels.
- **Long-running or background renders with job cancellation**: WP-078 (durable
  render queues). This evaluator is synchronous and bounded by its documented
  limits.
- **Decoded-media sources**: WP-070. Hosts bind tagged sRGB pixels through
  `setSourceImage`.
- **Grading and filter nodes, linear-light and colour-managed compositing, and
  GPU effects**: WP-072 and WP-089.
- **Groups**: they are frames that move, persist and undo with their members.
  Nested subgraph nodes are not claimed, because neither WP-074 nor VID-13
  requires them.

## Blockers

None known. The integrated checkpoint checks listed above are still pending.
