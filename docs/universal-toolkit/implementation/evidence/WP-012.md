# WP-012 — Reversible editing, selection, properties and validation

**State: accepted.** WP-010/011 are accepted prerequisites. This integrated
change implements APP-04 UndoService, APP-05 EditTransaction, APP-06
SelectionModel, APP-10 PropertyBinding and APP-11 ValidationModel against a
small authoritative PropertyDocument. The public contract is documented in
[editing](../../../editing.md) and [D-028](../../../decisions.md#d-028--keep-edit-previews-transient-and-history-keyed-by-document-identity).

## Scope and behavior

- `PropertyDocument` stores typed descriptors and committed values by UUID
  entity ID. It publishes a transient preview separately from the committed
  revision, validates every target before multi-target mutation, and
  invalidates reference history on structural/metadata changes. Its reset
  generation distinguishes replaced models even when IDs or revision happen
  to look familiar.
- `EditTransaction` holds original values and the starting snapshot, accepts
  repeated preview updates, runs typed/domain validation at commit, rejects
  stale revision/generation and restores the committed presentation on cancel,
  rejected validation, or controller destruction. One gesture records one
  inverse step. Commit notifications publish only after both model state and
  history are available.
- `UndoService` keeps independent document histories and an active-document
  facade. It supports undo/redo, saved clean cursor/revision, branching,
  adjacent merge keys, macro groups, an estimated inverse-data budget and
  conservative history invalidation after structural mutation. Oversized
  value edits are rejected before commit. No inverse operation relies on a
  delegate pointer or row index.
- `SelectionModel` stores selected/current/anchor UUIDs; visible-order ranges
  are resolved at invocation time. Full-model reconciliation and reset retain
  surviving IDs and drop removed IDs without emitting a user-selection signal.
- `PropertyBinding` projects descriptor, common/mixed value, default,
  writable/animated and error states from the model. Owner refresh is silent
  as user intent; accepted edits go through the shared transaction and emit a
  distinct signal. Exact 64-bit integer edits use decimal strings.
- `ValidationModel` tags runs with document/revision/reset generation, keeps
  pending distinct from invalid, rejects stale completion, and exposes first
  relevant issue target/path for focus navigation.

## Verification

- Focused C++ tests cover one drag/multi-target edit as one history step,
  atomic observer state, cancel/rejected validation, stale revision/reset,
  memory rejection, clean/branch/merge/macro behavior, two document histories,
  read-only/mixed/default/exact integer binding, ID selection across sort,
  filter, deletion/reset and stale asynchronous validation. The cross-path
  `tst_edit_workflow` uses a real `Tk.NumberField` operation, a real `Tk.Slider`
  pointer drag and a scoped `CommandRegistry` handler to edit one reference
  property, then verifies undo and document isolation.
- Qt 6.11.1 and Qt 6.8.3 integrated full builds and CTest passed **32/32 each**
  against the final source after the macro-history and canonical-ID fixes.
  `all_qmllint` exited 0 on both versions; longstanding unrelated QML lint
  warnings remain in existing controls.
- A standalone [installed editing consumer](../../../../tests/consumer/editing/README.md)
  configures against the staged Qt 6.11 package, links only
  `QindaTK::qindatk`, imports the installed QML module as `Tk`, edits through
  QML `PropertyBinding`, undoes/redoes from C++, resolves stable selection and
  rejects a stale validation result. It was rebuilt against the final staged
  headers/library/QML module and its offscreen run exited 0.
- There is no new visual control or layout geometry in this package; the
  existing NumberField and Slider surfaces are exercised for behavior.
  Screenshot/dump evidence does not apply to the service additions.
- The generated `docs/catalog.json` contains 117 exported types, including
  the six new QObject types. `git diff --check` and a nonblank-line audit
  passed; every new code/test file is below 500 nonblank lines.

## Boundaries

The reference document handles typed property values, not domain-specific
structure, persistence or collaboration. External structural edits clear its
value history. A richer application engine can adapt the transaction and
history contract while retaining its own authoritative data and inverse
records. Numeric ranges, asset validity and cross-property rules come from
application validators. UI controls supply interaction signals and gesture
boundaries; they do not own undo history. Native assistive delivery and later
domain editing surfaces remain separately qualified packages.
