# WP-085 — Scientific plotting

**State: accepted after integration.**

## Working capability

`Tk.ScientificDataset` ingests 1D ordered float64 X/Y samples with stable IDs,
declared units, optional host-supplied one-sigma Y uncertainty and explicit
missing Y. It validates a complete replacement before publishing it. The
full source remains available in a `QAbstractListModel`, CSV and deterministic
JSON figure metadata with SHA-256 of all samples and host parameters.

`Tk.ScientificPlot` uses the existing `ChartAxis` and `UncertaintyView` paths
for calibrated linear/log axes, error bars or bands, data-coordinate cursor,
stable sample selection and a full source table. The renderer paints the
figure title and preserves source and render parameters in PNG/SVG metadata.

### Requirement 1 — array shape, units, dimensions, missing values, precision, uncertainty

- Built: `ScientificDataset` gains `kind` (`Trace` ordered / `Scatter` any X),
  `dimensions` 2 or 3 with `z`/`zUnit`, `label`, asymmetric Y
  (`sigmaYLow`/`sigmaYHigh`) and X (`sigmaX`, `sigmaXLow`/`sigmaXHigh`)
  offsets, `extent()` and bounded `samplesInRange()`. New `ScientificGrid`:
  float64 rectilinear lattice, `shape [rows,columns]`, `null` = missing,
  non-finite rejected, atomic `replaceGrid`, `Nearest`/`Bilinear`
  `interpolate()` that never fills holes, bounded `window()`, CSV and
  SHA-256 metadata. Semantics in `docs/scientific-plot.md`, decision D-138.
- Tests: `tst_scientific_plot` `asymmetricAndXUncertainty`,
  `scatterAnd3DSamples`, `nonFiniteAndBoundedAccess`,
  `gridSemanticsAndInterpolation` (plus the two first-slice cases).

### Requirement 2 — traces, scatter, sampled surfaces with axis/selection/annotation support and bounded data access

- Built: `ScientificPlotRenderer` (new) behind `ScientificPlot`: any number of
  trace/scatter series, X and asymmetric Y error bars or bands, a
  `ScientificGrid` colour map with colour bar, `ChartAnnotationModel` point
  and line annotations, legend, calibrated linear/log ticks with axis titles
  and units, unit-mismatch refusal (`problem`), click and keyboard selection
  across series, `dataAt` with surface Z, bounded painting (M4 trace envelope,
  scatter stride with extremes, surface raster at most 1,024², D-139), data
  tables for series and surface nodes, text `summary`.
  `ScientificFigureComposer` exports multi-panel figures.
- Tests: `tst_scientific_figure` `multiSeriesProjectionAndSelection`,
  `calibratedTicksAndLogLimits`, `downsamplingKeepsExtremesAndGaps`,
  `surfaceLayerCursorAndHoles`, `annotationsAndReproducibleExport`,
  `composedPanels`; QML `tst_scientific_plot.qml`
  `test_two_series_surface_keyboard_and_table`.

### Requirement 3 — 3D scatter/surface providers on the scene/render boundary with explicit interpolation and camera transforms

- Built: `ScientificScene3D` (data-to-scene transform, explicit
  resolution × resolution interpolation lattice with holes, 3D points, orbit
  camera with view/projection matrices, `project`, picking, export),
  `ScientificGeometry3D` (Qt Quick 3D upload; built only when Qt Quick 3D is
  found), `ScientificPlot3DRenderer.qml` (View3D bound to the scene camera),
  `ScientificScene3DView` (software view with the export painter) and the
  `ScientificPlot3D` control. Decision D-140.
- Tests: `tst_scientific_scene3d` `mappingAndCameraTransforms`,
  `surfaceMeshAndInterpolation`, `pointsSelectionAndReproducibleExport`; QML
  `test_software_3d_orbit_pick_and_summary`; example smoke test
  `example_scientific-plot-3d` (software).
- Scope note (superseded by the audit fixes below): the GPU path now has a
  headless buffer test and a display test with scene-graph loss. Render
  context loss on every claimed platform/backend is WP-088 item 2.

### Requirement 4 — reproducible export with data/parameter provenance and a textual/tabular alternative

- Built: PNG/SVG export for 2D figures, composites and 3D scenes embedding
  full source metadata (samples or lattice SHA-256), render and camera
  parameters; byte-identical repeated exports (D-141). Textual alternatives:
  `summary`/`textSummary()`, long-format `csvData()`, series and surface
  tables, 3D lattice CSV and source table.
- Tests: `annotationsAndReproducibleExport`, `composedPanels`,
  `pointsSelectionAndReproducibleExport` compare repeated export bytes and
  read the embedded metadata.

### Requirement 5 — verify analytic functions, units/log limits, downsampling, non-finite data, reproducible exports

- Built as tests: analytic `y = x²`, `z = 2x + 3y/10`, `z = x + y`,
  `z = xy` (bilinear-exact) and saddle fixtures with exact expected values;
  unit mismatch and log-domain omission; 100,000-sample envelope keeping a
  spike and a gap; NaN/∞/overflowing endpoints rejected; repeated export
  byte equality.
- Scope note: performance measurement of large data belongs to WP-091
  (Complete performance and fault qualification, deferred by the user).

### Accept when — renders and exports real numeric data with declared precision and sampling behavior

- Built: examples `scientific-plot` (two figures: decay with asymmetric error
  bars, gap, model trace and annotations; Gaussian surface with probes) and
  `scientific-plot-3d` (saddle surface with a hole and probes). Export
  metadata declares `float64` precision and the sampling method and counts.
  Visual `--grab` checks are for the integrator's round build.
- Scope notes: output-fidelity comparison (GPU image vs export) is WP-089
  (Qualify format, device and output fidelity); screen-reader runs and
  translation are WP-092 (accessibility, localization and input); other
  platforms/backends are WP-088 (Linux only, by the user); SDK packaging is
  WP-093. WP-089 and WP-091 to WP-094 are deferred by the user. Out-of-core arrays beyond the in-memory bounds are not
  provided; hosts window data into the models (D-138).

## Audit of round cf1 and the fixes (branch `work/wp085-cf`)

An independent read-only audit of `8584ba8` found requirements 1, 2 and 5
largely met and listed eight gaps. Each was re-checked against
[WP-085](../phase-07-integrations.md#wp-085) and the code; all eight were
real. `round/cf1` was merged first (fast-forward).

| # | Audit finding | Change |
|---|---|---|
| 1 | The GPU 3D view bypassed the WP-076 render boundary and had no device-loss recovery | `ScientificPlot3D` now follows the `SceneView3D` lifecycle: `renderGeneration`, `resetRenderer()`, and renderer replacement on `sceneGraphInvalidated`, so every GPU buffer is rebuilt from `ScientificScene3D`. D-140 now says why `SceneModel3D` is not used (an editable entity document with undo; plot geometry is derived data). |
| 2 | Nothing tested `ScientificGeometry3D` or the GPU renderer | New `tst_scientific_geometry3d` (headless): vertex layout, surface vertices equal the mesh, octahedra per point, frame lines, bounds, problem/destroyed states, selection patch. New `tst_scientific_plot3d_render` (display + RHI, skips headless like `tst_scene_view_3d_render`): GPU pixels at projected surface/point positions, real scene-graph loss, recovery, `resetRenderer()`. |
| 3 | Export provenance left out selection, colours, fonts and metrics | 2D `render.selection` + `render.style`, 3D `selectedPoint` + `style` + `pointSampling`, composite `style`: every colour/ramp (`#AARRGGBB`), the metrics map, requested and resolved font family (`ScientificSampling::styleJson`). D-141 updated. |
| 4 | With a surface present, 3D points had no tabular alternative | `tableSource` (`"surface"`/`"points"`) with a switcher when both exist, `pointsCsvData()` (every sample, with units), lattice CSV gains unit columns, `summary` names up to eight points with coordinates and the selected point. |
| 5 | 3D points were unbounded (up to 100,000 octahedra, ~96 MB per rebuild, rebuilt on every selection) | `pointLimit` (default 4,096, max 16,384): stride thinning keeping X/Y/Z extremes and the selection; a selection among drawn points is no longer a mesh change and patches only two points' vertices (`setVertexData(offset, …)`). |
| 6 | Byte reproducibility only tested for PNG from one instance; embedded samples never read back | Fresh-instance PNG and SVG byte equality for 2D and 3D; embedded samples compared value by value to the input; SVG metadata decoded and compared with the PNG's. |
| 7 | `setKind()` left `intervals` stale | Kind changes re-project `intervals` (Scatter empties, Trace refills); tested. |
| 8 | Scope notes cited the wrong packages | Performance → WP-091, output fidelity → WP-089, screen reader/translation → WP-092, per-platform render-context loss → WP-088, SDK → WP-093; header no longer says "first slice" only. |
| 9 | Found while verifying 4 (not in the audit): every `ScientificPlot`/`ScientificPlot3D` table had empty cells, because `Tk.DataTable` reads rows with `get(index)` and neither model had one | `ScientificDataset.get` (`sample()` plus units) and `ScientificGrid.get` (row-major node plus units); QML tests read the cells through `DataTable.recordAt` and fail without it. |
