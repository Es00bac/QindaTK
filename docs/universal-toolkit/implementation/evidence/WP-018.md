# WP-018 — Native window, file and desktop integration

**State: accepted.** Proposal scope: PLT-01 WindowHost, PLT-03
FileDialogAdapter and PLT-05 DesktopIntegration. Public behavior and limits
are described in [native integration](../../../native-integration.md) and
[D-037](../../../decisions-services.md#d-037--keep-native-dialogs-optional-to-the-core-package).

## Behavior delivered

- `WindowHost` binds real `QQuickWindow` instances to authoritative
  `DocumentManager` view IDs. Two windows may share one document, while the
  last dirty view is guarded. External windows remain externally owned;
  screen geometry is clamped in logical pixels and reconciled after a screen
  change.
- `FileDialogAdapter` uses asynchronous request IDs and an injected backend.
  It makes cancellation and unsupported operations explicit, ignores late
  completions and checks local URI availability on completion. The optional
  `QindaTKWidgets` package supplies a native `QFileDialog` backend for
  `QApplication` hosts; the base QindaTK package needs no Qt Widgets link.
- `DesktopIntegration` provides file-open events, URL launch, local reveal,
  explicit open-with, activation and an application recent-list. OS recent
  registration and second-instance IPC report unavailable.

## Verification

- Isolated Qt 6.11 focused `tst_window_host` and `tst_native_file_dialog`
  passed 2/2. The integrated Qt 6.11 focused gate passed 8/8 including
  document lifecycle, transfer, TimeMap and binding tests. Full Qt 6.8 CTest
  passed all 54 unrelated/current targets except `tst_qml`, whose in-progress
  WP-020 command-control source was being revised during the run; both WP-018
  targets passed. Direct external-window destruction now has a dedicated view
  release test.
- The optional installed `QindaTKWidgets` consumer configured and built
  against staged headers/library, then reported native dialog availability
  under offscreen `QApplication`. The base installed QML/header consumer
  compiled and instantiated `WindowHost`, `FileDialogAdapter` and
  `DesktopIntegration` with no Qt Widgets link. The consumer found a public
  `WindowHost` header completeness issue, which was corrected and retested.

## Boundaries

The Linux offscreen runner has one screen and no desktop shell. Mixed-DPI
screens, actual monitor removal, native focus policy, macOS/Windows behavior,
portal grants, OS recent registration and second-instance IPC need platform
qualification or separately supplied adapters. The optional Widgets backend
requires a host `QApplication` and supports local URLs.
