# WP-054 — PDF viewing and annotation

**State: active; package not accepted.**

Luna's isolated `work/wp054-pdf-panels` lane was integrated as `5801f5e`.
It adds `PdfView` and `PdfAnnotationTools` over a bounded host-supplied page
window, stable annotation IDs and explicit request/acknowledgment state. The
two-page fixture uses `AssetProvider` for actual `pdf-page` image requests
and `pdf-text` search word positions. The lane's focused QML test passed 3/3
and its preview check passed with the configured `-j24 -l24` build limits.

The merged default file backend now renders local PDF pages through
`pdftoppm`, returns document page count through `pdfinfo`, and extracts text
with point-space word rectangles through `pdftotext`. Worker subprocesses
are cancellable and bounded by 30 seconds and 32 MiB output. A focused
`tst_file_asset_backend` test passed after PDF page, rotation and text cases
were added.

The merged tree passed the focused `tst_file_asset_backend`, PDF fixture,
waveform fixture and mixer fixture CTest run (4/4). In the inspected
[PDF reader capture](../../../screenshots/wp054-pdf-review.png), a real page
renders at the displayed size, and the page window scrolls inside the viewer.
The final preview dump placed `PdfView#pdfView` at 592×809,
`Scroll#pdfPageWindow` at 592×725, and the page render at 592×766.

Annotation persistence and reopen, interactive forms, final redaction, OCR
and signature workflows remain open. The controls expose these unavailable
capabilities instead of claiming they work.
