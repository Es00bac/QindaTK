# WP-058 — Mail, calendars and task workflows

**State: active; package not accepted.**

Luna's `work/wp058-productivity-controls` commit `cd3351a` supplied
`MailView`, `RichMailComposer`, `CalendarView`, `RecurrenceEditor` and
`TaskBoard` with a gallery section and combined fixture. They consume host
snapshots and send correlated edit requests. The fixture blocks delivery,
does not persist draft acknowledgments, and supplies recurrence previews
through a mock host in the original fixture.

The isolated build inherited configured `MAKEOPTS=-j24 -l24`; focused QML
checks passed 3/3, and both the suite fixture and gallery instantiated. The
merged Qt 6.11 build, focused QML test (3/3), example smoke and catalog check
passed. The merged dump places `MailView#mailView` at `0,0 628x281` with
CalendarView, TaskBoard and RecurrenceEditor visible below. The
[1280×900 screenshot](WP-058-productivity.png) was opened and inspected.

`RecurrenceService` now expands daily, weekly, monthly and yearly local-wall
rules with intervals, weekly weekdays, count/until ends and exceptions. It
skips nonexistent spring-forward times and chooses the earlier offset in a
fall-back fold. The merged focused C++ test passed, including a Denver DST
transition and an excluded occurrence. The productivity fixture now obtains
its preview from this service; the [1160×900 recurrence screenshot](WP-058-recurrence.png)
was opened and inspected and shows five locally computed rows after one
exception.

`LocalProductivityStore` now persists the four collections as a versioned
snapshot with stable IDs. It uses atomic replacement and retains the previous
valid snapshot for recovery after primary-file corruption. Task moves compact
ordering and have local undo. The `examples/local-productivity` fixture
connects message actions, draft saves, calendar acknowledgments, and task
move/undo to this store. The isolated configured-limit build, focused 3/3
store tests and fixture check passed; merged validation is recorded below.
The merged build passed with configured `-j24 -l24`; the focused C++ test
passed 3/3. The [1440×980 local-store screenshot](WP-058-local-productivity.png)
was opened and inspected. Its dump places `Caption#localStoreStatus` at
`8,45 1424x13` and the four panels in a 1424×910 grid.

The store now applies and undoes local calendar shifts, rejecting DST gaps and
folds, and the fixture persists and acknowledges accepted move requests.

`LocalAttachmentStore` now saves and rereads actual local attachment payload
bytes by stable ID (8 MiB bound), separately from draft metadata. It stages
metadata and bytes together and rolls back a failed replacement. The isolated
configured-limit build, focused 3/3 byte test and fixture check passed; its
900×560 screenshot was inspected.
The merged focused attachment test passed and the
[900×560 attachment screenshot](WP-058-attachment-store.png) was opened and
inspected; the fixture reread 185 bytes from its local payload store.

`LocalCalendarProjectionModel` now expands events in the saved store through
`RecurrenceService` into a bounded UTC window, preserving stable event and
occurrence IDs, local wall times and IANA zones. It reprojects when local
events change. The seven-day calendar fixture navigates these projected
records. The merged configured-limit build and focused projection test passed;
the [900×600 calendar screenshot](WP-058-calendar-projection.png) was opened
and inspected. Its dump places `CalendarView#calendarView` at
`12,33 876x494` and shows the one-off and weekly events.

`RichMailComposer` now edits one native `RichTextDocument` with
`RichTextEditor` and `FormatBar`. `snapshot()` saves both the compatibility
plain `body` string and canonical `richDocumentJson` in the same local draft
record; reloading the record restores formatting while the host retains its
stable draft ID and attachment metadata. Legacy drafts without the JSON field
load as plain paragraphs. The focused QML case types formatted text, saves the
snapshot, reopens it in a fresh composer and checks the rich run plus
attachment ID. The focused QML case passed (3/3 including setup and cleanup).
The local-store test passed 1/1 with a valid native rich-text document loaded
after recovery, alongside the stable ID, compatibility body and attachment
metadata. A fresh build of `tst_qml` and `qtk-preview` completed under
configured `-j24 -l24`. The preview dump places `FormatBar#composerFormatBar`
at `0,108 702x28` and `RichTextEditor#composerBody` at `0,140 702x81`; the
[1440×980 screenshot](WP-058-rich-drafts.png) was opened and inspected. See
[Rich draft bodies](../../../productivity-store.md#rich-draft-bodies).
The same focused QML case passed again after integration (3/3 including setup
and cleanup). The [merged 1440×980 screenshot](WP-058-rich-drafts-merged.png)
was opened and inspected; the draft composer visibly contains the format bar,
editable rich body, attachment count and local save action in the four-panel
fixture.

Remaining: provider adapters for real delivery/sync and attachment upload,
inline embedded asset resolution, automatic merging of conflicting record
edits and remote-sync conflict coordination.

The local store also detects concurrent snapshot writers. Each load/save
records the primary file's revision and SHA-256 content identity. `saveTo`
serializes writers with a per-file `QLockFile` and rejects a stale baseline
with `status == "conflict"` before touching either the primary or recovery
snapshot; a lock timeout reports `busy`. A focused two-store C++ case verifies
that the second writer cannot replace the first, reloads the winning snapshot,
reapplies its pending record and saves successfully; it also verifies that a
conflict leaves the recovery snapshot byte-identical. The configured
`tst_local_productivity_store` build completed with `-j24 -l24`; all five QtTest
cases passed. The caller must resolve record-level conflicts itself; this is
local file coordination, not remote sync or an automatic merge.
The merged configured-limit build and focused store CTest passed 1/1.

Scope notes: hosted-service sign-in, discovery and private APIs are host
adapters with the contract in the providers document (D-189); no hosted
account is exercised. Mailbox names and addresses are ASCII only (no modified
UTF-7 or SMTPUTF8). Overridden recurrence instances are preserved on the
server but not projected locally. Performance measurement, other platforms,
screen-reader runs and account qualification belong to WP-088 to WP-094. The
example fixtures still use the local store only; wiring a live account into
a demo belongs to the demo-app work in the deferred packages.
