# WP-050 — Rich text and paginated document editing

**State: review — not accepted.** Worker lane `work/wp050-richtext-opus`
(from `work/universal-implementation` at `2e31033`), commits `eaf0cd2`
(model, history, codec), `0dd55bc` (layout, views, controls) and the
closing commit named in the handoff. Proposal scope: OFF-01
RichTextEditor, OFF-02 RichDocumentView, OFF-03 FormatBar and OFF-05
PageNavigator. Supporting scope: ENG-04. The contracts are in
[rich-text.md](../../../rich-text.md) and the
[control catalog](../../../controls.md#rich-text-and-paginated-documents).
The backend decision is
[D-050](../../../decisions-application.md#d-050--own-the-rich-text-model-and-paginate-per-view).

## Behavior delivered

1. **Model.** Paragraphs, interned character runs, paragraph attributes,
   lists, links, tables, and inline, float and page objects anchored by
   U+FFFC. Positions are paragraph UUID + UTF-16 offset + affinity.
   Invertible steps form transactions with coalesced local history. An
   `externalUndo` receipt bridge follows D-040.
2. **Hard fixture first.** `buildHardFixture` (tests) and
   `examples/rich-document/showcase.qtkrich` combine several stress cases:
   - mixed Latin, Hebrew, Arabic, Devanagari, CJK, emoji ZWJ sequences and
     flags;
   - a table with a repeated header crossing a page break;
   - a float that cannot fit and moves with its anchor paragraph;
   - a page-anchored object and a right-to-left appendix.

   The backend was chosen from the probe measurements in D-050.
3. **Editing and pagination.** Real HarfBuzz shaping through `QTextLayout`,
   with grapheme-aware caret, deletion and selection and visual bidi
   movement. Input-method preedit is view-local; a commit or replacement is
   one undo step. Pagination is incremental and converges early, only
   visible pages are materialised, and a selection is held by document
   anchors across reflow from another view.
4. **Formatting and sync.** 27 public command IDs; each formatting action is
   one transaction and one undo step, keeping focus and selection.
   `FormatBar` shows resolved and mixed states. A continuous editor and a
   paged view share one document. Native structured persistence is
   canonical `qindatk.richtext/1` (byte-identical save → reopen → save). A
   `DocumentSession` extension adapter handles session save and recovery.
5. **Navigation.** `PageNavigator` rows are keyed by UUIDv5(section,
   ordinal) page keys and use a recycling thumbnail list, an outline, and
   section moves as one undo step. Navigating scrolls the view and keeps
   the logical selection.

### Measurements

The host was shared by several concurrent builds; the user reported load
about 58 when setting the four-job limit. The ranges below span three runs
of the same tests. Treat times as indicative. Counts are deterministic.

- **500 pages / 10,000 paragraphs.** Initial synchronous pagination took
  745–1,454 ms. The shaped-layout cache held 1,808 layouts (limit 2,048).
- **Typing one character on page 250.** 8.3–12.5 ms: 1 paragraph shaped,
  1 page rebuilt, 249 reused. Pagination restarted at page 250 and
  converged at 251.
- **New line on page 10.**
  - With page-break sections: 8.5–19.7 ms, 2 paragraphs shaped, 16 pages
    rebuilt, 475 reused, converged at page 26.
  - As one flow: 52–64 ms, 2 paragraphs shaped, 491 pages rebuilt from
    cached metrics.
- **Progressive pagination.** 8 ms slices (68–108 slices per run).
- **Bounded views.**
  - Scrolling 500 pages in a 900×700 view showed at most 2 page tiles.
  - The PageNavigator had 8 thumbnail delegates for 30 pages (the viewport
    bound was 8).
- **Session flush, 500 pages.** The first encode took 51 ms; a keystroke
  plus flush had a median of 6.8–7.5 ms and a maximum of 7.7–9.7 ms.

### Defects found and fixed during verification

- **Inline objects took only the glyph width.** Qt 6.11.1
  `qtextengine.cpp:1447` computes `letterSpacing *= font.d->dpi /
  qt_defaultDpiY()` in integers, which is 0 at the 72-dpi layout device.
  Inline widths now use percentage spacing, and zero-width anchors are
  U+2060 in the layout string.
- **List markers were stale before pagination.** They now rebuild lazily,
  and pages that are reused but renumbered still get a new revision.
- **List membership changes re-laid out every list item in the document.**
  Only definitions changed in place do that now.
- **Advertised shortcuts did nothing.** Ctrl+Enter (page break) and Ctrl+K
  (link) now reach their commands.
- **Navigation and scrolling.**
  - Page navigation collapsed the selection (against OFF-05); it now
    scrolls and keeps the selection.
  - IBus's empty focus-in event scrolled a navigated view back to the
    caret. The view now scrolls only on real input.
  - `cursorRectangle` did not notify on scroll, so the IME candidate window
    lagged behind.

## Deviations and incomplete behavior

- **FormatBar.** Binds through command IDs and `formatState`, not
  `PropertyBinding` as the OFF-03 sketch says. It uses
  `FontCatalog`/`ComboBox` because the WP-024 `FontPicker` binds a single
  property. Named styles (OFF-03 "style") are WP-051.
- **PageNavigator.** Navigates, shows the outline and reorders sections. It
  has no insert/delete page requests and no spreads. Thumbnails paint from
  the view's layout, not from AssetProvider images.
- **Tables.** No merged cells or table-editing UI; there is no page-setup
  UI (WP-051). A table row taller than a page splits by lines. Floats are
  top-of-paragraph only (no offsets or text-wrap modes). One level of
  tables only.
- **HTML.** Exchange only, imported through `QTextDocument`. Page geometry
  and floats are dropped on export.
- **Objects.** `asset:` sources show a labelled placeholder until an
  `AssetProvider` renderer adapter exists.
- **Accessibility.** The area exposes the text interface through
  `QAccessibleQuickItem` property names; tests check offsets, cursor and
  selection. AT-SPI and screen-reader qualification is not done.
- **Qt versions.** Only Qt 6.11.1 was run. The Qt 6.8 regression run and an
  installed-consumer check remain open. The object-width mechanism
  (percentage letter spacing) is guarded on each Qt version by
  `objectsTakeTheirWidthInTheLine`.
