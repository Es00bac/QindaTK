# WP-078 — Durable render queues

**State: active; package not accepted.**

`RenderQueueView` now presents host-owned immutable job snapshots with stable
IDs, source version/range, output format/path, progress, warnings, errors and
validated output manifests. It distinguishes draft, validated, queued,
running, cancelling, succeeded, failed, cancelled and stale states. Its
Validate, Submit, Cancel, Retry and Open output actions emit requests for the
host to decide; the view shows Open output only after the host reports a
successful job with a validated manifest. The host fixture deliberately
does not render files.

The isolated focused QML test passed 3/3 and the fixture rendered. The
[render queue screenshot](../../../screenshots/render-queue.png) was opened
and inspected in the integration tree: queued and running rows show progress;
failure, cancellation and stale rows expose appropriate actions; the approved
row alone offers Open output. The durable queue core and actual output
adapter are now integrated through `RenderQueueModel`.

The core adds a QML-registrable `RenderQueueModel` with stable immutable
snapshots, dependency scheduling, resource slots, persistent states and
per-job errors. It runs work through `JobModel`, with an extension callback
for host-owned render engines. The built-in caption PNG sequence provider
reads hashed source frames, burns a committed caption track, and publishes a
verified manifest and ordered real PNG files. The `jobs` property projects
rows for `RenderQueueView`; the view's request signals connect through the
host to model methods.

Verification: `tst_render_queue_model` writes and inspects a real captioned
PNG and exact manifest, reopens a journal marked running after publish,
verifies successful output recovery, then fails a missing-source attempt. It
reopens a separate interrupted attempt, removes its partial stage, and retries
successfully after restoring identical source bytes. The test also
checks successful output cannot be retried. See [render queue contract](../../../render-queue.md)
for declared restart and provider limits. The core's isolated configured-limit
build and focused CTest passed 1/1. Merged build, UI-to-core fixture and output
screenshot remain to verify.

Remaining capability: no built-in muxed video, audio or document provider;
those require a host engine registered through the C++ provider seam. No
partial-frame checkpoint or resume is promised. Multi-process sharing and
remote output transactions are outside the local journal contract.
