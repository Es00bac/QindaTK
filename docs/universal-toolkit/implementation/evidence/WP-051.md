## Structured rich-text table edit slice (integrated)

**Merged on the integration branch (`612049b`); WP-051 is not accepted.** Branch
`work/wp051-rich-table-edit` (worktree `QindaTK-wp051-rich-table-edit`),
based on `dac1b96`. A Sol sub-agent wrote the slice; it was reviewed, fixed,
tested and committed in the lane.

`RichTextDocument` exposes `tables` and `tableSnapshot(id)` with stable table,
row, column and cell IDs (plus `headerRows`, row `header` and cell
`paragraphIds`). It accepts TableEditor requests for row and column insertion
and deletion, single-paragraph cell text and relative column width. Each grid
edit is one invertible `StepTable` in native history. Unchanged cells keep
their paragraph objects, IDs and revisions; removed cells and their inline
objects return on undo. Anchors in removed cells move to the nearest
surviving cell. The change set invalidates the table's geometry and
pagination. New rows and columns copy their neighbour's look; a new column
also copies its width, and a row inserted inside the header block becomes a
header row. The native codec and the session adapter persist `columnIds`.
Files written before the field existed load with IDs derived from the table
ID. HTML import and paste create fresh column IDs.
`examples/rich-table/Main.qml` connects TableEditor to the paginated document
loaded from the rich-document fixture. Selecting a cell reveals it on the
page, the page caret selects its cell in the editor, and header Undo/Redo
buttons are provided. A refused request shows the document's reason in
`tableStructureStatus`. Details are in
[rich-text.md](../../../rich-text.md#structured-table-edits).

Defects found in the draft and fixed:

- `applyTable` and the request methods read `Table::blockIndex` without
  rebuilding the block order. After an undone paragraph split (a merge),
  undoing a table edit overwrote the trailing paragraph and left the table
  in the body twice. Both paths now rebuild the order, and the step checks
  that it replaces its own block. With the guard removed,
  `staleBlockOrderNeverCorruptsUndo` fails.
- `RichTextSessionAdapter` did not write `columnIds`, so a reopened session
  derived new column IDs (`tst_rich_text_session` failed on the draft).
- A pasted table without column IDs kept none. The importer now creates one
  per column; `resetContent` derives missing IDs; a table block without one
  ID per column is refused.
- `setTableCellText` let `\r` and U+2029 split the cell paragraph and dropped
  the replaced text's format. It is now one replacement step in that format.
- New columns had weight 1 however wide their neighbours were, and new cells
  had default formats.
- Anchors (a view's caret) in removed cells jumped to the table's first
  cell, possibly pages away.
- History charged every step for two full grids. A row edit on a very large
  table could exceed the 64 MiB budget and drop its own undo step.
- The draft's `tst_rich_text_codec` "cell count" case now keeps `columnIds`
  consistent (it failed on the draft); two cases cover `columnIds` count and
  duplicate errors.
- The example's overlay scroll bar covered the Split button and the last cell
  column; the editor now leaves a gutter.

Intentionally still open: merged and split cells (Merge and Split stay
disabled: rows hold one cell per column and the codec stores no spans),
table and cell style editing, multi-paragraph cell replacement from
TableEditor (refused with the document's reason; such cells remain editable
in the page), linked text-frame flow and style inheritance.

For the integrator:

- `columnIds` is an additive optional member of `qindatk.richtext` version 1,
  not a version bump. Older decoders report it as ignored. The policy is
  recorded in `rich_text_codec.h` and rich-text.md and needs confirmation.
- TableEditor (unchanged here) names icons `list-plus`, `list-minus`,
  `combine` and `split`, which the built-in set lacks. Add row, Delete row,
  Merge and Split therefore show an empty icon slot in the captures.
- Snapshots are rebuilt in full on every document change, and TableEditor
  recreates its cell buttons. This is fine for the fixture's 30×4 table but
  not near the 10,000-row limit. The cell-text field sits below the cell
  grid, so a long table needs scrolling to reach it.
