# WP-013 — Document sessions, persistence and crash recovery

**State: accepted.** WP-012 is the accepted editing prerequisite. This package
implements APP-07 DocumentSession, APP-08 DocumentManager, APP-18
RecoveryManager and ENG-02 native persistence/recovery. The public contract is
in [persistence](../../../persistence.md) and
[D-029](../../../decisions.md#d-029--capture-immutable-save-revisions-and-keep-recovery-separate).

## Behavior delivered

- `ReferenceDocumentCodec` captures immutable version-2 JSON with stable
  document/entity IDs, exact decimal 64-bit integers, finite doubles, bytes,
  typed defaults and per-target flags. It migrates version 1 in memory,
  preserves optional `extensions`, enforces size/item limits, and rejects
  malformed, duplicate, unsupported and future data.
- `AtomicDocumentStore` validates snapshot identity, writes through `QSaveFile`
  without direct-write fallback, compares a SHA-256 baseline before and just
  before commit, and returns the committed revision/hash. The injectable
  `DocumentStore` seam supports deterministic faults and alternative backends.
- `DocumentSession` owns one reference model, exposes URI/title/revision,
  saved revision, dirty/saving/read-only/external-change/recovered/error state,
  and captures save data on the GUI thread. A worker writes immutable bytes;
  completion marks clean only when live revision and extension generation
  match the saved snapshot. Save As changes URI only after success. Autosave
  delay is configurable.
- `DocumentManager` owns multiple sessions and shared per-document undo,
  rejects duplicate open identity/path, tracks multiple view IDs per session,
  activates the correct history, reports per-document Save All outcomes and
  blocks destructive close until a requested save succeeds with no newer edit.
  Cancel keeps dirty sessions/views; Discard is explicit.
- `RecoveryManager` keeps full-snapshot hashed journal frames apart from the
  user's file. It scans only a valid prefix, accepts a last valid revision
  after an interrupted append, compacts through atomic checkpoint replacement,
  and supports inspect/restore/discard. Restored sessions stay dirty. A saved
  file whose revision is newer than the recovery candidate cannot be silently
  overwritten from recovery.

## Verification

- `tst_reference_document_codec` covers exact values above 2^53, Unicode,
  binary data, identity/flags/extensions, immutable capture after a newer edit,
  version-1 migration, future/malformed/duplicate and unknown-field rejection.
- `tst_document_session` covers a two-document app, a held worker save followed
  by a newer edit, extension edits during save, Save All partial failure,
  cancel-close preserving views, real local-file cancellation and hash conflict
  preserving exact prior/external bytes, clean save/reopen, truncated journal
  tail and checkpoint recovery, and refusal to overwrite a newer saved file
  with an older recovery revision. The held worker and truncated tail are
  deterministic simulations of interruption at those boundaries.
- The integrated Qt 6.11.1 and Qt 6.8.3 builds passed; `ctest` passed **35/35**
  on each final source tree. `all_qmllint` exited 0 on each; existing unrelated
  QML warnings remain. The standalone
  [installed persistence consumer](../../../../tests/consumer/persistence/README.md)
  built against the staged Qt 6.11 package and ran offscreen with exit 0,
  exercising public headers, save/reopen/edit, and installed `Tk.DocumentManager`.
- [document-lifecycle.qml](../../../../examples/document-lifecycle.qml) passed
  its CTest smoke and `qtk-preview --check`. Its 1120×720 PNG was opened and

- Regenerated `docs/catalog.json` lists **120 exported types**. `git diff

  direct Ninja builds used those job/load limits without altering Portage.

## Boundaries

The reference codec is for `PropertyDocument`; raster, audio, video and office
engines need format-specific serializers and migration adapters. Local hash
checks do not create an interprocess lock, and `QSaveFile` replacement alone
does not promise durability across hardware power failure. Recovery scans a
validated revision but cannot capture edits made inside the autosave debounce
window. Recovery records omit workspace/window state, which WP-014 owns.
Initial open is synchronous and the reference recovery writer runs on the GUI
thread; larger domain stores should provide worker-backed loading/autosave.
