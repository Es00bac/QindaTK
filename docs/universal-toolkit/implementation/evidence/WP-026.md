# WP-026 — History, notifications and task feedback

**State: review.** Proposal scope: APP-17 HistoryView, CTL-26
NotificationCenter, CTL-27 Toast and CTL-28 TaskCenter. The public controls
are in [controls](../../../controls.md#history-notifications-and-task-feedback);
service ownership and limits are in [history-feedback](../../../history-feedback.md).

## Behavior delivered

- `UndoService` exposes stable in-memory history entry IDs, current and clean
  positions, branch invalidation and guarded navigation. HistoryView shows
  the active history and its saved marker; it cannot replay a retired entry.
- `NotificationModel` retains a bounded sequence with read/dismiss actions,
  severity and stable action IDs. NotificationCenter presents these records;
  Toast pauses its themed timeout on hover/focus. The host resolves action IDs
  after checking the current command context.
- TaskCenter enumerates `JobModel` state and progress, cancels through its
  model and requests a fresh host-side validation before retry. Closing the
  view does not cancel a job. Committed results get an Open result action.

## Verification

- Worker commit `28e35e57827803390e3666eeaa99395ff930566c` includes four
  QML controls, a focused test and a feedback example. Its isolated Qt 6.11
  build passed, the focused suite passed 8/8 and direct qmllint on new controls
  was clean.
- Compact and comfortable previews were rendered and inspected. In compact,
  NotificationCenter is `12,101 976×159`, TaskCenter `12,268 976×134`, and
  HistoryView `12,410 976×130`. Comfortable geometry is `14,111 972×184`,
  `14,305 972×155`, and `14,470 972×150`. An initial zero-height ListView
  finding was fixed with explicit measured height and Flex no-shrink.
- Root-owned focused C++ tests cover the real undo, notification and job
  services. The example intentionally has empty task/history services; its
  QML action paths use injected test fixtures rather than fabricated jobs.
- Review found repeated failures were not aggregated and Toast had no shared
  notification queue. The integrated `NotificationModel` now keeps stable IDs
  and repeat counts, reopens unread state, and supplies a bounded 32-item
  toast queue. Toast `announce()` posts through that model; expiration leaves
  the notice visible in every center bound to it. The focused Qt 6.11
  notification C++ test passed **1/1** and feedback QML suite passed **9/9**,
  including repeated failure identity and two-center retention.
- Root rendered and opened compact/comfortable aggregation previews. Their
  dumps show `NotificationCenter#aggregationPreview 0,0 800x65` and `0,0
  800x76`, each with one row and `Label#noticeTitle "Render failed (2)"`;
  both images show a readable repeat count and available read/dismiss actions.
  Captures: `build/integration/wp026-notification-compact.png` and
  `build/integration/wp026-notification-comfortable.png`.
