# WP-042 — Artboards, layers and navigation

**State: active presentation slices; package not accepted.** The declared
WP-041 dependency remains open. Luna is building useful views against the
currently integrated CanvasDocument facade while Sol retains the model and
command contracts.

`LayerTree` reads `CanvasDocument.layers`, selects `activeLayer`, and requests
visibility/lock changes through the model's existing methods. It shows
empty/null states and accessible named controls. The model is currently flat;
there is no hierarchy, reorder command, artboard set or reversible layer
structural history. The Qt 6.8 build and focused operation preview passed;
Sol opened the [compact](WP-042-layers-compact.png) and
[comfortable](WP-042-layers-comfortable.png) captures and found both rows
legible and aligned.

`NavigatorView` binds a fitted overview to the main view's document and maps
the main viewport corners into that overview. Press/drag changes only the main
view state's centre. A focused `qtk-preview --check` passed; Sol opened the
[4× main-view capture](WP-042-navigator-4x.png). The cyan viewport outline is
inside the 200×120 overview at roughly 9×7 pixels for this pose, and its
themed focus-ring-width stroke is visible. The overview renders with the
software backend. Its current contract has no artboard switching or layer
selection command.

The refreshed shared Qt 6.11 and Qt 6.8 builds both passed focused
`qtk-preview --check` scenes. The layer scene returned
`LAYER_TREE_OPERATIONS_OK 1 2 false true` after activating the base layer and
changing the second layer's visibility and lock. The navigator scene
instantiated with one fitted preview and issued a centre navigation request.

`AlignDistributePanel` now offers six semantic align requests, two distribute
requests, three reference modes and a document-unit gap field. It carries
copied stable string object IDs and leaves geometry, preview, lock policy,
commit and undo to the host. The focused Qt 6.11 QML test passed **4/4**
after Sol's review adjustment: the gap step is a document-unit setting and
one selected object can align to a page. `qtk-preview --check` passed; its
dump showed `AlignDistributePanel#alignFixturePanel 4,4 352x175`, the
reference picker, all eight action buttons and the gap field. Sol opened the
[compact](WP-042-align-compact.png) and
[comfortable](WP-042-align-comfortable.png) captures; both fit and remain
legible. The reproducible visual fixture is
[AlignPanelScene.qml](../../../../examples/spatial-canvas/AlignPanelScene.qml).
The same focused **4/4** test and preview check passed on Qt 6.8. The
installed-consumer check is pending with the package-level integration.

**Still required:** artboard model and editing, hierarchical virtual layer
reorder with cycle checks and undo, alignment/distribution commands, linked
selection/viewport behavior, and integrated dual-Qt/installed-consumer gates.

The shared Qt 6.11 CTest run passed **102/102** after these slices. The Qt 6.8
run passed **101/102**; its only failure was the offscreen RHI pixel case
recorded under [WP-040](WP-040.md#shared-regression-check--later-2026-09-23).
