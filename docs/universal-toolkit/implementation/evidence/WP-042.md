# WP-042 — Artboards, layers and navigation

**State: active presentation slices; package not accepted.** The declared
WP-041 dependency remains open. The views use the currently integrated
CanvasDocument facade while Sol retains the model and command contracts.

`LayerTree` reads `CanvasDocument.layers`, selects `activeLayer`, and requests
visibility/lock changes through the model's existing methods. It shows
empty/null states and accessible named controls. The model is currently flat;
there is no hierarchy, reorder command, artboard set or reversible layer
structural history. The Qt 6.8 build and focused operation preview passed;
Sol opened the [compact](WP-042-layers-compact.png) and
[comfortable](WP-042-layers-comfortable.png) captures and found both rows
legible and aligned.

`NavigatorView` binds a fitted overview to the main view's document and maps
the main viewport corners into that overview. Press/drag changes only the main
view state's centre. A focused `qtk-preview --check` passed; Sol opened the
[4× main-view capture](WP-042-navigator-4x.png). The cyan viewport outline is
inside the 200×120 overview at roughly 9×7 pixels for this pose, and its
themed focus-ring-width stroke is visible. The overview renders with the
software backend. Its current contract has no artboard switching or layer
selection command.

The refreshed shared Qt 6.11 and Qt 6.8 builds both passed focused
`qtk-preview --check` scenes. The layer scene returned
`LAYER_TREE_OPERATIONS_OK 1 2 false true` after activating the base layer and
changing the second layer's visibility and lock. The navigator scene
instantiated with one fitted preview and issued a centre navigation request.

`AlignDistributePanel` now offers six semantic align requests, two distribute
requests, three reference modes and a document-unit gap field. It carries
copied stable string object IDs and leaves geometry, preview, lock policy,
commit and undo to the host. The focused Qt 6.11 QML test passed **4/4**
after Sol's review adjustment: the gap step is a document-unit setting and
one selected object can align to a page. `qtk-preview --check` passed; its
dump showed `AlignDistributePanel#alignFixturePanel 4,4 352x175`, the
reference picker, all eight action buttons and the gap field. Sol opened the
[compact](WP-042-align-compact.png) and
[comfortable](WP-042-align-comfortable.png) captures; both fit and remain
legible. The reproducible visual fixture is
[AlignPanelScene.qml](../../../../examples/spatial-canvas/AlignPanelScene.qml).
The same focused **4/4** test and preview check passed on Qt 6.8. The
installed-consumer check is pending with the package-level integration.

`CanvasAlignmentModel` now connects those panel requests to the document.
It uses transformed object bounds, selection/page/key-object references and
one reversible `CanvasEdit` per operation. The model rejects a whole command
when a selected object is locked, hidden, missing or geometrically invalid.
The focused Qt 6.11 C++ command test passed **1/1**, including a sheared
object, exact positive distribution gaps and single-step undo. The live
[alignment fixture](../../../../examples/spatial-canvas/AlignWorkingScene.qml)
passed `qtk-preview --check`; its dump placed the canvas at `8,8 476x504`
and panel at `0,0 400x175` inside the right column. Sol opened the
[working capture](WP-042-alignment-working.png): controls and canvas shapes
are visible and the action labels fit.

`ArtboardView` is a host-owned board overlay with stable board IDs. It maps
board corners through a rotated `CanvasView`, draws frames and an active
resize handle above the document, and reports activate, arrange and resize
requests in document coordinates. The host paints board backgrounds under
document objects and owns commits. By default, board interiors and blank
canvas presses pass to canvas object tools while frame drags arrange boards;
an artboard editing tool can opt into interior capture. Sol reviewed and
fixed these behaviors during integration. Focused Qt 6.11 and Qt 6.8 QML
interaction tests passed **10/10** after the interior-capture refinement,
including frame drag, interior and blank-canvas tool input, keyboard
activation, Escape and host record replacement during a drag. The Qt 6.8
preview check passed. The integrated preview dump places `CanvasView#canvasView 0,0
900x600`, `ArtboardView#artboardView 0,0 900x600`, and the cover label at
`145,165 272x318`. Sol opened the
[compact](WP-042-artboard-compact.png) and
[comfortable](WP-042-artboard-comfortable.png) captures: both rotated board
frames and the underlying document shapes remain visible. The fixture is
[ArtboardScene.qml](../../../../examples/spatial-canvas/ArtboardScene.qml).

The shared Qt 6.11 and Qt 6.8 CTest suites each passed **104/104** after
ArtboardView integration and before the interior-capture refinement.
The focused **10/10** tests on both versions and Qt 6.8 preview check passed
after that refinement. `all_qmllint` exited 0 with existing warnings outside
this control; the catalog was regenerated at 264 types.

**Still required (before the code-first round):** persistent artboard model
and editing, hierarchical virtual layer reorder with cycle checks and undo,
linked selection/viewport behavior, and integrated dual-Qt/installed-consumer
gates. The code-first round below builds the first three; the gates are
qualification work (see the scope notes).

The shared Qt 6.11 CTest run passed **102/102** after these slices. The Qt 6.8
run passed **101/102**; its only failure was the offscreen RHI pixel case
recorded under [WP-040](WP-040.md#shared-regression-check--later-2026-09-23).

## Code-first round (cf1): model integration

Written on branch `work/wp042-cf` without building or running anything; the
integrator's round build runs the tests named here for the first time. Each
view now operates on the same `CanvasDocument`: its layer tree, its artboards
and its selection model.

1. **Domain model for boards, hierarchy, flags and references.**
   `CanvasLayer` has a `parent` group and a `group` flag; `order` is
   sibling-relative and the paint key uses the depth-first layer rank
   (D-092). Visibility and lock cascade through groups
   (`layerEffectivelyVisible/Locked`), so painting, picking, snapping,
   alignment, the selection model and tool declines honour a hidden or locked
   group. `CanvasDocument` owns ordered artboards with stable ids, rectangles,
   8-bit backgrounds and bleed (D-093); both render providers paint their
   backgrounds below objects. `CanvasAlignmentModel.referenceOptions` supplies
   the reference choices, including the artboard (D-095). The tree and boards
   save inside the extensions JSON; flat documents keep their bytes.
   Tests: `tst_canvas_layers` (`groupsReorderAndUndoAsSingleSteps`,
   `hiddenAndLockedGroupsCascade`, `invalidLayerTreesAreRejectedOnOpen`),
   `tst_canvas_artboards` (`boardEditsAreSingleUndoableSteps`,
   `backgroundsPaintBelowObjectsAndExportRegions`,
   `invalidBoardRecordsAreRejected`, `alignmentUsesTheArtboardReference`).
2. **Virtual layer editing and shared selection.** Document commands
   `addLayerAt`, `addLayerGroup`, `moveLayer`, `renameLayer`, `groupLayers`,
   `ungroupLayer`, `removeLayerTree` and `moveObjectToLayer` are one undo step
   each; commits refuse missing or non-group parents, cycles, excess depth,
   objects on groups and losing the last content layer.
   `CanvasLayerTreeModel` derives group/layer/object rows from the document
   and writes only document commands and the shared `CanvasSelectionModel`.
   `LayerTree` projects it through `VirtualCollectionAdapter` (WP-027) with
   drag, keyboard and rename editing. Tests: `tst_canvas_layers`
   (`hierarchyRejectsInvalidParents`, `groupUngroupAndDeleteTrees`,
   `treeModelSharesSelectionWithoutFeedback`) and `tst_layer_tree.qml`
   (hierarchy rows, shared selection, keyboard reorder/indent, drag into a
   group, visibility, lock, rename, empty state).
3. **Artboard creation/resize, alignment and the overview.**
   `CanvasArtboardModel` previews ArtboardView arrange and resize drags and
   commits one step on release; `ArtboardView.createEnabled` adds a
   board-creation drag; `exportArtboardSvg` writes a board's export region.
   Alignment can use the active board as reference. `NavigatorView` renders a
   content-fitted second `CanvasView` on the same render providers at its own
   coarse level of detail. Tests: `tst_canvas_artboards`
   (`artboardModelPreviewsAndCommitsOneStep`), `tst_artboard_model.qml`
   (frame drag, handle resize, frame click activation, creation and Escape,
   panel aligning to the active board), `tst_navigator_view.qml`.
4. **Multiple views without feedback loops.** The tree model reveals only
   selections made elsewhere and never writes selection in response to one;
   the navigator writes the main pose with one atomic
   `CanvasViewState.setCenter` and keeps a private preview pose; a
   `CanvasView` treats a pose change it did not make as navigation, so a
   `fitMode` view no longer refits over a navigator or synchronized view
   (D-094). Tests: `treeModelSharesSelectionWithoutFeedback`,
   `fittedViewKeepsExternalNavigation` (`tst_canvas_artboards`),
   `test_pointer_navigation_moves_only_the_main_pose`.
5. **Verification scenarios.** Hidden/locked groups:
   `hiddenAndLockedGroupsCascade`. Nested transforms through six hierarchy
   edits and their undo/redo: `nestedTransformsSurviveHierarchyEdits`.
   Reorder undo with rendered stacking and hit order:
   `groupsReorderAndUndoAsSingleSteps`. Many layers (209 in 16 groups) with
   exact ranks through save/reopen and equal bytes: `manyLayersRoundTrip`.
   Many artboards (122) with the layer tree through a session save/reopen:
   `sceneSurvivesSessionSaveAndReopen`. Overview navigation after a model
   reset, and the overview's coarser level of detail:
   `test_overview_follows_a_model_reset`.

**Accept when.** The layer tree, artboard view, alignment panel and navigator
bind one persistent `CanvasDocument`; alignment and hierarchy changes are
single undoable steps that survive save/reopen (tests above; not yet run).

### Scope notes

- Dual-Qt, installed-consumer, screen-reader and performance qualification
  are deferred to WP-088 to WP-094 (user decision, 2026-09-24).
- Group transforms, opacity, blend modes and masks, and the blend/opacity/
  mask roles of the CAN-09 sketch, belong to WP-044 (appearance) and WP-045
  (masks); groups here carry none, so hierarchy edits never move geometry.
- Rendered row thumbnails and board clipping or board-owned objects are not
  in WP-042's numbered requirements; rows show a kind icon and boards own no
  objects (D-093).
