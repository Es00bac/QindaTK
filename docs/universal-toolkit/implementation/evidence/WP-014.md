# WP-014 — Settings and workspace persistence

**State: accepted.** WP-013 supplied document sessions. This package implements
APP-09 WorkspaceSession, APP-12 SettingsModel and FIX-F09's floating shade
policy. See [settings and workspace](../../../settings-workspace.md),
[docking](../../../docking.md), and
[D-030](../../../decisions-services.md#d-030--independent-settings-and-workspace-files).

## Behavior delivered

- `SettingsModel` has registered descriptors with exact `QMetaType`, default,
  app/document/workspace scope, validators and restart requirements. Staging
  supports apply/cancel/reset. Import validates all known values before any
  commit, retains and reports unsupported keys, and preserves unknown plugin
  settings for a later install. The restart baseline is established after a
  persisted load, so an already-applied setting does not request another
  restart on launch.
- `SettingsPersistence` writes typed version-2 JSON in its own atomic file,
  migrates bare version-1 values, preserves extensions and rejects malformed,
  unsupported or oversized data. A failed load leaves committed preferences
  unchanged. Numeric v1 values are resolved against registered descriptor
  types before import.
- `WorkspaceSession` records document UUID/URI references, stable view IDs and
  per-view state, windows and active references, DockModel serialized state,
  and active dock workspace. It migrates v1 optional fields, validates identity
  and referential integrity before replacement, retains unknown workspace
  fields, and constrains restored windows to available screen rectangles.
  Missing document URIs are reported without writing document data. An
  existing document can regain multiple stable views.
- `DockModel::deserialize` preflights version, nested arrangement and saved
  layout values before mutation. Missing panel definitions remain pending.
  DockModel constrains floating rectangles to keep a reachable header within
  a resized host. DockHost shade remains transient: it survives a frame
  rebuild but resets on workspace switch/new host and is never serialized.
- `StateStore` is an injected byte-store seam; `AtomicStateStore` uses bounded
  reads and `QSaveFile` replacement with direct-write fallback disabled.
  Settings, workspace and documents have separate paths and schemas.

## Boundaries

`WorkspaceSession` returns normalized native-window records but does not
create windows; WP-018 owns that adapter. Domain applications provide the
actual per-view state, document serializers and secure secret storage. An
unsaved document with no URI cannot be recreated from workspace state alone;
document recovery remains a separate explicit choice. The reference format
only restores supported property documents. Dock layout IDs remain in window
records for the window adapter; missing IDs do not block the rest of the
workspace.
