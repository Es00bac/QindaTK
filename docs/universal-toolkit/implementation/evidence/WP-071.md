# WP-071 — Professional timeline video edits

**State: active; package not accepted.**

Luna's `work/wp071-video` commit `023f7fb` supplied `TrimView`,
`MulticamView` and `TransitionEditor` with a host acknowledgment fixture and
gallery section. The controls keep exact timeline ticks as decimal strings
and show missing-media and insufficient-handle states. The host still owns
edit policy, transactions, multicam synchronization, cut persistence and
transition evaluation.

The isolated build inherited configured `MAKEOPTS=-j24 -l24`; focused QML
checks passed 3/3, both fixtures instantiated, and
[the isolated screenshot](../../../screenshots/wp071-video-edits.png) was inspected.
The merged Qt 6.11 build, focused QML test (3/3), example smoke and catalog
check passed. The merged dump places `TrimView#trimView`,
`MulticamView#multicamView` and `TransitionEditor#transitionEditor` in the
1280×800 fixture. The [merged screenshot](WP-071-video-edit.png) was opened
and inspected; frame placeholders are expected without a connected provider.

Remaining: legal roll/ripple/slip/slide operations, linked-track behavior,
actual source bounds, synced angle cuts, rendered transitions, persistence,
undo and export equivalence.

## Code-first round (2026-09-24, branch `work/wp071-cf`)

Written without a build on top of WP-070's `work/wp070-cf` and round
`round/cf1`; the integrator's round build runs the tests below. Every changed
C++, QML and JS file passes `.cache/code-first/syntax_check.py` (0 failing);
the remaining qmllint notes name the new types and properties
(`Tk.SequenceEditor`, `Tk.MulticamModel`, `editor`, `multicam`), which the
pre-round module snapshot does not contain yet. Design:
[sequence-edits.md](../../../sequence-edits.md); decisions D-118 to D-121.

### Requirements

1. **Trim roles, roll/ripple/slip/slide, multicam angles/sync, transition
   handles: built.** Source/program time, edit point, head/tail handle and
   link group are defined in `sequence-edits.md` "Roles". `TimelineEditKind`
   gains `Roll`, `Slip`, `Slide`, `SetTransition`, `SwitchSource`, `Link`,
   `Unlink` (QML kinds `roll`, `slip`, `slide`, `setTransition`,
   `switchSource`, `link`, `unlink`); ripple uses WP-048's ripple trims.
   `TimelineClip` gains `linkId` and `transition` (`beforeCut`/`afterCut`
   ticks, alignment, parameters), persisted in `qindatk.timeline/1`.
   `MulticamModel` defines angles as `(T − syncStart) + syncOffset`.
2. **Frame-exact sequence edits and transition evaluation with legal media
   bounds: built.** `timeline_planner_nle.cpp` (roll, slip, slide, transitions,
   handle reconciliation) and `timeline_planner_links.cpp` (links, source
   switches, insert) clamp to recorded handles, minimum length and zero and,
   with `frameExact`, land edit points on frame starts (D-118).
   `MediaProgram` extends spans over transition windows and
   `MediaTransition` blends dissolve/wipe/dip and crossfades sound (D-120).
   Tests: `tst_sequence_edits` (`rollMovesTheCutWithLinkedSound`,
   `rollClampsToHandlesOnFrames`, `slipKeepsPlacementWithinSource`,
   `slideRollsBothNeighbours`, `rippleTrimMovesLaterClipsOnLinkedTracks`,
   `transitionsNeedACutAndHandles`, `editsKeepTransitionsLegal`),
   `tst_sequence_render` `transitionsRenderAndExportTheSameFrames`.
3. **Dual trim previews, multicam switching, parameterized transition
   controls through shared timeline transactions: built.** `SequenceEditor`
   runs TrimView previews as TimelineModel sessions whose snapshot follows
   the preview overlay (both filmstrips show the would-be edit), commits one
   history step, and applies TransitionEditor type/duration/alignment/
   parameter edits as `setTransition` transactions with a player preview of
   the window. `MulticamModel.switchAngle` is one `switchSource` transaction;
   the playhead follows a bound player. `TrimView.editor`, `TransitionEditor.editor`
   and `MulticamView.multicam` bind them (host mode unchanged). Tests:
   `tst_sequence_editor` (`trimPreviewCommitsOneStep`,
   `trimSessionsCancelAndRetire`, `transitionEditsAreTransactions`,
   `multicamSwitchesDuringPlaybackAndReopens`, `multicamRefusesIllegalSwitches`),
   QML `tst_video_edit_backend.qml` (clicks Preview/Commit/Cancel, Remove and
   an angle card); the host-mode `tst_video_edit_surfaces.qml` still applies.
4. **Audio-linked selections, ripple policies, missing media without losing
   offsets: built.** `linked` requests edit whole link groups (D-119) for
   move, trim, ripple, split, delete, roll, slip, slide, transitions and
   switches; split/paste/switch parts get derived groups; `audioFollowsVideo`
   is the explicit multicam audio policy. Ripple scope and locked tracks follow
   `TimelineEditPolicy`. Bounds never read media, so offline clips edit with
   exact offsets; the views show offline state without blocking. Tests:
   `linkedSplitAndDeleteKeepGroups`, `switchSourceCutsLinkedClipsInSync`,
   `offlineClipsKeepExactOffsets` (2^53 + 1 source offsets), the render test
   `linkedTrimsKeepPictureAndSoundTogether`.
5. **Boundary frames, linked edits, insufficient handles, angle switching,
   undo and exported sequence equivalence: tests written.** Frame-start
   rounding and handle clamps (`rollClampsToHandlesOnFrames`), refusals with
   field `handles`, dropped transitions restored by undo
   (`editsKeepTransitionsLegal`), full undo/redo equality
   (`undoRestoresEveryLinkedChange`), angle switching during mock playback
   and after reopen with `unsyncedClipIds()` empty (render and editor
   tests), and export equivalence: every pixel of frames 20–29 of an exported
   dissolve equals the rendered frame, the dissolve weights are 1/8…7/8 on
   exact pixel values, and pops stay aligned in picture and sound after a
   linked roll and slip.

**Accept when:** the three controls, bound to `SequenceEditor` and
`MulticamModel`, perform legal edits through TimelineModel transactions, and
the render tests check the output frames and audio relationships of those
edits in the monitor path and in exported files.
