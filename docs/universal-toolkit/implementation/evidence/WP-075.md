# WP-075 — Tracking and rotoscoping

**State: active; package not accepted.**

`TrackingRotoModel` tracks tagged frame features with explicit confidence and
loss, cancellable preview and acceptance, corrections, undo and persistence.
It stores stable-ID keyframed mask paths, interpolates matching topology,
propagates with accepted tracks, and applies feathered masks to real pixels.
`MotionFrameRenderer` consumes a referenced mask before the layer transform.

`TrackingPanel` and `RotoscopeEditor` present host snapshots and emit stable-ID
requests. Feature corrections use source pixel coordinates; mask vertices use
normalized source coordinates. The controls show loss rather than silently
applying a failed track, and require explicit acceptance of a propagated mask.
The [1120×720 screenshot](WP-075-tracking-roto.png) was opened and inspected:
the lost state, preview path and point handles are legible. The UI lane dump
reports `TrackingPanel` 456×654 and `RotoscopeEditor` 632×654.

The isolated model test passed 1/1, the QML control case passed 3/3, and the
fixture passed `qtk-preview --check`. The merged build and focused cases are
running. Remaining work includes a live model-to-view fixture, broader tracking
motion and occlusion coverage, and Qt 6.8 qualification. The host owns frame
decoding and exact frame-time mapping; see [tracking model](../../../tracking-roto.md).
