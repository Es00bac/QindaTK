# WP-077 — Rig, UV and texture authoring

**State: active; package not accepted.**

`Tk.MeshRigDocument` is merged on the integration branch. It holds stable
triangle, UV-corner and bone IDs; validates topology and ordered bone
hierarchies; deforms vertices by weighted poses; edits seam-aware UV islands;
and paints actual sRGB texture pixels from a ray hit. It has bounded undo,
versioned JSON persistence, and posed OBJ plus PNG export. The isolated
configured build and focused `tst_mesh_rig_document` passed. See
[mesh-rig.md](../../../mesh-rig.md) for the API and limits.

The merged configured build and `tst_mesh_rig_document` passed 1/1.
`RigEditor`, `UVEditor` and `TexturePaintView` are merged; their isolated
focused QML test passed 5/5 and the worker opened the fixture screenshot.
The `mesh-rig-live` example routes their stable-ID requests into the actual
document commands and uses `SceneView3D.meshRay` for paint gestures.

An optional `MeshRigGeometry` adapter uploads posed triangles and raw texture
pixels to Qt Quick 3D. The [GPU viewport screenshot](WP-077-mesh-rig-3d.png)
and [live rig/UV/paint workbench screenshot](WP-077-mesh-rig-live.png) were
opened at the merged code. They show the orange and cyan paint pixels in the
correct UV positions on the 3D mesh and the texture preview. The live fixture's
dump places `RigEditor#liveRigEditor` at 0,0 600x397,
`UVEditor#liveUVEditor` at 0,405 600x397, and
`SceneView3D#liveMeshViewport` at 0,0 968x625 within their layout columns.
The merged focused C++ test passed 1/1, QML test passed 5/5, and both live
examples passed their smoke tests. Automatic UV unwrap/packing, IK, material
channels and shared history remain outside this slice; WP-077 stays active.

## Audit gap fixes (cf1)

An independent audit of commit 7cef63a found ten gaps. All ten were checked
against [phase-06-video.md#wp-077](../phase-06-video.md#wp-077) and the code,
and all were real. None was moved to another package: the plan assigns
animation connection (item 4), selection synchronization and camera painting
(item 3), and persistence (item 4) to WP-077 itself.

| # | Audit finding | Change |
| --- | --- | --- |
| 1 | Nothing built or run | Built in `build/cf`; every result below is from that build. |
| 2 | The stroke work bound charged each face's whole UV box per dab and cancelled the whole stroke (about 122 dabs at 256², 7 at 1024²) | `dab()` scans only the dab's footprint: the sphere's disk on the face plane, mapped through the face's plane-to-texel affine map. A sample over the bound is refused, but the stroke and its pixels are kept and `endPaint` commits them. `tst_mesh_rig_paint::longStrokesStayWithinWorkBound` (three full sweeps at the default radius 8, 256² and 1024²) and `workLimitKeepsPaintedPixels` both fail with the old accounting. |
| 3 | Slider ticks were one undo step each and evicted the 16-step history | `beginEditGesture`/`endEditGesture` give every commit in a gesture one merge key. `RigEditor` pose and weight sliders emit `editGestureStarted`/`Finished` on press and release. `tst_mesh_rig_authoring::sliderGestureIsOneUndoStep` fails with an empty merge key. `tst_mesh_rig_live.qml::test_rig_slider_drag_is_one_undo_step` drags the real slider 20 moves, then undoes it in one step and reaches the edit before it. |
| 4 | A version 1 file without `texturePng` loaded null textures that saved unreadably | Version 1 still requires the base colour channel; an invalid size is refused. `tst_mesh_rig_rig::versionTwoPersistence` fails on the old loader. |
| 5 | Rig animation was a private linear key list, outside WP-073 | A bound bone's rotation is three angle lanes `meshrig/bone:<id>/rotation.<x,y,z>` in the WP-073 `AutomationModel` (`animationModel`, `bindBoneAnimation`, exact `timeTicks`/`ticksPerFrame`). Pose edits key those lanes, and `KeyframeTimeline`/`DopeSheet` edit them. Unbound bones keep private keys (D-291). Tests: `tst_mesh_rig_authoring::boneAnimationUsesAutomationModel`; `tst_mesh_rig_live.qml::test_rig_keys_show_in_the_keyframe_timeline`. |
| 6 | TexturePaintView sent its UV-space pointer into camera rays | `TexturePaintView` paints in texture space (`paintUv`: the texel under the pointer, still a surface sphere across seams). `SceneView3D` `meshTool: "paint"` paints from the camera through the pixel under the pointer (D-292). Tests: `tst_mesh_rig_paint::uvPaintMatchesTexelUnderPointer` (same texels as the camera ray at that point); `test_scene_view_paints_the_texel_under_the_pointer` presses and drags on SceneView3D and checks the texels at both pointer pixels. |
| 7 | Selection sync was one-way, renderer-only and untested | CPU `SceneView3DMeshLayer` (no RHI needed). Pick emits `meshFacePicked` or `meshBonePicked`, and `selectedMeshFaceId`/`selectedBoneId` highlight the selection from `cameraOverlay` (the exact inverse of `meshRay`, `tst_mesh_rig_paint::projectionInvertsCameraRays`). Tested both ways in `test_scene_view_selection_syncs_both_ways`. |
| 8 | No rig authoring mode | `RigEditor` mode `author` with `RigAuthoringPanel`: add child or root, remove, rename, reparent (descendants are not offered), head/tail, limits. The document gains `removeBone` (refused while children, weights, constraints or keys refer to the bone), `renameBone`, `setBoneParent` (cycle refusal and a topological reorder), and `setBoneRest`. Tests: `tst_mesh_rig_authoring::authoringEditsKeepIdsAndRefuseDanglingReferences`, `test_rig_authoring_mode_edits_the_rig`. |
| 9 | Rotate, Unwrap, Pack, pack preview and several rig requests untested | `test_uv_rotate_unwrap_pack_and_preview` clicks each button on a live document, checks the geometry change, and reads the dashed preview pixels. |
| 10 | No mesh DocumentCodec | `qindatk.mesh-rig.v2` is registered (kind `meshrig`, suffix `qtkmesh`), and plain `saveToFile` files open too. `tst_mesh_rig_authoring::sessionSaveRecoverAndReopen` covers save as, autosave, crash recovery after restart, save, and reopen with the same document ID and texture, plus an open stroke being excluded. |
