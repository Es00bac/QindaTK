### Build-and-fix run (2026-09-25, `build/cf`, `-j12 -l12`, merged with `round/cf1` at `b10cbf7`)

- `tst_audio_plugin_host`: 12 passed, 0 failed (real child processes; the

- `tst_audio_plugin_engine`: 8 passed, 0 failed (allocation probe active:
  zero device-thread allocations).
- `tst_qml -input tests/qml`: 922 passed, 0 failed, including
  `PluginHostControls` 5/5.
- `ctest -R "audio|plugin|mixer|midi|automation|parameter|example_plugin|take_comp|session"`:
  35/35 passed, including `example_plugin-host`.

Fixes made in this run:
- **Relocatable host lookup (D-202).** `libqindatk` had the build tree's and
  the install prefix's absolute host paths compiled in. It now finds
  `qindatk-plugin-host` relative to its own file (`dladdr`): the build tree's
  `libexec/` next to a `CMakeFiles/` folder, or `<libexecdir>/qindatk/` in an
  install. `strings` over the debug-stripped library shows no worktree path.
  `qtk-preview --dump` with `QINDATK_PLUGIN_HOST` unset shows
  `AudioPluginRegistry.hostExecutable` = `…/build/cf/libexec/qindatk-plugin-host`.
- **Killed host processes are reaped before deletion.** `fail()` deleted the
  `QProcess` right after SIGKILL. `~QProcess` warned ("Destroyed while process
  … is still running") and blocked on the wait. The process is now deleted on
  `finished`, and the instance destructor reaps any still pending.
- The test plugins' `clap_entry` definitions no longer repeat `CLAP_EXPORT`,
  which `clap/entry.h` already declares; GCC warned that it ignored it. The
  symbol is still exported (`nm -D`).
- A rack parameter row shows the host's `displayValue` when its binding has no
  value text yet, where it showed nothing before.
- The `plugin-host` example's fixture host rejects **Reload** for a plugin
  that is still not installed, instead of acknowledging it silently.

**Accept when.** CLAP is the one declared format and has the lifecycle,
audio and state fixtures above. LV2 and VST3 are declared unavailable, not
advertised, so they owe no evidence; a later adapter brings its own.

**Scope notes.** LV2 (lilv is not installed and is not a dependency) and
VST3 (SDK absent) adapters are not built. Not supported by the CLAP host:
side-chains, surround and 64-bit ports, transport information for plugins,
sample-accurate automation inside a block (values change at block starts,
at most 256 frames apart), presets (`PluginBrowser` preset preview stays a
host request), a shared host process for several instances, and Wayland
editor embedding. Editor embedding on a real X server and window-manager
focus behaviour, performance measurement (per-instance process and context
switch cost), other platforms, screen-reader runs and translation belong to
WP-088 to WP-094.
