# WP-061 — Calibrated audio controls and meters

**State: active; package not accepted.** WP-060 real audio engine remains open.

Sol added `AudioMeterModel` and `measureInterleaved` as the first measurement
slice. A known two-channel block checks peak/RMS dBFS, overload latch, hold,
fall, silence and nonfinite input. On the merged Qt 6.11 tree, the targeted
`tst_audio_meter_model` build and CTest passed 1/1 using configured
`-j24 -l24` build limits. The model exposes compact per-channel GUI snapshots;
its interleaved fixture path is explicitly non-realtime.

Sol also added `AudioParameterMap` for linear, logarithmic and dB gain
descriptors, with explicit silence at position zero and exact 0 dB unity
position. Knob/Fader can share this provider mapping for pointer and keyboard
travel while leaving the edit transaction with the host. Its targeted Qt 6.11
build and `tst_audio_parameter_map` CTest passed 1/1 using `-j24 -l24`.

Luna's `work/wp061-controls` lane was integrated as `12ad72d`. It adds
`Knob`, `Fader`, `AudioMeter`, and `LoudnessHistory` with mapper hooks,
transactional gesture requests, channel meter values, and provider-owned
history. Its configured-limit `-j24 -l24` build, focused QML test (4/4)
and preview check passed. Sol inspected the [audio controls screenshot](WP-061-audio-controls.png): meter tracks, clip reset, gain/pan travel and history
plot are visible. The fixture uses synthetic provider snapshots.
On the merged tree, `example_audio-controls` passed its focused CTest smoke.

Parameter gestures still need actual engine transactions; the realtime
callback-to-GUI handoff and integrated loudness computation with declared
windows are also open. The controls do not claim DSP or compliance results.
