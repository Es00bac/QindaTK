# WP-068 — Pitch analysis and correction editing

**State: active; package not accepted.**

Luna's `work/wp068-pitch-editor` implementation was integrated from `29e5fbc`.
`PitchEditor` renders a bounded host-supplied pitch contour, note regions and
confidence, then issues pitch, time and formant preview/commit requests with
exact sample strings. The host owns limits, parameter state and edit outcomes.

The isolated build used configured `-j24 -l24`; its focused QML checks passed
2/2 and its preview fixture instantiated. The merged focused QML run passed
4/4 and `example_pitch-editor` passed. The merged dump places
`PitchEditor#pitchEditor` at `0,0 1096x560` and its canvas at `2,2 1092x556`.
That first 1120×720 screenshot showed the host-less fixture; it was replaced
by the round-build screenshots below once the example drove the real host.

## Code-first round (branch `work/wp068-cf`): analysis and correction DSP

The host behind PitchEditor now exists: `AudioPitchSource` (YIN analysis on
the thread pool) and the `pitch` operation of `session.edits` (TD-PSOLA).
Docs: [audio-pitch.md](../../../audio-pitch.md); decisions D-194…D-197.
The tests below were run in the round build (next section).

| Requirement | What exists | Verified by |
| --- | --- | --- |
| 1. Regions, confidence/unvoiced, units, formant/time constraints, material | MIDI cents (A4 = 6900); 5 ms frame grid; notes/phrases with IDs; confidence `1 − d′`; unvoiced below threshold or ≤ −50 dBFS; declared limits ±700 cents, formant 0.8–1.25, stretch 2/3–1.5×, ≥ 20 ms regions; monophonic 60–1000 Hz default (docs/audio-pitch.md "Units and regions", D-196) | `tst_audio_pitch`: `unitsFollowTheMidiScale`, `noiseAndSilenceAreUnvoiced`, `notesAndSegmentsFollowThePitch`, `declaredLimitsAreEnforced` |
| 2. Actual detection and correction chosen from synthetic tone/glide and voiced fixtures | YIN (de Cheveigné & Kawahara 2002) with centred parabolic refinement; TD-PSOLA (Moulines & Charpentier 1990) on epoch-aligned sub-sample marks with formant grain resampling and time map (D-194, D-195) | `tst_audio_pitch`: sines within 0.02 cents, glide within 5 cents, harmonic-tone shifts ±100…±699 cents within 0.25 cents per frame, vibrato flatten/keep within 4 cents, formant centroid within 0.03 of the ratio, retiming within 2 hops. This file was compiled standalone against the DSP sources and passed 15/15 before commit |
| 3. Contour/note editing, preview/cancel, non-destructive parameters | `AudioPitchSource.snapshot` feeds PitchEditor; `previewEdit`/`commitEdit`/`cancelEdit` map its signals to `edits.preview`/`commitPreview`/`apply`; parameters saved as the edit list and recomputed on open | `tst_audio_pitch_session`: `sourcePublishesTheEditorSnapshot`, `previewsHoldTheAnalysisAndCommitOneStep`, `pitchEditorDrivesTheHost` (real PitchEditor gesture → committed edit) |
| 4. Worker processing, stale-result cancellation, cache invalidation, real rendered output | analysis once per committed buffer on the pool (token every 32 frames); holds through ready previews; stale at once on any committed change, refuses edits while stale, never publishes an older revision; previews on the pool; offline render and playback use the edited buffer; the device thread runs no pitch code | `tst_audio_pitch_session`: `aStaleAnalysisIsNeverPublished` (pool held so the old analysis is in flight), `editsRenderUndoAndReopen` (render within 0.25 cents), `playbackAllocatesNothingWhileAPitchEditLands` (allocation probe) |
| 5. Frequency targets, unvoiced regions, boundary artefacts, undo/reopen; measured limitations | exact outside-region samples, edge crossfades, undo/redo/reopen bit-identical renders; limitations listed from fixtures only (D-196) | `tst_audio_pitch`: `pitchCorrectionHitsTheTarget` (edge step ≤ 1.1× input), `noChangeReproducesTheInput`, `cancellationStopsBothPasses`; `tst_audio_pitch_session`: `editsRenderUndoAndReopen` |

**Example.** `examples/pitch-editor` now generates a reference phrase

compiled with no new errors. Observed results (offscreen, software renderer):

- `tst_audio_pitch_session` 9/9 passed (7 cases plus init/cleanup), with the

alphabetic baseline at 4 px, so it sat mostly above the canvas; the labels are
now top-/bottom-aligned inside it. The example's status line stayed on
"Analysing" after the analysis was ready; it now follows the source's state
until a gesture reports.
