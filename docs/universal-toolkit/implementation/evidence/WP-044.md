## Persistent vector core (integrated)

The reference `CanvasDocument` now stores one-contour cubic paths with
local-space anchors and incoming/outgoing handles. `addPath`, node/handle
move, insert, remove and closure changes each use a reversible `CanvasEdit`.
`PathEditor` overlays the existing CanvasView, maps handles through the object
transform and view pose, previews drags and commits on release. The
[working path scene](../../../../examples/vector-authoring/PathWorkingScene.qml)
connects it and the existing stroke/fill panels to the same document.

Object style now retains and renders odd-even/nonzero fill, cap, join and
bounded dash pattern as well as flat colors and typed fills. Paths and
nondefault strokes use composited tiles on RHI to keep their QPainter cubic
and stroke geometry. Native binary version 3 round-trips the new fields and
still reads versions 1 and 2. `CanvasDocument.exportSvg` writes the supported
flat-color vector subset atomically; image objects, ICC/gradient managed fills
and document output ICC report unsupported instead of silently disappearing.

On Qt 6.11, focused `tst_canvas_vector_authoring`, `tst_canvas_style_model`
and `tst_canvas_persistence` passed **3/3**. The authoring test checks a

winding, transformed containment and a known interior pixel in both the

## Multi-contour path and vector clipboard

The follow-up lane extends the path object with bounded extra contours. Closed
nested contours render as holes under even-odd fill; nonzero fill follows their
winding. Each contour has reversible node/handle, insertion, removal and
closure edits. `PathEditor.contourIndex` selects handles without moving any
geometry into QML. Native `qtkc` version 4 round-trips extra contours and
still reads versions 1–3. SVG writes one subpath per contour with the selected
fill rule. `ClipboardService` copies paths using the bounded native snapshot,
offers SVG when representable, and pastes one undoable edit with new IDs and
paint order. The example scene exposes contour selection and copy/paste.

Focused evidence: `tst_canvas_vector_authoring::contourHoleAndClipboard`
checks even-odd and opposite-winding holes, native reopen, SVG pixel output,
inner-edge hit testing, reversible contour edits and clipboard paste/undo.
The isolated Qt 6.11 focused test passed **1/1** with configured `-j24 -l24`
build limits. I opened the [1100×640 contour editor capture](WP-044-contour-editor.png):
the cyan path has a visibly white inner hole, yellow dashed strokes on both
boundaries, and accessible controls to switch contours and copy/paste. The
compact dump placed `CanvasView#pathWorkingCanvas` at `8,8 850x624`,
`PathEditor#pathWorkingEditor` at `0,0 850x624`, and the copy/paste buttons
at `0,458 226x24` and `0,490 226x24` within the right panel.
This follow-up is integrated; WP-044 remains active.

## Path-backed parametric primitives (integrated)

This slice is merged on the integration branch (`07fa60a`); WP-044 remains active and not accepted.
`CanvasDocument.addParametricShape` creates polygon, star and
rounded-rectangle paths from typed bounds and parameters. Changing side/tip
count, star inner radius, corner radius or bounds regenerates the path as one
reversible edit. The definition and generated nodes persist in native version
5; versions 1–4 still load. Rendering, hit testing and SVG export use the
existing path backend. A manual node edit deliberately changes the object to
freeform, and undo restores the parametric definition. The live
[ShapePalette fixture](../../../../examples/vector-authoring/ParametricWorkingScene.qml)
creates and edits all three families through the reference document; its
inspector follows parameter edits, undo and node drags.

Fixes made while finishing the lane's draft:

- Object validation, on every commit and decode, now requires a parametric
  object's stored nodes to match its definition (within 1e-9 of the bounds'
  magnitude, for platform sin/cos rounding). The draft let a decoded file or a
  host `CanvasEdit` keep a star definition over unrelated nodes, which the
  next parameter edit silently replaced.
- Parameter keys are strict per kind, as documented; the draft accepted
  `points` on polygons and `sides` on stars. A `kind` equal to the object's
  kind is accepted, so `parametricParameters()` output round-trips (the draft
  rejected its own output). Bounds whose far edge overflows are invalid.
- At full corner radius the two ends of a zero-length side merge into one
  smooth node, so generated paths hold no zero-length segment (a pill has 6
  nodes; a square becomes the 4-node circle).
- `CanvasNativeFormat` metadata still reported version 3; it now reports
  `CanvasDocumentFormat::Version`.
- The `tst_canvas_persistence` "future version" case wrote version 4, which
  is supported since v4; it now writes `Version + 1` (the integrator's line).
- `PathEditor` threw `TypeError`s (123 in the new fixture test) whenever a
  shorter node list arrived, because trailing handles re-evaluated before the
  Repeater removed them; `handlePoint` now guards the index.
- The fixture refreshes its inspector on every document change, reports
  `freeform` after a node drag, gives rejected edits explicit messages, uses a
  built-in icon for Rounded, gives the inspector a real 290 px flex basis
  (`Tk.Flex` ignored its `width`) and has stable objectNames.

## Code-first round cf1: booleans, stroke alignment, patterns and effects

Branch `work/wp044-cf` from `round/cf1`. Written code-first: every file
passed the round's `-fsyntax-only`/qmllint check; nothing below has been built
or run yet (the round build runs the named tests). Decisions D-106 to D-109.

1. **Persistent segments, winding, stroke, shape parameters and appearance
   stack order.** Paths, fill rules, caps/joins/dashes and parametric shapes
   were already persistent. `CanvasObject::appearance` now adds stroke
   alignment, miter limit, opacity, blend mode, a pattern and an ordered
   effect stack (stable ids, enabled flags, canonical JSON parameters;
   unknown kinds kept). Native v6 appends a length-prefixed appearance block
   to every object record (D-106); versions 1–5 still load and the
   commit-time size accounting counts the block. Tests:
   `tst_canvas_vector_appearance::appearancePersistsAndInvalidRecordsAreRejected`
   (all fields plus an unknown effect round-trip; truncated/padded blocks,
   out-of-range values, duplicate ids and non-canonical parameters are refused
   on decode and commit), `tst_canvas_vector_authoring::parametricPersistenceAndOlderVersions`
   (now also v5 files; offsets shifted by the v6 block).
2. **Geometry operations and rendering, including path combinations.**
   `CanvasDocument.combinePaths(ids, op)` performs union, intersect, subtract,
   exclude (Qt's path clipper on operands flattened within 1e-4 of their
   extent) and combine (contours merged with curves kept). The result
   replaces the backmost operand (id, layer, order, style, transform) in one
   undoable edit (D-108). The painter renders aligned strokes, pattern ink
   and a per-object layer for effects, opacity and blend; RHI rasterizes such
   tiles through it; paint bounds feed the index so shadows cross tiles
   (D-107). Tests: `tst_canvas_path_boolean` (six functions: the four
   operations' areas and bounds, undo/redo/persistence of a curved union,
   pentagram self-intersection under both fill rules, transformed operands,
   curve-keeping combine, refusals that change nothing);
   `tst_canvas_vector_appearance::strokeAlignmentPaintsOneSide`,
   `patternFillDrawsInkOverTheFill`, `effectsRenderInStackOrder` (two
   blur-free shadows whose order changes a known pixel; bypass; undo),
   `blurOpacityAndBlend` (exact three-box blur value 64/255 two pixels outside
   an edge; multiply and 50% opacity composites).
3. **Style and shape controls, reorderable effects, binding to the
   selection.** `CanvasStyleModel` gained `alignment`, `miterLimit`,
   `opacity`, `blend` and `pattern` keys, publishes `selectionStyle`,
   `strokeStyle` and `fillStyle` for `selectedIds` (with `mixed` keys, following
   undo) and applies panel requests field by field (`applyStrokeStyle`,
   `applyFillStyle`). `CanvasAppearanceModel` binds one object's stack to
   `AppearanceStack` with add/remove/move/enable/parameter edits, each one
   undoable. `StyleWorkingScene.qml` now binds the stroke, fill, opacity and
   blend controls, an `AppearanceStack` and the path operations to the
   reference document. Tests: `tst_canvas_vector_appearance::styleModelBindsTheSelection`,
   `appearanceModelEditsTheStack`; `tests/qml/tst_vector_appearance_example.qml`
   (three functions driving the scene's panels, stack and path buttons).
4. **Clipboard, undo, save/reopen and a declared export path with explicit
   unsupported reporting.** The clipboard's native snapshot carries the
   appearance (`appearanceModelEditsTheStack` pastes and compares it). SVG
   export writes patterns, masked aligned strokes, chained SVG 1.1 filter
   effects, opacity and CSS blend, and now keeps document-unit stroke widths
   under scaled and non-uniform transforms (previously scaled with the
   element); enabled unknown effects refuse export with
   `objects.appearance.effects` (D-109). Tests: `tst_canvas_vector_export`
   (`appearanceExportsAsSvg` checks the written structure and compares Qt's
   SVG renderer with the canvas at scaled-stroke and stretched-geometry
   pixels; `unsupportedEffectsBlockExport`).
5. **Winding, self-intersections, degenerate paths, transform accuracy,
   output fixtures, reversible edits.** Winding and degenerate paths were
   covered; self-intersection (`selfIntersectionFollowsTheFillRule`),
   transform accuracy of booleans (`transformsMapIntoTheBackmostSpace`) and of
   SVG strokes (`appearanceExportsAsSvg`), known-pixel output fixtures for
   every appearance feature, and exact undo of booleans and appearance edits
   are added above.

**Accept when.** Styled content (aligned strokes, patterns, effects, opacity,
blend, combined paths) is created and edited through the models and panels,
and recovers equal objects after native save/reopen and clipboard paste; SVG
export writes it or refuses it explicitly (tests above; not yet run).

### Scope notes

- Qualification (performance, other platforms and Qt versions, screen-reader
  runs, translation, output-fidelity comparison against other renderers) is
  deferred to WP-088–WP-094 (user decision, 2026-09-24). Qt's SVG renderer
  may not draw every exported construct (for example CSS `mix-blend-mode`);
  the tests check it only where it does.
- Curve-preserving booleans are not required: results are straight-segment
  paths within the stated tolerance (D-108).
- Group and layer transforms, opacity and blend (the CAN-09 LayerTree roles
  WP-042 deferred) are not in WP-044's numbered requirements, which concern
  vector objects; object opacity and blend are covered here. Masks belong to
  WP-045 (accepted); the `masked` flag of effect records stays false.
- Further parametric families are not a numbered requirement; polygon, star
  and rounded rectangle remain the parametric set.
