# WP-044 — Vector authoring and appearance

**State: active; package not accepted.** WP-043 is accepted; WP-042 remains active.

The integrated Luna lane (`1fb8eb7`) adds `StrokeStyleEditor`,
`FillStyleEditor`, `ShapePalette` and `AppearanceStack`. Their request contracts
keep full style/effect descriptors, including unsupported metadata. The
vector-authoring fixture applies requests to a small host-owned document; its
focused QML interaction check passed **3/3** on the merged Qt 6.11 tree and
`qtk-preview --check` passed.

Sol added `CanvasStyleModel` for the reference canvas. It applies solid fill,
stroke colour and width across selected visible, unlocked objects in one
undoable `CanvasEdit`; the canvas native codec preserves those fields. The
focused `tst_canvas_style_model` passed **1/1**, including two-object atomic
edit, undo, native save/reopen and locked-object rejection. The real
[style fixture](../../../../examples/vector-authoring/StyleWorkingScene.qml)
passed preview check; its dump placed `CanvasView#styleWorkingCanvas` at
`8,8 706x624`, `StrokeStyleEditor#styleWorkingStroke` at `0,0 390x237` and
`FillStyleEditor#styleWorkingFill` at `0,245 390x69`. Sol opened the
[1120×640 capture](WP-044-style-working.png); both objects and the inspector
are legible.

The merged Qt 6.8 build and focused `tst_canvas_style_model` CTest passed on
2026-09-23 with the configured `-j24 -l24` limits. The style fixture also
passed `qtk-preview --check` on that build.

## Persistent vector core (pending integration)

The reference `CanvasDocument` now stores one-contour cubic paths with
local-space anchors and incoming/outgoing handles. `addPath`, node/handle
move, insert, remove and closure changes each use a reversible `CanvasEdit`.
`PathEditor` overlays the existing CanvasView, maps handles through the object
transform and view pose, previews drags and commits on release. The
[working path scene](../../../../examples/vector-authoring/PathWorkingScene.qml)
connects it and the existing stroke/fill panels to the same document.

Object style now retains and renders odd-even/nonzero fill, cap, join and
bounded dash pattern as well as flat colors and typed fills. Paths and
nondefault strokes use composited tiles on RHI to keep their QPainter cubic
and stroke geometry. Native binary version 3 round-trips the new fields and
still reads versions 1 and 2. `CanvasDocument.exportSvg` writes the supported
flat-color vector subset atomically; image objects, ICC/gradient managed fills
and document output ICC report unsupported instead of silently disappearing.

On Qt 6.11, focused `tst_canvas_vector_authoring`, `tst_canvas_style_model`
and `tst_canvas_persistence` passed **3/3**. The authoring test checks a
reversible handle move and node insertion/removal, native reopen equality,
SVG style fields, a rejected degenerate path, repeated-loop odd-even/nonzero
winding, transformed containment and a known interior pixel in both the
canvas and Qt's SVG renderer. I opened the 256×256
[canvas](WP-044-vector-output-canvas.png) and
[SVG](WP-044-vector-output-svg.png) captures; both show the same cyan curved
body with a dashed yellow round-cap stroke.
The real path fixture passed `qtk-preview --check`. I opened its
[compact](WP-044-path-compact.png) and
[comfortable](WP-044-path-comfortable.png) 1100×640 captures: the visible
square anchors, round control handles, Bézier guides, styled path and inspector
stay within the canvas in both densities. The compact dump places
`CanvasView#pathWorkingCanvas` at `8,8 850x624` and
`PathEditor#pathWorkingEditor` at `0,0 850x624`; comfortable uses
`10,10 830x620` and `0,0 830x620` respectively. `PathHandle#pathout_0`
is `252,24 20x20` compact and `243,24 24x24` comfortable.
Collapsed controls are shown offset from their anchors, so a straight node
can be turned into a curve by dragging either handle.

Still open: multi-contour/boolean paths, stroke inside/outside alignment,
parametric shapes beyond rect/ellipse, patterns, appearance-stack effects,
full selected-property bindings and clipboard. These are listed in
[vector authoring](../../../vector-authoring.md); the model rejects
unsupported style keys.
