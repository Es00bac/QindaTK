# WP-005 — Private Qt boundary and Qt version qualification

**Status: accepted for the stated Linux headless paths, 2026-09-23.** The
pre-change exposure and SDK setup are in [the baseline](WP-005-baseline.md).

## Implemented boundary

`StylusHandler` is now an installed public `QObject`/`QQmlParserStatus`
facade. Its implementation-only `StylusInputHandler` derives from Qt's
private `QQuickPointerDeviceHandler` and is parented directly to the canvas
item. The facade forwards typed samples, active/cancel/grab state and
supported input filters. QML construction attaches after component
completion; direct C++ construction with an item attaches immediately.
Failed exclusive grabs do not emit `began`. The default accepts keyboard
modifiers, including Shift, matching the former handler behavior.

`src/CMakeLists.txt` links `Qt6::QuickPrivate` privately. The installed
`QindaTKConfig.cmake` no longer calls `find_dependency(Qt6QuickPrivate)`.
Neither staged `QindaTKTargets.cmake` exports it. The installed
`stylus_handler.h` contains no Qt private include or private base class.

## Verification

The live `portageq envvar MAKEOPTS` was `-j24 -l24`; both direct Ninja builds
used those exact job and load limits. No Portage settings were changed.

| Gate | System Qt 6.11.1 | Isolated Qt 6.8.3 SDK |
| --- | --- | --- |
| QindaTK Debug build | `ninja -C build/integration -j24 -l24`: exit 0 | `ninja -C build/qt68 -j24 -l24`: exit 0 |
| Tests | `ctest --test-dir build/integration --output-on-failure`: 15/15 | `ctest --test-dir build/qt68 --output-on-failure`: 15/15 |
| QML lint target | `all_qmllint`: exit 0 | `all_qmllint`: exit 0 |
| Isolated install | `cmake --install build/integration` into ignored `build/qt611-stage` | `cmake --install build/qt68` into ignored `build/qt68-stage` |
| External consumer | `tests/consumer/stylus` configured, built and ran offscreen: exit 0 | Same fixture configured/built and ran offscreen: exit 0 with the SDK `lib` directory on `LD_LIBRARY_PATH` |
| Public dependency inspection | No QuickPrivate in installed config/targets; consumer compiler command has no Qt private include path | Same result |

The isolated Qt 6.8 SDK contains its own Qt Svg library. On this host,
running the staged consumer without an SDK runtime library path picked up
the host Qt 6.11 Svg library and failed version resolution. Setting
`LD_LIBRARY_PATH` to `build/qt68-sdk/6.8.3/gcc_64/lib` resolved all Qt
libraries to 6.8.3 and the consumer ran successfully. The optional
qtk-preview QindaQt desktop bridge was automatically disabled because its
host library lies outside the selected Qt prefix; it was enabled on the
system Qt 6.11 build.

## Migration and limits

The public C++ class changed base and ABI. Rebuild clients and replace casts,
subclassing or protected method use that relied on
`QQuickPointerDeviceHandler`. The former inherited `dragThreshold` and
`cursorShape` properties are not proxied. Existing QML sample-stream use and
documented input filters are the compatibility target. These runs exercise
synthetic pen, eraser, mouse and touch delivery. They do not qualify a
physical tablet, GPU/Wayland path, Windows, macOS or native assistive bridge;
those remain later platform gates. See [D-015](../../../decisions.md#d-015--keep-private-qt-behind-a-public-stylus-facade)
and the [support matrix](../../../platform-support.md).
