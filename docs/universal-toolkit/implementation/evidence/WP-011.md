# WP-011 — Commands, contexts, shortcuts and focus

**State: accepted.** WP-010 typed contracts are the base. This package adds
APP-01 CommandRegistry, APP-02 CommandContext, APP-03 ShortcutMap and PLT-08
FocusManager as core services, with optional adapters for existing command
presentations. The accepted scope is the public command path and transient
focus service described in [commands](../../../commands.md), not a claim that
all application actions or later editor transactions are implemented.

## Contract and implementation

- `CommandContext` owns weakly held application/document/view scope instances.
  An explicit active path resolves the most specific live handler, snapshots
  inherited document/focus/selection/tool values, and cancels requests when a
  scope closes. Destruction prunes a subtree and activates a surviving parent.
- `CommandRegistry` holds stable descriptors and scope-owned operations. It
  computes enabled, checked, visible and disabled-reason state, rejects stale
  or disabled invocations, emits success/rejection, and invokes one handler
  once. `CommandBinding` exposes the same state to QML presentations; a
  successful operation invalidates state so checked/disabled projections
  refresh.
- `ShortcutMap` parses portable sequences, shows native display strings,
  stores and loads per-command override maps, resolves active scope priority,
  reports same-rank exact/prefix conflicts, and supports timed/cancelable
  chords. A window event filter routes keys to the registry. It leaves
  ordinary text-editing keys to focused input controls and suspends dispatch
  during live IME composition. Scope removal also removes its bindings.
- `FocusManager` stores weak item/window references for nested transient
  surfaces. It restores a saved target when focus is still in the closing
  surface or cleared, while retaining a later explicit focus choice. Closing
  or destroying an owner/target prunes its surfaces.
- `Tk.MenuItem`, `Tk.CommandPalette` and the new `Tk.CommandButton` can bind
  to that shared registry and shortcut map. Their original direct-use paths
  remain valid. `Tk.ToolBar` seats `Tk.CommandButton`; `Tk.KeyCap` remains a
  display control. The adapters expose accessible names and disabled reasons.

## Boundary and follow-on work

Applications register descriptors/handlers in C++, own their context scope
activation and set each window's shortcut map. The map exports an override
dictionary but does not persist preferences or register operating-system
shortcuts. FocusManager manages concrete live items; it does not yet persist a
logical focus ID or automatically attach every popup. Asynchronous commands,
undo/edit transactions, preference UI, and domain-specific action models are
owned by later packages. The accepted result is one tested semantic command
path for the existing menu, toolbar, palette, keyboard and assistive routes.
