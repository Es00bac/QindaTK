# WP-063 — Waveform and spectral editing

**State: active; package not accepted.** WP-060 real audio engine remains open.

Luna's isolated `work/wp063-waveform-spectrogram` lane was integrated as
`7992890`. It adds `WaveformEditor` and `SpectrogramView` with exact sample
selection and host request/acknowledgment boundaries. The isolated focused
sample-boundary/commit/cancel test and fixture preview check passed using the
configured `-j24 -l24` build limits. The dump showed the waveform at
1084×250 and spectrogram at 1084×300. Sol inspected the
[waveform/spectrogram screenshot](WP-063-waveform-spectrogram.png): selection,
axes, snapshot heatmap and state labels are visible.

The fixture uses mock snapshots. The audio backend must provide exact sample
extrema and bounded spectral tiles/FFT metadata, implement real trim/fade and
spectral processing, and connect undo, cancellation and cache invalidation.

Audio-thread safety: no editing or analysis code runs on the device thread;
edits produce new immutable buffers and a recompiled graph, adopted at a
period boundary like any recompile (the WP-060 allocation probe still covers
`render()`).

Scope notes:
- Performance measurement on long files, other platforms, screen-reader
  runs and the refreshed screenshot belong to WP-088…WP-094.
- Spectral paint/lasso masks, time stretch, pitch shift and repair tools
  beyond band gain are not in this package's requirements; the rectangle
  region with band gain is the supported spectral operation.
- A length-changing edit does not move clips on the timeline (D-134); that
  is a timeline operation for the host.
- The `waveform-spectrogram` example still shows fixture snapshots; the
  providers are exercised end to end in `tst_audio_source_edit`.
