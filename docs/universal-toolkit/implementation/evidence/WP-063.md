# WP-063 — Waveform and spectral editing

**State: active; package not accepted.** WP-060 real audio engine remains open.

Luna's isolated `work/wp063-waveform-spectrogram` lane was integrated as
`7992890`. It adds `WaveformEditor` and `SpectrogramView` with exact sample
selection and host request/acknowledgment boundaries. The isolated focused
sample-boundary/commit/cancel test and fixture preview check passed using the
configured `-j24 -l24` build limits. The dump showed the waveform at
1084×250 and spectrogram at 1084×300. Sol inspected the
[waveform/spectrogram screenshot](WP-063-waveform-spectrogram.png): selection,
axes, snapshot heatmap and state labels are visible.

The fixture uses mock snapshots. The audio backend must provide exact sample
extrema and bounded spectral tiles/FFT metadata, implement real trim/fade and
spectral processing, and connect undo, cancellation and cache invalidation.

## Code-first round (cf1): DSP, tile backend and real edits

Built on the WP-060 engine/session, the WP-062 mixer and the WP-061 meters.
Design and conventions: [audio-editing.md](../../../audio-editing.md),
decisions D-134…D-137. The integrated round build ran the tests below
(`tst_audio_dsp` 15/15, `tst_audio_source_edit` 10/10, `tst_qml`
WaveformSpectrogram passing); the audit fixes further down added more.

| Requirement | What now exists | Verifying tests |
| --- | --- | --- |

Audio-thread safety: no editing or analysis code runs on the device thread;
edits produce new immutable buffers and a recompiled graph, adopted at a
period boundary like any recompile (the WP-060 allocation probe still covers
`render()`).

Scope notes:
- Performance measurement on long files, other platforms, screen-reader
  runs and the refreshed screenshot belong to WP-088…WP-094.
- Time stretch, pitch shift and repair tools beyond band and mask gain are
  not in this package's requirements. (Paint/lasso masks were listed here
  too; the audit showed AUD-21 is owned only by WP-063, so they are now
  implemented, see below.)
- A length-changing edit does not move clips on the timeline (D-134); that
  is a timeline operation for the host.
- The `waveform-spectrogram` example keeps its fixture snapshots for design
  review; `waveform-live` (below) runs the editors on the real stack.

## Audit fixes (cf1 gap round)

An independent audit estimated the package at about 80–85 % done and listed
six gaps. Each was re-checked against the plan and the code; all six were
real and are fixed in this branch (merged with `round/cf1` first).

| Audit finding | Change | Test that fails without it |
| --- | --- | --- |
| 1. No gain or fade amounts: G recorded a no-op "Gain 0.0 dB" step | `WaveformEditor` gets `gainDb` / `fadeShape`, a gain handle (drag up/down) and fade-in/fade-out handles (drag inwards, preview curve, snap to exact boundaries); `editRequested` carries `parameters` (`{gainDb}`, `{shape}`); Up/Down set the gain, E switches the curve, G at 0 dB requests nothing | `tst_waveform_spectrogram::test_gainAndFadeHandlesRequestAmounts`, `::test_editKeysRequestDomainOperations` (amounts, no 0 dB step); `tst_audio_edit_bounds::waveformHandlesAndChannelLayoutEditTheSession` (−6 dB on one channel and an equal-power fade out, exact samples through `session.edits`) |
| 2. No test cancels or supersedes a worker that already ran | Fixtures that launch the worker, let it finish, then cancel or supersede before its result is delivered | `tst_audio_edit_bounds::waveformWorkerCancelledAfterItRanIsNeverPublished`, `::spectrogramWorkerCancelledOrSupersededAfterItRanIsNeverPublished`; both fail when the `stillCurrent()` guards are removed (checked) |
| 3. Edit patches grew without bound | D-187: gain, fades and silence hold no samples (recomputed from the base on replay); spectral patches are a cache bounded by `edits.patchBudgetBytes` (64 MiB, `patchBytes` reports it), oldest dropped and recomputed bit for bit; a replay edits one private working copy in place | `tst_audio_edit_bounds::committedEditsKeepBoundedMemory` (0 bytes after five linear edits; four spectral edits under a one-patch budget, then undo ×3 and redo ×3 reproduce each buffer exactly) |
| 4. Scope note dropped paint/lasso masks without a plan reason | D-186: `spectralGain` takes `mask` (sample/Hz polygons, even-odd per polygon, union across polygons, ≤ 4096 points), saved with the edit; `SpectrogramView` has `selectionMode` rectangle/lasso/paint (R/L/B), `maskCommitted`, `maskPolygons` drawn from sample/Hz at any zoom, and Delete processes the mask | `tst_audio_dsp::maskBinRangesFollowThePolygon`, `::maskedGainMatchesTheBandAndStaysInsideTheMask` (a rectangle mask equals the band edit bit for bit); `tst_audio_edit_bounds::maskedSpectralEditReachesTheSession`; `tst_waveform_spectrogram::test_lassoAndPaintMasks` |
| 5. No channel layout | `AudioWaveformSource.splitChannels` gives `channelColumns` and `channelLayout` (L/R for stereo); `WaveformEditor.channelLayout` draws one band per channel, a drag inside one band selects that channel (across bands `"all"`), edits follow `selectionChannelId` | `tst_waveform_spectrogram::test_channelLayoutSelectsAndEditsOneChannel`; `tst_audio_edit_bounds::waveformHandlesAndChannelLayoutEditTheSession` (per-channel exact extrema) |
| 6. Zoom keeping selection coordinates untested | The committed spectral region is an overlay (`spectrogramSelection`) placed from sample/Hz | `tst_waveform_spectrogram::test_selectionKeepsItsCoordinatesThroughZoom` (zoom, band change and scroll past the left edge; the request still uses the committed samples past 2^53) |

## Live example (`examples/waveform-live`)

The live examples stand in for demo applications, so this one runs on the
real backend: `generateTestTake` writes a 4 s, 48 kHz take (five notes) that
`importMedia` puts on a track of an `AudioSession`; the session's
`AudioEngine` opens the built-in null device and loops the source.
`AudioWaveformSource` (peak pyramid) and `AudioSpectrogramSource` (STFT
tiles, sharing the waveform's view range) feed `WaveformEditor` and
`SpectrogramView`. Startup applies four real edits through `session.edits`
(equal-power fade in, −9 dB gain, linear fade out, and a −150 dB
1000–1700 Hz band previewed on the thread pool and committed); the toolbar
and keys add gain, fades, silence, delete, crop and rectangle/lasso/paint
spectral gain with Preview/Commit/Cancel; Undo/Redo use the model's history.
The playhead, transport time and output meter come from the engine.

A scripted pass over the example (delete → undo → redo → crop → undo →
silence → +3 dB → spectral 150–300 Hz preview/commit) gave frames
192000 → 168000 → 192000 → 168000, 96000 → 192000, seven edits in the list,
both analyses `ready` at revision 16, and playback still looping.

Toolkit defects it exposed, each fixed with a test that fails without it:

| Defect | Fix | Test |
| --- | --- | --- |
| `AudioEngine.configurationApplied` was emitted before the transport snapshot was published, so `transport.requestPlay()` from the handler was rejected ("No audio device is running") and the example never played | `finishJob` emits the answer after `publishSnapshot` (docs/audio-engine.md) | `tst_audio_engine::transportIsCurrentWhenConfigurationIsApplied` |
| A selection narrower than the gain label drew the label over both fade handles | the gain handle drops below the fade handles when it does not fit between them | `tst_waveform_spectrogram::test_narrowSelectionKeepsHandlesApart` |
