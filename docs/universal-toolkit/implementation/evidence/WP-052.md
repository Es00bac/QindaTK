# WP-052 — Equations, references and document review

**State: active; package not accepted.** WP-051 is still active.

Luna's isolated `work/wp052-panels` lane was integrated as `aab57af`.
It adds `EquationEditor`, `ReferenceManager`, and `ReviewPane`, plus a
host-owned QML fixture. Their requests preserve stable IDs and show broken
references, unsupported equation symbols and orphaned comments. The isolated
`-j24 -l24` build, focused ReferenceManager interaction test (3 passed) and
fixture preview check passed. Sol inspected the [document review screenshot](../../../screenshots/wp052-document-review.png): the three controls and their
error/action states are visible and readable.

Equation AST parsing/layout, reference resolution/formatting, and persistent
review anchors, accept/reject operations and undo remain to be implemented in
the structured document backend. Those missing operations prevent acceptance.

**Accept when.** Equations are inline objects that lay out, paginate and
paint on the page. Field results and review marks are document text and
formats, and every request is one reversible transaction. The
[document review example](../../../../examples/document-review/Main.qml)
now binds the three panels to one `RichTextDocument` and its page view.

## Audit gap fixes (`work/wp052-cf`, after `round/cf1` at `85d6f5b`)

An independent audit of `dfff600` found five gaps. All five were real and
are closed in the code. None was moved to another package. Built in
`build/cf` (Qt 6.11.1).

| Gap | What changed | Tests that fail without it |
| --- | --- | --- |
| OFF-10 footnotes had no owner (the scope note named no package) | The scope note was wrong: OFF-10 is WP-052's own scope. `FieldKind::Footnote`/`Endnote` fields hold the note text, number in document order (`1`, `2` / `i`, `ii`) and renumber, undo and persist like other fields. Pagination reserves room at the foot of the page column of the reference's line and draws a rule above the first note. Endnotes, and all notes in continuous layouts, follow the last block. `insertNote`, `setNoteText`, and `ReferenceManager` note drafts (`referenceNoteText`). The example has a footnote (`rich_text_notes.cpp`, `rich_text_pagination.cpp`) | `tst_rich_text_notes` (`notesNumberUndoAndPersist`, `footnotesSitAtTheFootOfTheirPage`, `continuousLayoutsListNotesAtTheEnd`); `tst_document_review.qml::test_note_draft_sends_its_text`; `tst_review_example.qml::test_navigation_notes_and_visual_equation` |
| Requirements 1 and 3: structure and formatting applied untracked while tracking | The scope note was wrong here too; the gap is closed in the code. Paragraph breaks carry insertion and deletion marks, so accepting a tracked delete across paragraphs gives the same document as the untracked delete. Formatting (character, paragraph, styles, lists, page breaks) is a `format` change that keeps the former look, and rejecting it restores that look. Deleting a table row or column is a tracked deletion that names the row or column, and accepting it removes them. Equation source and reference changes are a deleted and an inserted copy, and the equation keeps its ID. Everything else that edits content (inserting tables, rows or columns, merging and splitting cells, widths, table styles, section moves, caption re-series) is refused as `unsupported`. | Requirement 4: a tracked cut and paste lost field and comment identity | A paste now re-anchors a field or comment whose only other text is marked deleted, so a tracked cut and paste is a move. Accepting the deletion leaves the caption resolved (`Figure 1`, not `[?]`) and the comment open. Rejecting both changes puts them back (`rich_text_fragment.cpp`) | `tst_rich_text_review_tracking::trackedMovesKeepIdentity`. Removing the one-line guard makes it fail (checked) |
