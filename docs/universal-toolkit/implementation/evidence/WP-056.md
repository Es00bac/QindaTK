# WP-056 — Slide authoring and presentation

**State: active; audit gaps closed and verified on `work/wp056-cf`, awaiting acceptance review.**

Luna's `work/wp056-slides` lane was integrated as `f47855f`. It adds
`SlideCanvas`, `SlideSorter`, `SlideMasterEditor`, `AnimationPane`, and
`PresenterView`. The controls expose selection, object edits, slide
reordering, inherited master overrides, animation requests, and separate
audience/presenter snapshots through host-owned state. The fixture shows
request acknowledgments without claiming an animation evaluator.

The isolated lane built with configured `-j24 -l24` limits, passed its focused
QML interaction test and `qtk-preview --check`. The merged build, focused QML
case (3/3) and slide fixture smoke check passed. The merged preview dump
placed `SlideSorter` at 294×859, `SlideCanvas` at 770×859,
`SlideMasterEditor` at 384×227 and `AnimationPane` at 384×312. I opened and inspected the
[slide authoring capture](../../../screenshots/wp056-slide-authoring.png):
the slide sorter, selected slide canvas, master and motion inspector are
legible together at 1520×960.

Persistent slide/object edits and undo, master inheritance, animation
evaluation and export, and native separate audience/presenter windows with
monitor recovery remain backend work.

## Code-first round (cf1): persistent model, playback and windows

Built on `work/wp056-cf` without building or running; the round build runs
the tests named below. Design: [slides.md](../../../slides.md), decisions
D-158 to D-161 in [decisions-domains.md](../../../decisions-domains.md).

1. **Persistent object model.** `SlideDeck` (`src/core/slide_deck*.cpp`,
   `slide_deck_types.*`) holds masters with placeholders and layouts, slides
   with placeholder-bound and free objects, rich-text text boxes (rich-text
   fragment JSON), notes, transitions and effects, as the `DocumentModel` of
   `qindatk.slides.v1`, registered in the built-in codec registry.
   `slide_timeline.*` evaluates builds and frames. Tests:
   `tst_slide_deck::newDeckHasMasterLayoutsAndATitleSlide`,
   `decodingRejectsBrokenReferences`.
2. **Object editing, reorder/duplicate, inheritance/override on the command
   system.** Every edit is one validated whole-state `DocumentCommand`
   through `UndoService`; own-flag inheritance (D-158); text boxes edit
   through a `RichTextDocument` and commit as one step. Tests:
   `tst_slide_deck::masterChangesKeepDeliberateOverrides`,
   `reorderAndDuplicateKeepContentAndEffects`,
   `textBoxesEditThroughTheRichTextStack`, QML
   `tst_slide_deck_binding::test_sorter_reorders_the_deck_with_undo`.
3. **Animation editing/evaluation and deterministic playback.** Exact-tick
   effect timing (D-159), easing through `CurveEvaluator`, `SlideShow`
   position/navigation/clock, one painter for every output (D-160). Tests:
   `tst_slide_deck::effectEditsUseExactTicks`,
   `tst_slide_playback::scheduleUsesExactTicks`,
   `sampledFramesAreExactAndDeterministic`,
   `showNavigatesBuildsSlidesAndTransitions`, `clockBlankingAndLiveEdits`,
   `frameViewPaintsTheShowFrame`.
4. **Audience and presenter windows.** `PresentationWindows` creates two
   native windows through `WindowHost`; `PresenterConsole` binds notes,
   navigation, clock, blanking and display choice; the audience display is
   chosen by screen name, falls back to `waiting` on removal and reconnects
   automatically (D-161). Tests:
   `tst_presentation_windows::singleDisplaySharesThePresenterScreen`,
   `audienceDisplayDisconnectsAndReconnects` (QPA test screens are removed
   and added again), QML
   `tst_slide_deck_binding::test_console_shows_notes_and_navigates`.
5. **Verification.** Master changes and overrides, reordered/duplicated
   slides, sampled frames at exact ticks (numbers and pixels), separate
   audience/notes output, undo, and save → autosave recovery → reopen
   (byte-identical re-encode) → PDF export with and without notes pages are
   covered by the tests above, plus the `example_slide-show` smoke test.

Scope notes: real monitors, window managers, mixed DPI, screen-reader runs
and PDF output-fidelity comparison are qualification work (WP-088 to
WP-094). Image/media objects, per-effect custom curves and motion paths are
outside OFF-19/OFF-22's completion checks and are listed under "Not in this
slice" in slides.md. (The earlier note that also excused the presenter
annotation layer was wrong: OFF-23's contract names annotation commands; it
is implemented below.)

## Audit gap round (cf1 audit, about 75-80 % complete before it)

An independent audit of `5f7cf65` found nine gaps. Each was re-checked
against the plan (items 2-4, OFF-19/22/23) and the code; all nine were real.
What changed:

1. **Canvas on the WP-042 stack (OFF-19).** `SlideCanvasDocument`
   (`slide_canvas_document.*`) is a `CanvasDocumentAdapter` over one slide;
   `SlideCanvas` is now a `CanvasView` with `ToolController` (select,
   Shift multi-select, marquee, move), `SpatialTransform` (resize, rotate,
   nudge) with `SnapModel` (objects, slide edges, centre guides drawn by
   `GuideLayer`), delete, fill and master apply. Objects gained a rotation.
   Each object's pixels come from `renderObjectImage`, the output painter's
   own object code, so master background, font size and rich text show as in
   the show. Every gesture is one deck step (`editObjects`). Tests:
   `tst_slide_canvas` (6 cases: resolved slide, pixels vs audience output,
   resize/rotate steps, snapped move, group/removal/stale/insert refusal,
   locked objects), QML `tst_slide_authoring` (toolbar, drag move, handle
   resize, rich text).
2. **Rich text survives canvas edits.** The canvas edits text only through
   `beginTextEdit` + `RichTextEditor` + `commitTextEdit`; the example no
   longer calls `setObjectText`. Test:
   `tst_slide_authoring::test_text_edits_keep_rich_formatting` (bold run kept
   across a second canvas edit).
3. **No accidental overrides.** `commitTextEdit` with unchanged content keeps
   the placeholder inheriting and records no step. Test:
   `tst_slide_integrity::committingAnUntouchedPlaceholderKeepsItInheriting`.
4. **Prompts are not content.** Placeholders have a separate `prompt`; a new
   deck's placeholders are empty; only the editing canvas paints prompts.
   Test: `tst_slide_integrity::placeholderPromptsNeverReachAnOutput`
   (audience frames of new and inserted slides are the bare background).
5. **Animation preview, kinds and exported playback (OFF-22).** `SlidePreview`
   plays an effect's build step with the show's evaluator; `cancel()` shows
   the build complete, the same state as a presenter click during a build;
   `SlideDeck.exportPlayback` writes PNG frames at
   `Slides::playbackPositions`. The pane offers every effect kind for new
   and existing effects; both examples wire the preview. Tests:
   `tst_slide_preview` (preview = show = export pixels, cancellation, states),
   QML `test_animation_pane_adds_any_kind_and_previews`.
6. **Presenter-display removal (OFF-23).** The presenter window never goes
   onto the audience's display; with only that display left it is hidden
   (`presenterStatus`), the audience window's keys keep the show
   controllable, and it returns when a display appears. Test:
   `tst_presentation_windows::presenterDisplayRemovalNeverShowsNotesToTheRoom`
   (with and without an audience choice).
7. **Presenter buttons step builds.** `PresenterView` gained `stepsBuilds`,
   `canGoNext/Previous` and `stepRequested`; `PresenterConsole` maps them to
   `SlideShow.next/previous`. Test: QML
   `test_console_buttons_step_builds_and_draw_ink`.
8. **Resource bounds.** Text fragments are capped at 2 MiB and the deck at
   `encodedLimit` (default 64 MiB, the decode limit) at edit time;
   `saveToFile` never writes an unreadable file; undo steps charge detached
   data with text at its real size. Tests: `tst_slide_integrity`
   (`textIsBoundedAtEditTime`, `undoChargesTextAtItsSize`,
   `everyAcceptedDeckSavesAndReopens`).
9. **Annotation commands (OFF-23).** `SlideShow` holds per-slide presenter
   ink and a pointer for the running show; frames carry them to every
   output; `PresenterConsole` draws them from its preview and clears them.
   Tests: `tst_slide_preview::annotationsReachTheAudienceButNotTheDeck`, QML
   `test_console_buttons_step_builds_and_draw_ink`.

Also: integration tests now drive `SlideCanvas`, `SlideMasterEditor`
(`test_master_editor_updates_inheriting_slides`) and `AnimationPane` against
a real deck; `examples/slide-authoring` is now a deck-backed workspace;
D-158, D-160 and D-161 carry "Amended" notes; `phase-04-office.md` status
updated.

### Verification of the gap round (2026-09-25)

The gap round above was first left uncommitted and unverified. Building it
showed seven failing test functions; each was traced to a real defect, not
to the test:

- **Corner handles scaled one axis (WP-042 bug).** `CanvasTransformController`
  looked for "Top"/"Bottom" in handle names, but SelectionOverlay's corners
  are "topLeft", "bottomRight"...; every corner drag scaled horizontally
  only. Fixed with prefix/suffix matching and an AGENT-GUARD. New test
  `tst_canvas_transform::cornerHandlesScaleBothAxes`; QML
  `test_dragging_the_selection_moves_it_in_one_step` now checks height.
- **Image objects inherited the previous image's transform (WP-042 bug).**
  `CanvasPainter::paintImage` took `painter->transform()` (a reference to
  the live matrix) by reference, so from the second image object on every
  image was drawn at a compounded transform, which here dropped the slide's
  shape and text off the canvas. Fixed by copying; caught by
  `tst_slide_canvas::canvasPixelsMatchTheAudienceOutput` (mean channel
  difference to the audience frame 5.18 before, under 3 after).
- **The canvas never snapped.** `SnapModel` needs a view pose; `SlideCanvas`
  gave it none. The view, `SnapModel` and `SpatialTransform` now share one
  `CanvasViewState` (also enables keyboard nudges). New QML test
  `test_drag_move_snaps_to_the_centre_guide` (fails without the pose);
  `tst_slide_canvas` fixture got a pose too.
- **Untouched placeholder commit still overrode.** Comparing the committed
  fragment with the resolved text failed because the editor round-trip
  normalises the JSON. `commitTextEdit` now compares with the fragment the
  editor produced when the edit opened (`m_textBaseline`).
- `tst_slide_deck` asserted the old prompt-as-text behaviour; its two
  assertions now check `text` empty and `prompt` set (finding 4).
- `tst_slide_canvas::groupEditsAndRemovalsAreOneStep` expected an edit to be
  stale after undo restored the same content; staleness is by content, so
  the test now changes the object first.
