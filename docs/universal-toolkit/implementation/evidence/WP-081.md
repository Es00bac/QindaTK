# WP-081 — Extensions and developer surfaces

**State: accepted after integration.**

`Tk.TerminalSession` is merged on the integration branch. It owns a real
user-initiated Unix PTY process, libvterm-parsed styled rows and cursor,
bounded scrollback, UTF-8 input, resize, copyable text and process cleanup.
Constructing the session does not start a process. The isolated configured
build and focused `tst_terminal_session` passed. See
[terminal-session.md](../../../terminal-session.md) for the API and limits.

The merged configured build and `tst_terminal_session` passed 1/1.
`TerminalView` and its explicit-start live PTY example are merged. The Luna
lane passed its focused QML test 3/3, then captured and inspected both an idle
screen and [actual ANSI-colored process output](WP-081-terminal-live-output.png).
`CodeDocument` and `CodeEditor` are merged. They use a native Qt text document
for Unicode editing, IME, undo and UTF-8 save/reopen, with revision-tagged
syntax and diagnostics. The isolated C++ check passed 1/1, focused QML check
3/3, and the [live editor screenshot](WP-081-code-editor.png) was opened.
Visible folding, grouped multi-caret edits and revision-guarded completion
were subsequently merged; see [the completion slice](WP-081-code-editor.md).
An optional local clangd language-service path is merged; see
[the LSP slice](WP-081-lsp.md). Other protocol servers remain host adapters.

`ScriptRuntime` and `ScriptConsole` are merged. The runtime evaluates bounded
local JavaScript against JSON-only snapshots and an explicit command allowlist,
then replays commands on the owner thread with optional semantic undo grouping.
It now imports and exports a bounded versioned JSON command macro so host apps
can store a successful recording and replay it later. Import alone never
invokes a command; replay rechecks the live allowlist and registry. A failed
replay does not replace the imported recording.
Its isolated focused C++, QML and example checks passed; the
[live console screenshot](WP-081-script-console.png) was opened. It is not a
process sandbox and does not expose arbitrary application objects.

`ExtensionRegistry` is merged with JSON descriptor, ABI/version/dependency and
capability checks, real trusted Qt plugin load/invoke/unload, and saved-state
recovery. Its fixture test passed on the merged tree. See
[extension-registry.md](../../../extension-registry.md) for its trust boundary.
`ExtensionManager` now connects that registry to a reusable panel: the host
can add a local descriptor, see restored-but-missing entries and diagnostics,
and explicitly load or unload a trusted plugin. The focused QML test passed
4/4; `example_extension-manager-live` and `example_gallery` passed 2/2.
Sol opened the [compact](WP-081-extension-manager.png) and
[comfortable](WP-081-extension-manager-comfortable.png) screenshots. The
compact dump places `ExtensionManager#liveExtensionManager` at 12,61
876x527 and its two rows at 0,0 860x62 and 0,64 860x62; comfortable rows
are 852x69. Disabled Load buttons and diagnostics remain visible when the
descriptor is absent. Explicit bounded local directory discovery and a
visible Refresh action are now merged; see
[the discovery slice](WP-081-extension-discovery.md) and its screenshot.
The registry does not provide process isolation.

The combined merged build passed, followed by focused C++ tests 5/5, focused
QML checks 9/9 across the terminal, editor and script console, and their live
example smoke tests 3/3. The terminal/editor/script screenshots were opened.
The newer LSP and discovery slices have their own focused evidence and are
not included in the earlier combined test count above.

## Acceptance

The last gap was host persistence of recorded commands:
`exportRecordedMacro()` and `importRecordedMacro(json)` (merged in `19ce296`)
let an app store a successful recording and replay it after a restart. Import
never runs a command, and replay rechecks the live allowlist and registry. On
the integration tree at `05c0314`, the full build and CTest ran with four jobs:
250 of 251 passed, including `tst_extension_registry`, `tst_script_runtime`,
`tst_terminal_session`, `tst_code_document`, `tst_code_language_service`, the
QML suite and the five developer-surface live examples (code editor, code
editor with LSP, extension manager, script console, terminal). The one
failure, `tst_canvas_persistence`, came from a stale "future version" case
after the canvas format moved to version 4; `6c603f8` fixed that test and it
passes.

Dispositions of the items this record previously listed as open:

- **Cross-platform terminal adapters:** this package delivers and verifies the
  Unix PTY provider. Other platforms belong to WP-088's platform matrix, where
  an unavailable configuration stays unqualified.
- **Other language servers:** requirement 3 asks for optional language-service
  integration behind a versioned adapter, which the clangd path proves; other
  servers are host adapters.
- **Process-isolated scripting and package installation** are not WP-081
  requirements. The runtime is bounded and cooperative and is documented as
  not a security sandbox; extensions are discovered and loaded explicitly from
  local descriptors.
- **Host integration:** the macro persistence above closes the gap Sol named as
  the last one before acceptance.
