# WP-047 — Transport model and bar

**State: accepted.** Proposal scope: AUD-02 TransportModel and AUD-03
TransportBar. The control contract is in the [control catalog](../../../controls.md#transport);
the exact conversion contract is in [time-map.md](../../../time-map.md).

## Behavior delivered

- `TransportModel` publishes acknowledged engine state from a host-owned
  `TransportAdapter`. Requests carry IDs; later engine revisions win when
  acknowledgments arrive out of order. External engine snapshots update the
  same state. Position and range values cross QML as exact decimal sample
  strings.
- Capabilities and unavailable reasons govern play, seek, record, loop and
  punch. Device errors and denied recording are exposed. Unsolicited position
  snapshots are coalesced to a bounded GUI cadence; command replies publish
  promptly. Adapter replacement rejects pending requests, and late callbacks
  cannot address a destroyed model.
- `TransportBar` shows `TimeMap` timecode, frame, sample or tick readout and
  provides keyboard and pointer transport actions. It contains no playback
  timer. `TestTransportClock` is a deterministic contract adapter, not an
  audio or video engine.
