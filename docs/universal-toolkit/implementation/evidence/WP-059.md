# WP-059 — Forms, schemas and report design

**State: active; package not accepted.**

The isolated Luna lane `work/wp059-forms-schema-report` (`a015b83`)
supplied `LocalDatabaseProvider` over SQLite plus `FormDesigner`,
`DatabaseSchemaView` and `ReportDesigner`. The provider performs parameter
bound reads/writes, inspects columns/keys/foreign keys, validates a single
schema statement before an explicit migration, and provides a basic
group/count report preview. The sample uses an in-memory fixture database.

The isolated build used the configured `-j24 -l24` limits. The focused
provider test passed 3/3, the QML workflow test passed 3/3, and the form
fixture and gallery instantiated. The [form/schema/report screenshot](WP-059-forms-schema-report.png)
was opened and inspected: form fields bind to data, schema columns and a
migration preview are visible, and the report shows grouped rows.
After integration, the merged provider and focused QML tests passed,
and the 1280×960 fixture screenshot was regenerated and inspected. Its
dump places `FormDesigner#formDesigner` at `0,0 628x228`.

The isolated follow-up lane `work/wp059-design-report-output` (`919f4a6`)
added `LocalDataDesignStore` with versioned atomic save/reopen, stable
table/field/query bindings and validation against the live SQLite schema.
`LocalReportDocumentModel` runs a bound query and produces a paginated
`RichTextDocument` with PDF output. The fixture exposes save/reopen, report
preview, a page navigator and export. The configured-limit isolated build,
focused test (3/3) and fixture check passed; its 1280×1100 screenshot was
opened and inspected and showed two report pages. Merged validation follows.
The designer and output path now also support a grouped numeric SUM that
survives design save/reopen. A focused check rejects a nonnumeric SUM field
after schema inspection.
`LocalDatabaseProvider` now previews and applies ordered schema plans inside
SQLite transactions. Preview rolls back every step; an apply commits all
steps or none. The focused provider check covers dependent steps and a
later-step error without a partial schema change.

Remaining: integration with shared `DocumentSession`/undo, richer report
bands and other totals,
physical printing and saved-design qualification against schema changes.
