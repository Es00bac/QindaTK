## Delivered

1. **Tempo/meter model** (`TempoMapModel`, `tempo_map_model*.cpp`): UUID
   events at exact PPQ ticks, integer µs/quarter, validation (fixed first
   tempo/meter, unique ticks, BPM range, power-of-two meters, meter changes on
   bar lines, 4,096 limit), `qindatk.tempo/1` JSON with PPQ check.
2. **Transactions**: `addTempo/addMeter/move/edit/remove` sessions with
   preview, commit and cancel. There is one session at a time. Invalid previews
   are never published. Commits are revision-guarded, and history is 256 steps
   with precondition-checked undo/redo.
3. **Time map and content**: the model is the only writer of
   `TimeMap.tempoSegments` (previews included). `TimelineClip` gains
   `anchor`/`musicalTick`/`musicalOffset`. Beat-locked starts re-derive on
   every time-map change, and time-locked clips keep their ticks. Planner,
   history, codec, load and viewport rows (`anchorMode`) are updated, and
   `ClipItem` shows a music icon. A tempo edit that would overlap a beat-locked
   clip under `RejectOverlap`, or push it before zero, cannot commit.
4. **`Tk.TempoLane`**: bar grid, meter band, tempo step graph on the shared
   `TimelineViewport`. It supports drag (move on the beat grid, vertical BPM),
   double-click add, keyboard (select, move, ±BPM, delete, T/M add) and numeric
   entry (`Tk.TempoEventEditor`: bar.beat.tick, BPM, meter).
5. **Automation model** (`AutomationModel`, `automation_*.cpp`): lanes
   keyed by parameter ID, canonical unit/range/default/step, stable point
   UUIDs at exact ticks, step/linear/cubic with segment-local handles. Cubic
   segments are evaluated by `CurveEvaluator`. Move, add, remove, set, segment,
   handle, interpolation and range edits are sessions. JSON is
   `qindatk.automation/1`, with undo.
6. **`Tk.AutomationLane`** hosts `Tk.CurveEditor` (knot and handle gestures)
   on timeline coordinates. Unmoved coordinates return the stored exact
   values. It supports segment drag, double-click add, keyboard, and numeric
   entry (`Tk.AutomationPointEditor`).
7. **Modes**: off/read/touch/latch/write transitions, and a record-gesture
   path with caller-supplied tick timestamps. Passes keep the prior curve,
   replace the pass range, ramp back over `returnTicks`, wrap on loops, and
   commit one undo step each. `capabilities` and `setModeAvailability` give
   explicit `Unsupported` refusals with reasons.
8. **Engine seam**: `EngineSchedule` publishes immutable
   `EngineScheduleSnapshot`s of committed data (atomic `shared_ptr`, detached
   TimeMap copy), with exact sample/tick/musical queries and `renderBlock`.
   `MockAutomationEngine` is the concrete consumer: a deterministic sample
   clock, values at requested timestamps, and gestures stamped at engine time.
9. **Example** `examples/tempo-automation/Main.qml` (a ctest smoke test via the
   examples glob) shows beat-locked "Drums" and time-locked "Dialogue" clips,
   both lanes, the mode selector with a latch-capability toggle, and the mock
   engine with a recorded cutoff slider.
10. **Docs**: `tempo-automation.md`, and updates to `controls.md`,
    `edit-timeline.md`, `time-map.md` and `index.md`, plus D-054. The catalog
    was regenerated once (284 types; the committed base catalog was already
    stale against the generator, hence a large diff).

## Integration notes for Sol

- **CurveEditor seam**: one additive property, `referenceLine` (default true),
  skips the identity diagonal. If a later WP-043 commit changes
  `CurveEditor.qml`, keep that property (or an equivalent) and the
  `referenceLine: false` in `AutomationLane.qml`. Signals and knot shapes are
  used unchanged.
- **Timeline files** (WP-048): `TimelineClip` gained three fields and
  `TimelineEditRequest::clipAnchor`. `resolveMusicalMarkers` became
  `resolveMusicalAnchors` and moved, with `withDerivedPosition`, into
  `timeline_model_musical.cpp`. Clip rows gained the last role `anchorMode`.
  Clip JSON always carries `anchor`.
- `EngineSchedule` stores its snapshot in `std::atomic<std::shared_ptr<…>>`
  (C++20). That works with GCC 15 and MSVC; an older libc++ without it would
  need `std::atomic_load`/`atomic_store` or a small lock.
- A bare `void x` read in a binding was not captured as a dependency in this
  build; the lanes pass dependencies as function arguments instead. Other
  controls using `void` reads may be worth checking.
