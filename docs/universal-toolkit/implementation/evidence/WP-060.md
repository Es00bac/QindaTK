## Added in this lane

- **Engine seam** — `AudioEngine` (QML `Tk.AudioEngine`, a `TransportAdapter`
  with its own `transport` model): device list, acknowledged
  reconfiguration on a worker thread with rollback, telemetry, takes.
  `AudioEngineProcessor` is the only device-thread code: SPSC command (64) /
  event (256) / capture (4 s) rings, atomics, pointer-adopted immutable
  graphs released by generation, sample-exact loop wraps, commands at period
  boundaries. `AudioTakeWriter` drains takes to float32 WAV on its own thread.
- **Graph** — `AudioRenderGraph` compiled from the committed `TimelineModel`,
  decoded media and `EngineScheduleSnapshot`; per-sample `track:<id>/gain`
  automation (dB or linear); one `render()` for device and file.
- **Devices** — `builtin:null`, `builtin:loopback` (always built, silent,
  monotonic-clock paced, hot-unplug simulation) and optional ALSA
  (`QINDATK_ENABLE_ALSA`, pkg-config `alsa` + link check like Poppler; found
  here: alsa-lib 1.2.15.3). Stable `<backend>:<name>` IDs; a lost device stays
  listed and active, never replaced.
- **Session** — `AudioSession` (QML `Tk.AudioSession`) reuses `TimelineModel`,
  `TempoMapModel`, `AutomationModel`/`EngineSchedule`, `ResourceResolver`:
  WAV import (PCM 8/16/24/32, float 32/64), undoable clips, recorded takes
  placed with round-trip latency compensation, `qindatk.audio-session/1`
  JSON save/open (relative media URIs + SHA-256), missing media by ID, relink,
  offline render; the session `TimeMap` follows the device rate.
- **Panel** — `DeviceSettingsPanel` gains optional `engineState`/
  `engineMessage` and read-only `recoveryAvailable`: a lost/error engine shows
  its message and offers **Reconnect** by the same stable ID. An apply that
  arrives during a stop/loss teardown is queued, not refused.
- **Example** — `examples/audio-session/Main.qml`: live host on
  `builtin:null` (panel + transport bar + measured callbacks); smoke test
  `example_audio-session`.
- Docs: `docs/audio-engine.md`, `controls.md`, `index.md`, D-088,
  `catalog.json` regenerated (453 types). New files ≤ 500 non-blank lines
  (largest `audio_session.cpp` 482), SPDX headers.

## Seam for WP-061…068

Build on `AudioSession` + `AudioEngine`; do not add clocks or device code.
Extend `AudioRenderGraph::compile/render` for new signal paths (it must stay
allocation-free; add per-graph preallocated state rather than per-block
buffers), send new transport operations as `EngineCommand`s with
acknowledgments, read automation via `EngineScheduleSnapshot` IDs, and add
platforms as `AudioDeviceBackend` implementations. Offline renders are the
sample reference for device output.

## Scope notes

- **Platform/device matrix → WP-088.** Only Linux/ALSA plus software devices
  are implemented and qualified here; PipeWire-native, JACK, WASAPI, CoreAudio,
  real interfaces, hotplug notifications and audible-device latency measurement
  (tests must stay silent) belong to platform qualification. ALSA capability
  lists are offered candidates; `hw_params` decides at open.
- **Scheduling:** commands apply at period boundaries (loop wraps are
  sample-exact); no sub-period command timestamps.
- **Recording** is linear through loop wraps; per-pass takes, punch and
  comping are WP-065. Latency is nominal (buffer configuration), not
  `snd_pcm_delay`.
- **Media:** WAV only in core (other formats via WP-019 adapters); decode,
  resampling and offline render run synchronously on the calling thread
  (queueing through `JobModel`/render queue is a host choice); relink is not an
  undoable document command (timeline edits are).
- **Mixing:** track gain automation, mute/solo, clip summing only; fades,
  clip gain, buses/sends and plugins are WP-062/066. Cubic automation is
  flattened to 32 linear pieces per segment.
- **Packaging:** the Gentoo ebuilds do not yet expose an `alsa` USE flag
  (Poppler is also automagic there); overlay packaging is outside this lane.
- **RT priority:** SCHED_FIFO is requested and reported; this host grants none
  (`ulimit -r` 0), so the deadline figures above are at normal priority.
