# WP-057 — Notebooks and structured blocks

**State: active; package not accepted.**

Luna's `work/wp057-notebook` implementation was integrated from `20d369c`.
`NotebookView` presents host-owned notebook sections, pages, search results,
history and page metadata. `BlockEditor` presents text, code, table, media,
ink, embed and unsupported block records. Both issue identified mutation
requests; the host supplies authoritative snapshots and acknowledges edits.

The isolated build used configured `-j24 -l24`; its focused QML checks passed
3/3 and the fixture passed `qtk-preview --check`. The integrated
[notebook screenshot](WP-057-notebook-merged.png) was opened and inspected.
The merged focused QML run passed 4/4, including a corrected host-search
case: indexed body hits show even without a metadata match, zero host results
stay empty, and clearing the query restores the page list. The merged
fixture passed `example_notebook-authoring`; its dump places
`NotebookView#fieldNotebook` at `0,24 1504x920` and
`BlockEditor#notebookBlockEditor` at `0,0 1144x788`.

Persistent notebook mutations, cross-block cursor semantics and
real table/media/embed providers remain required before acceptance.

## Audit gaps closed (cf2, `work/wp057-cf`)

An independent audit of cf1 found nine gaps. All nine were checked against
[phase-04-office.md#wp-057](../phase-04-office.md#wp-057) and the code. All
were real and are now fixed. Built in `build/cf` after merging `round/cf1`
(`b10cbf7`), with the configured parallelism.

| # | Audit finding | Change | Test (fails without the change) |
| --- | --- | --- | --- |
| 1 | Paste paths skipped the 1 Mi per-block text limit, so a pasted block could make the notebook unsavable (session) or unopenable (standalone) | `insertText` and `insertHtml` normalize each new block. `insertBlocksAt`, which every paste path ends in, refuses a paste when any block would pass `MaxTextLength` (joined endpoints included) | `tst_notebook_document::pastesRespectTheBlockTextLimit` |
| 2 | Typing stayed in QML `drafts` until focus left the field, so autosave and recovery missed it, and a page change dropped drafts | Notebook mode commits a draft after `gestureIdle` without typing (one merged step per block). `flushDrafts()` runs before a page change and on destruction, and the example calls it before save. A refused commit keeps its draft. `load()` now reads `block` directly: it had reloaded the previous text from stale bindings, and the next keystroke committed over the new text | `tst_notebook_keyboard::test_typing_reaches_the_model_without_a_focus_change` (session revision changes while focused; page change commits; one undo step) |
| 3 | No key-event test for BlockEditor | New `tests/qml/tst_notebook_keyboard.qml` drives real keys: Ctrl+Enter split, Backspace merge, Left/Right/Up/Down across blocks, Tab/Shift+Tab, Alt+Up/Down, Shift+Down cross-block selection with Backspace delete, Ctrl+C/V across blocks, Ctrl+B. The tests exposed two defects, both fixed: a modifier key pressed alone (the Ctrl of Ctrl+C) cleared the cross-block selection, and a pooled delegate (culled but still `visible`) consumed focus requests. Pooled cards are now hidden, and `claimFocus` skips hidden ones | `tst_notebook_keyboard::test_split_merge_and_caret_crossing_by_key`, `::test_nesting_moves_and_selection_delete_by_key`, `::test_clipboard_and_format_keys_across_blocks` |
| 4 | `insertRange` refused a range that held an unsupported block, so cut-then-paste lost it | Unknown types paste verbatim (fresh ID, same type and data). Only the type name and the 8 MiB data bound are checked, the same rule `decodeNative` applies | `tst_notebook_document::rangesKeepUnsupportedBlocks` |
| 5 | A present image never rendered without a host `AssetProvider` | `BlockEditorMedia` draws a `ready`/`modified` image straight from the resolver URI (`blockMediaImage_<id>`) when no provider is set. The example ships `bank-sketch.png` and registers it | `tst_notebook_keyboard::test_ready_image_renders_from_the_resolver`; screenshots below |
| 6 | Locked descendants were deleted with a parent, page or section | `removeBlock` checks the whole subtree, and `removePage`/`removeSection` check every block (`NotebookTree::anyLocked`) | `tst_notebook_document::lockedDescendantsRefuseSubtreePageAndSectionDeletes` |
| 7 | `saveToFile` could write a file over 64 MiB that `loadFromFile` refuses | `saveToFile` runs the same `decodeNative` check before writing and writes nothing on failure | `tst_notebook_services::standaloneSaveRefusesAnUnopenableFile` |
| 8 | OFF-26 "reconcile conflicts without dropping attachments" had no test or scope note | `reconcileJson(json, baseJson)` (new `notebook_document_reconcile.cpp`, [notebooks#reconcile](../../../notebooks.md#reconcile)) merges another version as one undo step and never removes anything. A page changed on both sides keeps this side and gains a "(other version)" copy with fresh IDs | `tst_notebook_services::externalChangeReconcilesWithoutDroppingAttachments` (the disk file changes → the save is refused as a conflict → reconcile keeps all four resource IDs → save and reopen) |
| 9 | None of the cited tests had been run | All were run (below) | — |
