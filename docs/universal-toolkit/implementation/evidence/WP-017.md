# WP-017 — Accessibility, locale and gesture services

**State: accepted.** Proposal scope: PLT-06 AccessibilityAdapter, PLT-07
LocaleService and PLT-09 GestureRouter. Public use and support boundaries are
in [accessibility, locale and input](../../../accessibility-locale-input.md),
with [D-034 and D-035](../../../decisions-services.md).

## Behavior delivered

- `AccessibilityAdapter` publishes model-backed virtual Qt accessible
  children with stable semantic IDs, names, roles, descriptions, values,
  selection, focus, offscreen state and mapped command actions. It retains
  interface identity over reordering and retires removed IDs. Announcements
  are queued and bounded. A QML host uses `Accessible.role: Accessible.Pane`.
- `LocaleService` owns per-instance locale, time zone, numbering, calendar
  and chrome direction choices. It formats and parses at the UI boundary
  without rewriting canonical document values; bidi content direction is
  derived independently from the text.
- `GestureRouter` arbitrates one semantic gesture per view, handles mouse,
  touch, pen and eraser claims, suppresses synthetic duplicates and resolves
  wheel and temporary navigation policy. It starts an edit only after winning
  ownership, commits once and cancels on lost grab, owner destruction, stale
  view/target or explicit cancellation.

## Verification

- Integrated Qt 6.11.1 full CTest passed **50/50** before the concurrently
  registered WP-046 test; isolated Qt 6.8.3 full CTest passed **52/52** after
  it. Focused accessibility tests exercise native `QQuickWindow` tree
  discoverability, stable virtual IDs, selection and command-driven undo;
  locale tests switch locale during a live pending edit and exercise bidi and
  parsing failures; gesture tests cover contention, cancellation and undo.
  Builds used the actual configured `MAKEOPTS=-j24 -l24` equivalent.
- An external Linux AT-SPI client enumerated grid cells, a canvas shape and
  timeline clips, including an offscreen model item, with roles, names,
  descriptions and values. It invoked Intro's `press` action. The fixture
  logged `ACTION_HANDLER_CALLED value=2 undo=1`, proving the desktop bus action
  reached `CommandRegistry` and an `EditTransaction` with undo. Reproduction:
  [AT-SPI fixture and probe](../../../../tests/accessibility/README.md).
- The [RTL locale scene](../../../../examples/platform-services.qml) passed
  compact and comfortable `qtk-preview --check` and dump. At comfortable
  density the dump reported `Flex#rtlChrome 14,14 892x592`,
  `Label#longLocalizedLabel 0,40 892x44`, and
  `TextField#dirtyLocaleField 0,260 892x30`. Root opened the 920×620 compact
  and comfortable grabs in `build/wp017-atspi/`; the long label wraps, the
  field remains reachable, and chrome direction is separate from mixed bidi
  content. The visible draft is presentation data; the pending edit assertion
  is in the C++ locale test. Prior WP-011 tests cover IME preedit behavior.
- A clean installed consumer compiled public headers and imported all five
  new QML service types on Qt 6.11.1 and Qt 6.8.3. `all_qmllint` exited 0
  with existing warnings. The generated catalog lists the new exports.

## Boundaries

The Linux AT-SPI check is external to the app process and exercises the
same desktop bus used by screen readers. It does not claim human Orca,
Windows NVDA or macOS VoiceOver qualification; those platform passes remain
in WP-092. Translation catalogs and raw device event delivery belong to
applications/Qt input adapters; these services supply the policy and semantic
boundary. The visual fixture alone is not evidence of actual IME composition
or editing through locale switching.
