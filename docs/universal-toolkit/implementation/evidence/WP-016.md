# WP-016 — Clipboard and drag/drop protocols

**State: review.** Proposal scope: APP-15 ClipboardService and APP-16
DragDropService. The public contract is in [transfers](../../../transfers.md)
and the destination ownership decision is [D-033](../../../decisions-services.md#d-033--transfer-intent-and-authoritative-destination-edits).

## Behavior delivered

- `TransferPayloadCodec` validates a versioned internal MIME envelope with
  canonical IDs, exact decimal revisions and bounded item, text, PNG and
  nesting sizes. It advertises external UTF-8 text or PNG only when that
  representation is truthful for a single item.
- `ClipboardService` has an injectable clipboard boundary and a Qt system
  adapter. Inspection reports accepted format, conversion warning and the
  reason a destination cannot accept content. Text, PNG and collection-object
  paste commit through one `EditTransaction` and one undo step. Copy remaps
  object IDs. Same-collection cut stays pending until an atomic reorder paste;
  stale source state and unsupported moves, links and resources are explicit.
- `DragDropService` owns a single typed session, destination preview token,
  stable view/target/revision checks, one-shot commit, Escape/cancel and
  autoscroll signals. `PropertyCollectionDropTarget` is a shipped C++ adapter
  for object Copy into a `QVariantList`; it remaps row IDs and records one undo
  step. Cross-document Move requires a domain endpoint that proves an atomic
  source-and-destination commit; the reference adapter rejects it.

## Boundaries

The reference collection accepts plain map rows with canonical UUID `id`
fields. It rejects unresolved entity/resource references and Move/Link rather
than inventing a remapping or source-delete policy. Applications supply
domain `DropTarget` adapters and OS drag event bridges for richer content.
The supplied clipboard handles UTF-8 text, PNG bytes and typed object rows;
range paste and foreign rich formats await specific model adapters.
