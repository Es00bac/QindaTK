# WP-083 — diagram implementation slice

**State: implemented slice, not accepted.** This work starts from integration
base `1a835db` in `QindaTK-wp083-diagram-core`. It implements the first
diagram surface and native document plus a second layout/flow slice; CAD remains
open under [WP-083](../phase-07-integrations.md#wp-083).

## Delivered

- `DiagramDocument`: stable UUID nodes, ports and edges, directed connection
  validation, typed ports, card/group moves, cascade removal, title edits,
  bounded undo/redo and atomic `qindatk.diagram/1` JSON save/reopen. A failed
  reopen leaves the current graph unchanged.
- `DiagramCanvas`: binds the document to the existing keyboard-accessible
  `NodeGraph` gesture surface. It handles card dragging, port connection,
  edge disconnection and local selection/viewport state.
- `NodeGraph.wireRouting: "orthogonal"`: deterministic midpoint dogleg for
  forward links and an outer lane for backwards links. Card movements reroute
  from the current stable port associations.
- A live four-card workflow example and gallery section.
- Explicit, one-step `autoLayout` condenses cycles into columns and ranks the
  resulting DAG. Parallel edges do not change rank, saved node order breaks
  layout ties, and manual positions remain until the operation is invoked.
- Nonnegative `flow` on each real document edge, `inFlow`/`outFlow` derived on
  nodes, undo and JSON persistence. Canvas flow mode uses capped widths and
  shows totals on cards and in accessibility descriptions.

Qt 6.11.1: **3/3** registered focused cases passed. The focused QML runner
passed its link/move wiring and forward/reverse route known answers. The C++
model case covers stable identity, type rejection, grouped movement, undo,
redo, save/reopen and invalid-load atomicity. `gen_catalog.py` regenerated
the catalog with 416 types.

The [inspected screenshot](WP-083-diagram.png) uses the software renderer at
1180×720. `qtk-preview --dump` shows `DiagramCanvas#liveDiagramCanvas`
at `12,67 1156x618`; node cards are 200×72 and the orthogonal wires connect
four visible cards. The screenshot shows both forward and backward routes.

Second-slice focused checks on Qt 6.11.1: `tst_diagram_document` and
`example_diagram-live` passed 2/2; the existing focused diagram QML runner
passed 4/4. The C++ known-answer test verifies two parallel links, an SCC
cycle, exact ranks and rows, incoming/outgoing totals, manual-position
preservation, one-step Undo/Redo, idempotent layout and saved flow values.
The [inspected flow screenshot](WP-083-flow.png) at 1180×720 shows the new
Auto layout action, four differently weighted wires and card totals. The
preview dump reports `DiagramCanvas#liveDiagramCanvas` at `12,67 1156x618`
and 200×72 card geometry.

## Remaining WP-083 scope

Obstacle-aware/crossing-minimized routes, visual stencil providers,
multi-selection gestures, flow conservation checks, true Sankey band placement,
shared document-session history and additional export
providers remain. CAD still needs a distinct entity/units model, geometry
and constraint backend, 2D/3D viewport, dimensions, precision checks and
reopen/export fixtures. This slice does not satisfy the WP-083 acceptance gate.
