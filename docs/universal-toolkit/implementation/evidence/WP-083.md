# WP-083 — diagram implementation slice

**State: accepted after integration.**

## Delivered

- `DiagramDocument`: stable UUID nodes, ports and edges, directed connection
  validation, typed ports, card/group moves, cascade removal, title edits,
  bounded undo/redo and atomic `qindatk.diagram/1` JSON save/reopen. A failed
  reopen leaves the current graph unchanged.
- `DiagramCanvas`: binds the document to the existing keyboard-accessible
  `NodeGraph` gesture surface. It handles card dragging, port connection,
  edge disconnection and local selection/viewport state.
- `NodeGraph.wireRouting: "orthogonal"`: deterministic midpoint dogleg for
  forward links and an outer lane for backwards links. Card movements reroute
  from the current stable port associations.
- A live four-card workflow example and gallery section.
- Explicit, one-step `autoLayout` condenses cycles into columns and ranks the
  resulting DAG. Parallel edges do not change rank, saved node order breaks
  layout ties, and manual positions remain until the operation is invoked.
- Nonnegative `flow` on each real document edge, `inFlow`/`outFlow` derived on
  nodes, undo and JSON persistence. Canvas flow mode uses capped widths and
  shows totals on cards and in accessibility descriptions.

## Code-first round cf1 — requirement closure

Branch `work/wp083-cf` from `round/cf1`. These tests were first run in the
cf1 round build (`fa3327e`: `tst_diagram_document` 9/9,
`tst_diagram_editing.qml` 10/10) and again in the gap-closure round below. The CAD sketch and its
SVG/DXF output are described in [WP-083-cad.md](WP-083-cad.md).

1. **Separate models behind common contracts.** `DiagramDocument` and
   `CadDocument` stay separate and share the duck-typed domain canvas
   contract of D-122 (revision, canUndo/canRedo, lastError, undo/redo,
   save/load, exportSvg; views own selection and viewport pose).
   Test: `tst_diagram_document::sharedCanvasContract` drives both through
   the meta-object only.
2. **Layouts, routed edges, flow/Sankey.** Rank layout now orders columns
   by predecessor barycenter (D-123). `routeEdges` gives obstacle-aware
   orthogonal routes that the canvas draws through `NodeGraph.edgeRoutes`
   and SVG export reuses (D-124). `sankeyLayout` places node bars and bands
   on one scale; the new `Tk.SankeyDiagram` paints them.
   `flowImbalances` reports through nodes that do not conserve flow.
   Tests: `barycentricLayoutUncrossesColumns`, `routesAvoidCards` (known
   channel and lane answers, reroute after removal and Undo, invalid
   metrics), `sankeyBandsAndConservation` (exact 18 px/unit scale, bar and
   band positions, band sums equal bar heights, imbalance and tolerance,
   degenerate sizes, cyclic feedback bands); QML
   `tst_diagram_editing::test_canvas_draws_document_routes` and
   `test_sankey_places_bands_from_document` / `test_sankey_empty_document`.
3. **Geometry/constraint backend.** Delivered by the CAD slice (projection
   solver, six constraint kinds, dimensions, measurement). The declared CAD
   operation set is the 2D sketch (D-125); existing `tst_cad_document` and
   `tst_cad_viewport.qml` cover it.
4. **Snapping, selection, property editing, persistent operations and
   export.** DiagramCanvas adds `snapStep`, Ctrl+click multi-selection with
   one-step group move and `removeNodes` delete, a title/flow inspector
   strip, and Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y. Diagram output adapters:
   routed `exportSvg` and ID-preserving `exportGraphMl`. CAD already had
   point/grid snapping, selection, dimension editing and SVG/DXF export.
   Tests: `groupRemovalAndExports` (byte-exact SVG and GraphML fixtures,
   XML well-formedness, escaping, failed export leaves the file, one-step
   group removal and Undo); QML `test_group_move_is_one_step`,
   `test_snap_step_rounds_moves`, `test_delete_removes_selection_in_one_step`,
   `test_inspector_edits_title_and_flow`.
5. **Verification fixtures.** Routing and conservation known answers,
   degenerate Sankey and route inputs, cancel (Escape on a pending link) and
   keyboard undo/redo (`test_shortcuts_and_cancel`), export fixtures, plus
   the existing CAD precision, constraint, undo and reopen/export cases.

## Scope notes

Visual stencil assets are provider-backed (`stencilId` is persisted for the
host). A shared cross-document session history is host composition of each
document's history. Crossing reduction is one barycenter sweep, not an
exact minimum (D-123). CAD splines, relative-angle and curve-curve
tangency constraints and DXF/SVG import are outside the declared 2D set
(D-125).

## Gap-closure round — audit of `fa3327e`

An independent audit of `fa3327e` found eight gaps. After merging
`round/cf1` (fast-forward to `0cf89b8`), each was re-checked against the
plan and the code; all eight were real and are closed here.

| Audit finding | Resolution | Test that fails without it |
| --- | --- | --- |
| CAD constraints could not be removed (only by undo, lost on reopen, or by deleting geometry) | `CadDocument.removeConstraint(id)`; `removeEntity` also accepts a constraint ID. Geometry never moves. | `tst_cad_document::constraintsRemovableAfterReopen` (save, reopen, remove, tilt, undo) |
| CadViewport could not add constraints or edit circle/arc geometry | Ctrl+click multi-selection, `constraintOptions`/`applyConstraint`, keys H/V/D/A/C/T, and the `Tk.CadInspector` strip: constraint buttons, radius, arc start/sweep, per-constraint remove | `tst_cad_viewport.qml::test_constraint_tools_and_removal`, `test_radius_and_arc_editing` |
| DiagramCanvas could not create cards or ports; Group/Ctrl+G did nothing | `stencils` feed the Add menu, `addStencil` creates card + typed ports in one transaction; inspector `diagramAddInput`/`diagramAddOutput`; persistent `DiagramDocument` groups (`addGroup`, `removeGroup`, saved in the native file) behind Group, Ungroup, Ctrl+G, Ctrl+Shift+G and group drags | `tst_diagram_commands::groupsPersistAndFollowRemoval`, `stencilTransactionIsOneStep`; `tst_diagram_commands.qml::test_stencils_add_cards_with_ports`, `test_group_button_and_shortcuts` |
| No align/distribute (EXT-03 "connect/move/align commands share canvas transactions") | `alignNodes(ids, edge)` and `distributeNodes(ids, axis)`, one undo step each, on the inspector's arrange strip; `begin/commit/cancelTransaction` on both documents (D-283) | `tst_diagram_commands::alignAndDistributeAreOneStep`, `transactionContractIsShared`; `test_align_and_distribute_selection` |
| CAD view cancel/undo untested; first tap committed a point, so Escape left an orphan and a circle took two undos; no Ctrl+Z/Ctrl+Y | The first tap only records `pending`; the finished tool is one transaction; a rejected finish rolls back. Ctrl+Z, Ctrl+Shift+Z, Ctrl+Y; Escape clears the selection when no tool is pending | `tst_cad_viewport.qml::test_cancel_and_undo`, `tst_cad_document::transactionsAreOneUndoStep` |
| Reopen was stricter than save: a projection pass could move a within-tolerance point > 1e-6 mm and reject the file | `solve()` checks residuals before each projection pass; reopen accepts only a file that needs no projection, so what an edit commits always reopens bit for bit | `tst_cad_document::reopenAcceptsSketchSavedWithinTolerance` (1 m segment, angle residual 9e-7 deg; fails on the old code with "CAD file violates saved constraints") |
| No constrained export fixture | Constrained rectangle through `setDimension`, a unit change and Undo, exported to SVG and DXF: every exported line equals the model length (75 mm, 50.8 mm) within 1e-9 mm and DXF mirrors SVG | `tst_cad_document::constrainedExportMatchesModel` |
| Scope notes pointed at "WP-088 to WP-094"; stale "not yet run" wording | `docs/cad.md`, `docs/diagram.md` and this file now name WP-089 to WP-094 and say WP-088 is planned, not deferred | — (documentation) |

`docs/cad.md` also no longer says a failed solve leaves `setArc` unchanged
(it never solves; no constraint references an arc).
