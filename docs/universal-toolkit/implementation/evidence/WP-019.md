# WP-019 — Format registry and import/export jobs

**State: review.** Proposal scope: PLT-17 ImportDialog, PLT-18 ExportDialog
and PLT-20 FormatRegistry. The public service contract is in
[format-registry](../../../format-registry.md); control properties and stable
objectNames are in [controls](../../../controls.md#typography-calendar-and-format-dialogs).

## Behavior delivered

- `FormatRegistry` advertises operations separately and ships only the
  versioned QindaTK reference document and strict UTF-8 text providers.
  Native format detection considers a reference-document byte marker or a
  `.qtk` suffix as a provider candidate. Preflight then decodes and validates
  the actual bytes before any import job or adoption; a malformed, oversized,
  unrelated or nonlocal source is rejected. Candidate detection alone does not
  guarantee that the file is importable.
- Import/export preflight reports bounded previews, warnings, losses and
  approval options. Source hash, document revision, session-snapshot hash and
  destination hash receipts prevent using an old approval after inputs change.
  Lossy output requires explicit acknowledgement. Export uses `QSaveFile` and
  reports whether the file was committed, including late cancellation.
- Worker jobs receive immutable data. Import creates no live document until a
  successful result is explicitly adopted into a `DocumentManager`. The
  dialogs show actual provider choices, preflight, job state and errors;
  export is separate from document Save and does not clear dirty state.

## Verification

- The Qt 6.11 integrated build and full CTest passed **57/57**, including
  `tst_format_registry` and the import/export QML fixture. The latter
  exercises successful asynchronous import/adoption, operation-filtered
  choices, refused lossy or unsafe replacement requests, and unavailable
  file picking. `all_qmllint` exits zero. The focused worker fixture passed
  6/6, including initialisation/cleanup.
- The C++ fixture covers native extensions and missing links, BOM/newline
  preservation, loss acknowledgement, changed source/revision/snapshot,
  destination races, cancellation and provider failure. Tests use temporary
  local files and real `JobModel` workers, not a mocked successful job.
- Root inspected import and export 1280×800 preview PNGs. Compact import
  dialog geometry is `(430,316) 420×169`; compact export is `(430,290)
  420×221`; comfortable import is `(388,302) 504×197`. The static preview
  shows no selected file; the job and adoption paths are established by tests.
- The fresh Qt 6.8 CTest run passed `tst_format_registry` and all WP-019 QML
  cases. Its full `tst_qml` target reported three failures only in concurrently
  active WP-021/WP-026 fixtures, so the repository-wide gate remains open.
  A staged Qt 6.11 and Qt 6.8 external consumer compiled against installed
  public headers, imported `FormatRegistry`/both dialogs and instantiated
  them successfully. The Qt 6.8 consumer used the matching SDK library and
  plugin paths at runtime.

## Dismissal follow-up (2026-09-23)

Review found that Escape could dismiss an active ImportDialog while its job
later adopted a document. The dialog now invalidates its job and file-picker
request at `aboutToHide`, requests job cancellation, and clears a completed job
ID after adoption. The focused Qt 6.11 format-dialog suite passed **7/7**,
including dismissal during a real queued import with no late session. This
follow-up still needs the consolidated Qt 6.8 and repository gates before
package acceptance.

## Boundaries

No Adobe, Office, DAW, NLE or remote/cloud format support is claimed. The
reference provider handles typed property-document data and extensions; text
handles a representable body and reports losses. Host applications supply
additional providers and their own fidelity fixtures. Interprocess file locks
and arbitrary vendor format roundtrips are outside this package.
