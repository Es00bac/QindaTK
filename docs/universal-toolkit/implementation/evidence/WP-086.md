# WP-086 — Image slices, volumes and transfer functions

**State: accepted after integration.**

## Requirements

1. **Axes, spacing/orientation, channel/time, units, voxel types, chunked
   storage.** Built in the first slice (`VoxelVolume`, D-086). This round adds
   `copyChunk()` (a whole chunk through the bounded cache) for GPU upload.
2. **Slice/reslice and volume rendering with bounded residency and explicit
   interpolation.** Built. `ImageSliceItem.plane: Oblique` reslices in world
   space through the cursor with `resliceOrientation` (D-149).
   `VolumeViewItem`/`VolumeView` raycast the volume: composite or maximum
   intensity, orbit camera, zoom, clip box, sampling rate with opacity
   correction, explicit `Nearest`/`Linear` (D-146). The GPU path
   (`VolumeRenderNode`, `src/shaders/volume_raycast.{vert,frag}`, built with
   `qt_add_shaders` when Qt Shader Tools exists) uploads one channel/frame as
   an R8/R16/R32F 3D texture, packed chunk by chunk through the LRU cache,
   and runs the same ray march; the CPU `VolumeRaycaster` is the exact
   reference and the fallback (D-147). Reference rays are capped at 192².
3. **Linked crosshairs, plane navigation, transfer editing through typed
   property transactions.** Built. Crosshairs/navigation from the first slice
   now include oblique stepping along the normal and 3D picking into the
   shared cursor. `TransferFunctionModel` is a `DocumentModel`: each edit is
   one typed before/after step in its `UndoService` (a session can adopt it);
   `beginEdit`/`commitEdit`/`cancelEdit` make a drag, keyboard nudge or
   slider press one step, Escape cancels, Ctrl+Z / Ctrl+Shift+Z and header
   buttons undo/redo (D-148).
4. **Scientific 3D scatter/surface/volume examples; view/transfer settings
   persisted apart from source data.** Built for volumes:
   `examples/volume-imaging` shows three principal planes, a 30° oblique
   reslice and a volume rendering sharing one cursor and transfer function.
   Save view writes the cursor, every slice view's settings, the volume view
   and the transfer function to a settings file, apart from the voxels;
   Restore view reapplies them after a restart, only to the same dataset, and
   the transfer part is one undoable step. `examples/scientific-3d-family`
   joins WP-085's surface/scatter example and this one in one window.
5. **Verify phantoms, orientation/spacing, transfer mapping, GPU fallback,
   cancel/undo, large-data memory bounds.** Tests below, including the GPU
   path against the reference on this host's hardware. Scope note: GPU
   qualification across other drivers and platforms, and performance
   measurement, are WP-088 to WP-094.

**Accept when** the three controls display actual multidimensional data with
known interpretation: `ImageSliceView`, `VolumeView` and
`TransferFunctionEditor` all run on the sphere phantom in the example and
the gallery, and `examples/scientific-3d-family` shows the complete 3D
family (surface, scatter, slices, volume) in one window.

## Tests from round cf1

- `tst_volume_render` (C++): transfer table sampling; composite known answer
  (four samples of α 0.6 → 248, independent of sampling rate and
  interpolation); clip box (two samples → 214); physical spacing and early
  termination (→ 254); MIP of the phantom (centre 190/220); a rotated
  orientation placing the hot voxel above the centre; picking the shell at
  z 13.25 and the MIP core; missing provider chunks transparent; residency
  cap held while rendering and packing a 32-chunk provider volume under a
  4-chunk cap; 3D texture packing layout; the full fallback-reason order;
  view settings JSON round trip and atomic rejection; `VolumeViewItem` on the
  software scene graph drawing the reference image with the software
  fallback reason and picking into the cursor.
- `tst_volume_render_rhi` (same binary, `QT_QUICK_BACKEND=rhi`): compares the
  GPU image with the reference within 4 levels; skips without a hardware
  RHI or when the GPU path reports a fallback.
- `tst_volume_edit` (C++): oblique geometry, image values and slice count for
  identity and rotated volumes; stepping along the normal with anisotropic
  spacing and rotated reslice matrices; direct edits as undo steps; one step
  per gesture, cancel, refusal during a gesture; loads resetting history; a
  session adopting the history.
- `tests/qml/tst_volume_view.qml`: parts and software fallback, orbit drag
  with Escape cancel (no pick), click picking, keys/wheel/mode, settings
  round trip, editor gesture cancel + undo/redo buttons + Ctrl+Z, oblique
  view navigation.
- Existing `tst_volume_imaging`, `tst_volume_slices`,
  `tst_volume_imaging.qml` and `example_volume-imaging` must still pass.
