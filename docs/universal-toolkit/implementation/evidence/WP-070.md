# WP-070 — Media decoding and source/program monitors

**State: active; package not accepted.** Local frame and thumbnail decode is
implemented; playback, frame cache, A/V sync and sequence output remain open.

Luna's isolated `work/wp070-monitor-bin` lane was integrated as `f3e795f`.
`SourceProgramMonitor` sends exact frame IDs and timestamps to its owner and
displays acknowledged state. `MediaBin` reuses `AssetGrid` for bounded
thumbnail delegates and requests search, relink and proxy actions from its
owner. The fixture demonstrates host-owned updates rather than storing
catalog or playback state in QML.

The isolated Qt 6.11 focused QML interaction run passed 4/4, and its fixture
passed `qtk-preview --check`. The dump placed the monitor viewport at
562×581 and the media bin at 534×622. Sol opened and inspected the
[fixture capture](WP-070-media-bin.png): metadata and controls are legible;
frame and thumbnail placeholders are expected because this fixture has no
decoder or asset thumbnail provider. The merged `build/integration` build
compiled the controls, and `example_media_source_browser` passed its focused
CTest smoke check.

The default file asset backend now uses installed FFmpeg command-line tools
to read local video metadata and decode `frame`/`thumbnail` requests. A numeric
`frameId` selects an exact zero-based decoded frame; timestamp requests carry
an `exactFrameIndex: false` result flag. The focused backend test generated a
two-frame FFV1 video, decoded both frame and thumbnail requests, and passed.
The fixture still intentionally uses placeholder monitor frames because it
does not supply a video asset resource ID.
