# WP-070 — Media decoding and source/program monitors

**State: active; package not accepted.** Local frame and thumbnail decode is
implemented; playback, frame cache, A/V sync and sequence output remain open.

Luna's isolated `work/wp070-monitor-bin` lane was integrated as `f3e795f`.
`SourceProgramMonitor` sends exact frame IDs and timestamps to its owner and
displays acknowledged state. `MediaBin` reuses `AssetGrid` for bounded
thumbnail delegates and requests search, relink and proxy actions from its
owner. The fixture demonstrates host-owned updates rather than storing
catalog or playback state in QML.

The isolated Qt 6.11 focused QML interaction run passed 4/4, and its fixture
passed `qtk-preview --check`. The dump placed the monitor viewport at
562×581 and the media bin at 534×622. Sol opened and inspected the
[fixture capture](WP-070-media-bin.png): metadata and controls are legible;
frame and thumbnail placeholders are expected because this fixture has no
decoder or asset thumbnail provider. The merged `build/integration` build
compiled the controls, and `example_media_source_browser` passed its focused
CTest smoke check.

The default file asset backend now uses installed FFmpeg command-line tools
to read local video metadata and decode `frame`/`thumbnail` requests. A numeric
`frameId` selects an exact zero-based decoded frame; timestamp requests carry
an `exactFrameIndex: false` result flag. The focused backend test generated a
two-frame FFV1 video, decoded both frame and thumbnail requests, and passed.
The fixture still intentionally uses placeholder monitor frames because it
does not supply a video asset resource ID.

## Code-first round (2026-09-24, branch `work/wp070-cf`)

Written without a build; the integrator's round build runs the tests below.
Every changed C++, QML and JS file passes
`.cache/code-first/syntax_check.py` (0 failing). The remaining qmllint notes
name the new types and properties, which the pre-round module snapshot does

`QindaTK: FFmpeg media backend enabled (libavformat 62.12.102, libavcodec 62.28.102)`.
Design and limits: [media-playback.md](../../../media-playback.md);
decisions D-096 to D-099.

### Requirements

1. **Frame identity, timestamps, rate policy, audio sync, stream/colour
   metadata, bounded frame ownership: built.** `MediaSourceInfo` indexes
   packets into presentation order and applies one rate policy (D-097):
   constant rate within one time-base unit of `i / rate`, otherwise per-frame
   timestamps; frame starts round up, ticks hold. Duplicates, untimed packets
   and truncation are reported as damage. Audio positions are media samples
   relative to the first video frame (`audioOffsetSamples`). Colour tags follow
   the documented policy. Frames are owned by a bounded engine cache (48
   frames, 256 MiB), one presented copy and one node-owned texture. Tests:
   `tst_media_decode` `ratePolicyAndFrameIdentityAreExact`,
   `colourPolicyTagsFrames`, `testSignalFramesDecodeExactly`,
   `audioIsSampleExactAndConverts`, `audioOffsetPlacesSamplesOnMediaTime`.
2. **Decode, basic sequence composite and encode providers with rate, seek and
   damaged-media fixtures: built.** FFmpeg libraries, optional and private
   (D-096): `MediaDecoder` (key-frame seeks, forward decode, reopen fallback,
   audio resampling), `MediaProgram` (source or `TimelineModel` composite:
   track order, hidden/muted/solo, conform, letterbox, missing and
   out-of-range clips), `MediaEncoder` (FFV1 + PCM s16le in Matroska).
   Fixtures: the toolkit's own test signal (bars, burned-in frame code, sync
   pops), plus ffmpeg-CLI fixtures for a 600-frame MPEG-4 GOP with B-frames, a
   variable-rate file, a 100 ms audio offset, and truncated/non-media files.
   Tests: `tst_media_decode` (`longSeeksAcrossGopsWithBFrames`,
   `variableRateIndexHoldsFrames`, `missingDamagedAndTruncatedMedia`,
   `decoderPoolReopensChangedFiles`, `assetBackendResolvesTimesToExactFrames`),
   `tst_media_program` (`timelineProgramCutsAtExactFrames`,
   `conformsFractionalRateSources`, `layeringHiddenAndMissingClips`,
   `audioMixFollowsTrackState`). CLI fixtures QSKIP without `ffmpeg`.
3. **Source/program monitors and virtual media bins with metadata, proxy
   state and relink: built.** `MediaPlayer` drives `SourceProgramMonitor`
   (new `player` mode: engine-acknowledged seeks, identity of the frame on
   screen, keyboard). `MediaCatalog` backs `MediaBin` (new `catalog`
   binding): metadata jobs, virtual bins, search, relink and hash-matched
   folder relink, proxies (create, activate, inspect per asset), persistence
   (D-099). Tests: `tst_media_catalog`
   (`importReadsMetadataIntoBinsAndSearch`, `relinkKeepsSequenceReferences`,
   `proxiesReplacePicturesNotIdentity`, `contentRoundTripsBinsAndProxies`),
   `tst_media_playback` (`playerSourceModeSeeksRelinksAndGoesOffline`,
   `playerProgramModeFollowsTimelineEdits`), QML
   `tst_media_monitor_player.qml`; the existing
   `tst_source_program_media_bin.qml` covers the unchanged host mode.
4. **Authoritative playback/seek acknowledgments, decoder cancellation,
   GPU/software frame transfer: built.** `MediaPlaybackEngine` is a
   `TransportAdapter` (D-098): acknowledged play/stop/seek/loop, clock-driven
   playback with dropped-frame accounting, prefetch, presentation of the
   current target only, cancellation of superseded work. The decoder checks
   its token between packets and in libavformat I/O and stays usable after a
   cancel. `MediaFrameView` uploads each presented frame once into a
   node-owned texture (`gpu` on RHI, `software` otherwise). Tests:
   `tst_media_playback` (`rapidSeeksNeverPresentASupersededFrame`,
   `playbackFollowsTheClock`, `loopWrapsInsideTheRange`,
   `decodeWorkerSkipsCancelledJobs`, `frameViewShowsThePresentedFrame`),
   `tst_media_decode` `cancellationStopsAndDecoderStaysUsable`.
5. **Verify first/last/boundary frames, long seeks, variable-rate policy,
   missing assets, audio sync and a real sequence export: tests written.**
   Boundary frames 0/24/25/26/49 and clip cuts 49/50/99; long seeks across a
   600-frame GOP; the VFR hold policy; offline media in the player, bin,
   program and export; sync pops aligned in picture and sound in playback
   (`audioAndPictureShareTheTransportPosition`) and in the exported file
   (`exportWritesVerifiedSequence`, which decodes the export and checks every
   cut's frame code); the durable queue provider end to end with a stale-source
   rejection (`renderQueueExportsTimelineProgram`).

**Accept when:** the fixture `examples/media-source-browser.qml` browses,
plays, seeks and queues an export of a real two-cut sequence, and the tests
above check the frame identity of each step.

### Items handed over by WP-073 and WP-074

- External asset resolution and relink for compositions: `MediaFrameFeed`
  resolves layer `sourceId`s through the `ResourceResolver`, feeds decoded
  frames at each layer's exact `localTicks`, removes offline sources and
  re-feeds after a relink.
- Decoder cancellation: a newer `prepare()` cancels the previous request's
  decodes; the decoder itself stops at the next packet.
- Nodes fed from decoded media: the same feed sets `NodeGraphModel` source
  nodes (tagged sRGB); `NodeGraphModel::clearSourceImage` clears offline ones.
- Test: `tst_media_catalog` `frameFeedFeedsLayersAndGraphSources`.

### Round cf1 follow-up: white monitors in the fixture capture

The round capture of `examples/media-source-browser.qml` showed both monitors
and both bin thumbnails as white rectangles. They were real decoded frames:
the test signal put its white sync flash on frame 0, which both monitors
(readout `00:00:00:00 · 0 · 0`) and the time-0 thumbnails show first; the
software frame view was drawing correctly (`frameViewShowsThePresentedFrame`
passes). The generator gained `popPhase` (default 0, so every known-answer
test keeps its fixtures); the fixture starts its flashes mid-second, generates
both clips at the 75 frames the program needs, and cuts each clip into the
program as soon as its media is imported. A capture from an empty temp folder
at qtk-preview's default 120 ms wait shows bars in both monitors and both
thumbnails. New test: `tst_media_decode` `testSignalPopPhaseMovesTheFlash`.
