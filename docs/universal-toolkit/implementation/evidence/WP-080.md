# WP-080 — Detached native panels

**State: active; not accepted.** WP-040 remains in review. The native-panel
implementation is being integrated on `work/universal-implementation`.

`DockModel` now owns a `detached` mode in the same workspace serialization as
docked and in-host floating panels. It stores a global logical window rectangle
and preferred screen name. `DetachedPanelHost` uses `WindowHost` to create and
close actual `QQuickWindow` instances, moves each declaration's existing
content item into the native window, and returns that item to its home when
the panel reattaches or the native window closes. `DockHost` registers panel
content automatically and exposes a detach action in its placement dialog.
The docking example has an explicit detach button. A missing screen falls
back to an available screen through WindowHost's clamped geometry path.

**Implementation boundary:** Native windows keep their own Qt Quick focus
and rendering context while the same document-bound item moves between them.
No duplicate document model is created. `DockFloating` remains the in-host
floating presentation. A native titlebar close docks the panel into its
remembered zone.

**Focused verification (2026-09-23):** `cmake --build build/integration
--target tst_detached_panel_host -- -j24 -l24` completed; `ctest --test-dir
build/integration -R '^tst_detached_panel_host$' --output-on-failure` passed
1/1. The test opens a real offscreen `QQuickWindow`, keeps the same content
item, falls back from a missing screen, roundtrips detached placement through
the model serializer, reattaches, and handles native close. `qtk-preview
examples/docking/Main.qml --check --size 1280x800` passed. The

**Open before acceptance:** Qualify focus, popup placement and mixed-DPI
