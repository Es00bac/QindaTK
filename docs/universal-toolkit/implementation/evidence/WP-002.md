# WP-002 — Three source behavior findings

Status: **accepted** on the integrated source. This closes FIX-F01, F02 and
F03. The selectable-label proof is recorded separately in
[F01 evidence](WP-002-F01.md). Luna implemented F02 in `5d51535` and F03 in
`540a59e`; Sol reviewed and integrated both, then completed theme-token and
documentation updates.

## F02 — Ruler invalidation

Before the fix, changing `pixelsPerUnit` from 10 to 20 at constant origin,
position and size left the canvas image identical to the static 10 px/unit
image. The focused QML test failed on that original source. The ruler now
requests a canvas repaint when `pixelsPerUnit` changes; it also invalidates
for orientation and minimum minor-spacing changes. The integrated test
observes a changed Canvas data URL while confirming all geometry is fixed.
Worker captures in compact and comfortable density show changed tick spacing
and preserved `Ruler#rulerUnderTest 20,20 400x22` / `400x26` geometry. The
worker's RGB pixel checks counted 1,181 and 1,211 changed pixels after zoom.

## F03 — Waveform one-column geometry

Before the fix, the one-peak scene drew only its centre line; empty and
many-peak scenes behaved normally. The one-column branch now draws a finite
full-width plateau at the sample magnitude. The original multi-column loops
remain untouched. Worker comparisons found one-peak content changed while
empty and many-peak crops stayed the same at both densities.

After integration, `qtk-preview` dumps retained the single waveform's
`Waveform#probeWaveformOne 0,45 640x28` compact and `0,51 640x34`
comfortable, with matching Canvas bounds. Both final PNGs were opened and
inspected. A corrected RGB comparison against the pre-F03 integration image
placed all changed pixels in the single-waveform band: bounding box
`(0,48,640,70)` compact and `(0,55,640,81)` comfortable. The ruler and
many-peak crops had no changed pixels in this static fixture. The separate
runtime Ruler test proves F02's dynamic repaint.
