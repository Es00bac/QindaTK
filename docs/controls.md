# Controls catalog and API contract

Every QindaTK control is a QML type in `src/qml/` with the same name as the
file. Import with `import QindaTK as Tk`. This page is the contract: names,
properties, signals, sizes. `docs/catalog.json` is the machine-readable
mirror generated by `tools/scripts/gen_catalog.py`; keep both current.
The shared state, notification and accessible-action policy is in
[control-interaction.md](control-interaction.md).

## Conventions shared by all controls

| Convention | Rule |
| --- | --- |
| Base | `QtQuick.Templates as T` types for anything interactive; `Item`/`Rectangle` for passive pieces. |
| Height | `Tk.Theme.size.control` (24). `small: true` → `controlSm` (20). `large: true` → `controlLg` (28). Chips 32 (`size.chip`), island actions 36 (`size.action`), rows 22 (`size.row`), headers 24 (`size.header`), tabs 22 (`size.tab`). |
| Text | body 12px (`font.body`); captions 10px; overlines 10px uppercase semibold tracked. |
| Radius | `radius.sm` (4) for controls, `radius.md` (6) for chips/panels/popovers, `radius.full` for islands, badges, switches. |
| Colours | Only `Tk.Theme.color.*` roles. Rest: `controlBg`/`controlBorder`; hover: `controlHoverBg`/`controlHoverBorder`; active/checked: `controlActiveBg`/`controlActiveBorder`; inputs: `inputBg`/`inputBorder`/`inputFocusBorder`; chips: `chipBg`/`chipBorder`/`chipHoverBg`/`chipHoverBorder`. |
| Focus | Theme-coloured focus ring around the focused control or delegate. Custom composites use `activeFocus` so keyboard and assistive focus remains visible; each row below names any stable ring objectName. |
| Disabled | `opacity: Tk.Theme.opacity.disabled`. |
| Tooltip | `property string tooltip` on every control; show a child `Tk.ToolTip` on hover and use the text as the accessible name for icon-only controls. The attached form creates a QtQuick.Controls style tooltip. |
| Icons | `iconName` (Lucide name, see `qtk-preview --list-icons`) rendered by `Tk.Icon` at `size.icon` (14) or `size.iconSm` (12) when `small`. |
| Motion | colour/opacity transitions `Tk.Theme.motion.fast`; nothing longer than `motion.base` in chrome. |
| Naming | `iconName`, `trailingIconName`, `text`, `small`, `large`, `variant`, `checked`, `tooltip`, `value/from/to/stepSize`. Signals in past tense (`clicked`, `activated`, `valueModified`, `closed`). |
| objectName | Not set by the control; internal parts that tests need are named in the tables below. |

Layout primitives (`Flex`, `Grid`, `Stack`, `Box`, `Scroll`) are documented
in [layout.md](layout.md); theming in [theming.md](theming.md); docking in
[docking.md](docking.md).

## Command composition and typed inspectors

All command rows read enabled, checked, label and disabled-reason state from
`CommandRegistry` when a registry and command ID are supplied. Menu choices
use the same command invocation path. Editor controls receive an existing
`PropertyBinding`; they do not create or own document content. A rejected
edit cancels its preview, and an accepted user edit is one undo transaction.

## Asset-backed media adapters

These controls own one `Tk.AssetProvider` subscription each. They request only
when `active` is true and the provider/resource ID are set. Changing the
provider, resource, options, document, view ID, or active state releases the
old subscription before starting another. Destruction releases the current
subscription; virtualized delegates that are pooled should set `active: false`

## Docking — see docking.md

`DockHost`, `DockPanel`, `DockFrame`, `DockTabStrip`, `DockDivider`,
`DockFloating`, `DockDropOverlay`, `DockPlacementDialog`. The model is `Tk.DockModel` (C++).
`Tk.DetachedPanelHost` connects that model to `Tk.WindowHost` for real native
panel windows. DockHost's `detachedHost` property registers each declared
content item and its `detachPanelNative`/`reattachPanel` functions move it
between windows. A detached native window has objectName
`detachedPanelWindow_<panelId>`; see [docking.md](docking.md).
`DockTabStrip` is a named PageTabList; its panel entries are PageTabs with
accessible titles and selected state. Tab focuses an entry, Left/Right moves
and activates across the group, and Home/End selects the first/last panel.
Space/Return/Enter and the accessible press action activate through
`DockModel.activateInGroup`; owner model updates only update selection.
`tabActivated(panelId)` reports accepted user selection. The visible focus
ring is `dockTabFocus_<panelId>`; `tabItem(index)` exposes a current delegate
for focus management by host code. Horizontal pointer drags reorder through
`DockModel.moveInGroup` without activating the dragged panel. A vertical drag
tears it off through the host drag lifecycle. Reordering can recreate the
strip and its delegates; acquire them again after structural model changes.
`DockDivider` is a focusable `Accessible.Splitter` named by its `tooltip` or
“Resize dock panels”. Left/Right moves a vertical seam and Up/Down moves a
horizontal seam by `Theme.space.lg`; accessible increase/decrease uses the
same signed delta path as dragging. It emits `dragged(delta)` and leaves lane
extents and slot shares to `DockZone` and `DockModel`. Its visible focus ring
is `<divider objectName>_focus`.
`DockFloating` exposes eight named `Accessible.Splitter` resize handles
(`dockFloatingResize_<panelId>_<side>`). Arrow keys resize each handle's
applicable axes; accessible increase/decrease and pointer drag share
`DockModel.setFloatingRect` and its minimum-size rules. Focus is outlined with
a themed ring. `Theme.size.seamTarget` supplies expanded edge and corner
targets without changing frame geometry; very small panels shrink corner
targets and disable edge targets that cannot fit without overlap.

Dock headers expose a keyboard-focusable, named Place button
(`dockPlacement_<panelId>`); Shift+F10 on a focused panel/tab opens the same
host-owned `DockPlacementDialog`. Its destination picker supports legal zones,
relative panel placement, tab grouping and explicit tab order. Floating move
uses bounded horizontal/vertical NumberFields; Apply commits through DockModel,
Cancel discards the proposal. `panelPlacementAccepted(panelId)` reports accepted
user requests only. Dialog objectNames: `dockPlacementDialog`,
`dockPlacementDestination`, `dockPlacementX`, `dockPlacementY`, `dialogPrimary`,
`dialogSecondary`. See [docking](docking.md#keyboard-and-accessible-panel-placement)
for bounds, stale-state guards and focus restoration.

## Transport

`Tk.TransportBar` is a themed `Tk.ToolBar` bound to `Tk.TransportModel`.
It shows the acknowledged sample position as timecode, frames, samples or
ticks through `TimeMap`. Play, stop, record, locate, loop and punch actions
submit requests to the model; the bar does not advance a media clock. Space,
R, L, P, Home and Left/Right are the keyboard actions. The bar reports engine
capability and device errors in its disabled control tooltips and status text.
Its stable parts are `transportPlay`, `transportStop`, `transportRecord`,
`transportLocateStart`, `transportLoop`, `transportPunch`, `transportTime` and
`transportStatus`. A real media engine must implement the `TransportAdapter`
interface; `TestTransportClock` is a deterministic contract fixture.

### ScreenWorkArea

`Tk.ScreenWorkArea` is a nonvisual C++ observer. Set `anchor` to a Quick item
and `anchorPoint` to a point in that item’s coordinates (default origin).
Read `availableGeometry` in global logical coordinates. The screen containing
the anchor point is selected among the window’s virtual siblings; a point in
a desktop gap falls back to the window’s screen. A detached or destroyed
anchor reports an empty rectangle. `refresh()` synchronously rechecks it.

The observer tracks ancestor movement, reparenting, window movement, screen
changes, work-area notifications and DPI changes. Set `trackTransforms` when
arbitrary ancestor transforms must be checked after each GUI frame. `Menu`
enables that check only while visible, supplies its parent and popup position,
refreshes before opening, and caps its implicit height before native window
creation. Qt retains responsibility for native popup placement and flipping.
Qt reports geometry in logical coordinates; never multiply this rectangle
by device pixel ratio. The platform may not supply reserved work areas on
multi-monitor X11; see the [monitor qualification note](universal-toolkit/implementation/evidence/WP-007-FND-09-monitor.md).
