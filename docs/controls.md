# Controls catalog and API contract

Every QindaTK control is a QML type in `src/qml/` with the same name as the
file. Import with `import QindaTK as Tk`. This page is the contract: names,
properties, signals, sizes. `docs/catalog.json` is the machine-readable
mirror generated by `tools/scripts/gen_catalog.py`; keep both current.
The shared state, notification and accessible-action policy is in
[control-interaction.md](control-interaction.md).

## Conventions shared by all controls

| Convention | Rule |
| --- | --- |
| Base | `QtQuick.Templates as T` types for anything interactive; `Item`/`Rectangle` for passive pieces. |
| Height | `Tk.Theme.size.control` (24). `small: true` → `controlSm` (20). `large: true` → `controlLg` (28). Chips 32 (`size.chip`), island actions 36 (`size.action`), rows 22 (`size.row`), headers 24 (`size.header`), tabs 22 (`size.tab`). |
| Text | body 12px (`font.body`); captions 10px; overlines 10px uppercase semibold tracked. |
| Radius | `radius.sm` (4) for controls, `radius.md` (6) for chips/panels/popovers, `radius.full` for islands, badges, switches. |
| Colours | Only `Tk.Theme.color.*` roles. Rest: `controlBg`/`controlBorder`; hover: `controlHoverBg`/`controlHoverBorder`; active/checked: `controlActiveBg`/`controlActiveBorder`; inputs: `inputBg`/`inputBorder`/`inputFocusBorder`; chips: `chipBg`/`chipBorder`/`chipHoverBg`/`chipHoverBorder`. |
| Focus | Theme-coloured focus ring around the focused control or delegate. Custom composites use `activeFocus` so keyboard and assistive focus remains visible; each row below names any stable ring objectName. |
| Disabled | `opacity: Tk.Theme.opacity.disabled`. |
| Tooltip | `property string tooltip` on every control; show a child `Tk.ToolTip` on hover and use the text as the accessible name for icon-only controls. The attached form creates a QtQuick.Controls style tooltip. |
| Icons | `iconName` (Lucide name, see `qtk-preview --list-icons`) rendered by `Tk.Icon` at `size.icon` (14) or `size.iconSm` (12) when `small`. |
| Motion | colour/opacity transitions `Tk.Theme.motion.fast`; nothing longer than `motion.base` in chrome. |
| Naming | `iconName`, `trailingIconName`, `text`, `small`, `large`, `variant`, `checked`, `tooltip`, `value/from/to/stepSize`. Signals in past tense (`clicked`, `activated`, `valueModified`, `closed`). |
| objectName | Not set by the control; internal parts that tests need are named in the tables below. |

Layout primitives (`Flex`, `Grid`, `Stack`, `Box`, `Scroll`) are documented
in [layout.md](layout.md); theming in [theming.md](theming.md); docking in
[docking.md](docking.md).

## Docking — see docking.md

`DockHost`, `DockPanel`, `DockFrame`, `DockTabStrip`, `DockDivider`,
`DockFloating`, `DockDropOverlay`. The model is `Tk.DockModel` (C++).
`DockTabStrip` is a named PageTabList; its panel entries are PageTabs with
accessible titles and selected state. Tab focuses an entry, Left/Right moves
and activates across the group, and Home/End selects the first/last panel.
Space/Return/Enter and the accessible press action activate through
`DockModel.activateInGroup`; owner model updates only update selection.
`tabActivated(panelId)` reports accepted user selection. The visible focus
ring is `dockTabFocus_<panelId>`; `tabItem(index)` exposes a current delegate
for focus management by host code. Horizontal pointer drags reorder through
`DockModel.moveInGroup` without activating the dragged panel. A vertical drag
tears it off through the host drag lifecycle. Reordering can recreate the
strip and its delegates; acquire them again after structural model changes.
`DockDivider` is a focusable `Accessible.Splitter` named by its `tooltip` or
“Resize dock panels”. Left/Right moves a vertical seam and Up/Down moves a
horizontal seam by `Theme.space.lg`; accessible increase/decrease uses the
same signed delta path as dragging. It emits `dragged(delta)` and leaves lane
extents and slot shares to `DockZone` and `DockModel`. Its visible focus ring
is `<divider objectName>_focus`.
